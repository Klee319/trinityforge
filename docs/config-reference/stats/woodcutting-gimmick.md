# stats/woodcutting-gimmick.yml

出荷config `TrinityForge/src/main/resources/stats/woodcutting-gimmick.yml` の本文コメント(先頭ヘッダを除く)をここに移設したもの。
config-editor で保存すると本文コメントは復元されないため([tools/config-editor/lib/yamlio.js](../../tools/config-editor/lib/yamlio.js) 参照)、運用ドキュメントとしてここに退避している。
**設定値そのもの(キー/値)はymlの方を参照。ここはコメント本文のみを収録し、移設前後でキー・値が完全一致することをスクリプトで検証済み。**

## ⚠️ このymlは jar と同時に配備しないと直らない修正を含む(2026-07-31 G1 round2 レビュー指摘6)

`tiers.max-extra-logs` の 8/16/32/64 → **16/32/64/128** への引き上げ（`tmp/decisions.md` の N2 追記で承認済み）は
**100% この yml 側にしかない**。Java 側のフォールバック既定値（`WoodcuttingGimmickConfig` の
`tree-fell.max-extra-logs: 8`）は据え置きなので、**jar だけ差し替えて yml を配備しないと**

- tier1〜4 が旧 8/16/32/64 のまま（配備先 yml に `tiers:` があればその古い値、無ければグローバル 8）
- `leaves-max` 列が無いのでグローバル既定 512 に落ちる

となり、「幹を伐り切って葉を掃除する」という指摘6の修正原理が成立しない
（`leaves-decay-only: true` は残った幹が距離6以内で支える葉に触らないので、**葉が1枚も壊れない**）。

**配備手順: `TrinityForge.jar` と `stats/woodcutting-gimmick.yml` は必ず同時に配ること。**
逆に `scan-limit` と `max-horizontal-distance` / `max-vertical-distance` は Java 既定値が出荷 yml と
同じ値なので、jar だけ差し替えても既定で効く（ドリフトはテストが縛っている）。

## 本文コメント一覧(元のyml内での出現順)

### 直後: `max-extra-logs: 8`

```
tiers未定義/該当tierなしの場合のフォールバック既定値(トリガーになった原木1本は含まない)。
走査は「プレイヤーが設置した丸太」を木から除外する(2026-07-31 G1 レビュー指摘1)。
丸太で組んだ壁や家の上端を叩いても、視界外の最下段が一緒に消えることは無い。
```

### 直後: `cooldown-ticks: 200`

```
プレイヤー毎クールダウン(tick)。20tick=1秒。既定10秒(要調整)。
```

### 直後: `break-leaves: true`

```
幹に繋がる葉も一緒に壊すか(2026-07-30)。false にすると原木だけ消えて葉が空中に残る。
```

### 直後: `leaves-max: 512`

```
1回の伐採で壊す葉の絶対上限(2026-07-31 N2)。tiers 側に leaves-max があればそちらが優先。
0以下にすると旧挙動(leaves-per-log × 実際に伐った原木の本数)へ戻る。
```

### 直後: `leaves-per-log: 6`

```
旧キー(2026-07-30)。leaves-max を0以下にしたときだけ「伐った原木の本数 × この値」として使う。
葉は「伐採のおまけの片付け」なので道具の耐久も採取EXPも取らない(TreeFellingListener 参照)。
```

### 直後: `leaves-per-tick: 48`

```
1tickあたりに壊す葉の枚数(2026-07-31 N2)。512枚なら約11tick=0.55秒で樹冠が消える
(バニラのランダムティック崩壊は平均68秒、simulation-distance の外では止まる)。
0以下なら同tickで全部壊す — チャンク更新とライティング更新が集中するので非推奨。
```

### 直後: `leaves-decay-only: true`

```
true なら「バニラなら崩壊する葉」だけを壊す(2026-07-31 N2)。
= 設置された葉(persistent、装飾の葉壁)は壊さず、残った原木から距離6以内で支えられた葉も残す。
上限を桁で上げたので、false にすると樹冠が癒着したジャングル/ダークオークで
「1本伐ると林冠が連鎖消滅する」。既定 true を崩さないこと。
```

### 直後: `chain-drop-rolls-max: 32`

```
一括伐採1回あたりに引く drop-tables の上限回数(2026-08-24、既定は 32)。
連鎖で壊した葉は BlockBreakEvent を発火しないため、これが無いと一括伐採では
リンゴ等の追加ドロップが1回も抽選されない(手で葉を割ったときしか出ない)。
実際に引く回数は「壊した葉の枚数」とこの値の小さいほう。
葉1枚ごとに引くと1回で最大1024回になり手動と桁が変わるので上限を置いてある。
0以下にするとこの経路の抽選を行わない(2026-08-24 以前の挙動)。
```

### 直後: `scan-limit: 512`

```
「木全体」を把握する走査で読むブロックの上限本数(2026-07-31 G1 レビュー指摘6b で定数から出した)。
伐る本数の上限(max-extra-logs)とは別枠 — 上限で伐り残した幹も葉の走査の種に必要なため。
1回の原木破壊でメインスレッドがこの本数ぶんの getBlockAt を回すので、巨木林で tick に効くようなら
下げるためのレバー。0以下なら既定512へ戻す(走査ゼロにすると一括伐採が無言で死ぬため)。
```

### 直後: `max-horizontal-distance: 8` / `max-vertical-distance: 32`

```
叩いた位置からの距離の上限(2026-07-31 G1 round2 レビュー指摘2)。
これを超える丸太は走査も伐採もしない。設置丸太の除外(PlacedBlockTracker)は
BlockPlaceEvent を通った丸太しか覆えないので、WorldEdit/schematic/setblock/構造物生成で
置かれた丸太・ピストンで動いた丸太・チャンク上限FIFOで記録から落ちた丸太は「自然木」に見える。
距離で先に切ることで、記録に乗らない丸太建築でも「クリック位置から十数ブロック離れた視界外の行が
消える」という最悪ケースが起きなくなる(第二の歯止め)。
既定値の根拠(バニラ樹木の実寸より大きいので自然樹の伐採は一切変わらない):
  水平8 … 最も横に広がる原木構造は大マングローブの枝分かれで概ね ±6、
           巨大ジャングル/ダークオークの枝で ±4〜5。±8 なら 17x17 の footprint に収まる。
  垂直32 … 最も高い樹木はトウヒ/ジャングルの2x2 巨木で概ね30段。
巨木林で建築誤爆をさらに絞りたいなら小さくしてよい(自然樹も伐り残るようになる)。
0以下にするとその軸は無制限(2026-07-31 以前の挙動)。
```

### 直後: `tiers:` の1行目

```
2026-07-31 G1 レビュー指摘2 で 8/16/32/64 から倍にした。
なぜ上げたか: leaves-decay-only(既定true)は「バニラなら崩壊する葉」しか壊さないので、
幹を伐り切れない木では残った幹が樹冠を距離6以内で支え続け、葉が1枚も壊れない。
「葉の掃除がバニラより大幅に速く」を満たす唯一の道は幹を伐り切ることなので、
decay-only を緩めるのではなく本数上限を上げた(緩めるとジャングルで林冠が連鎖消滅する)。
tier ごとに伐り切れる想定(幹の本数):
  tier1=16 … オーク/バーチ/アカシア/サクラの通常木(幹4〜8本)、細いトウヒ(6〜13本)
  tier2=32 … ダークオークの2x2(幹24本前後)、マングローブの枝分かれ、大きめのアカシア
  tier3=64 … ジャングルの2x2 大木(幹40〜60本)、背の高いトウヒ
  tier4=128 … トウヒの2x2 巨木(幹80〜120本)、癒着した複数株
残余: これでも上限を超える巨木(最大級のトウヒ2x2やツタで繋がった塊)では幹が伐り残るので、
その木では依然として葉が残る。これはバグではなくバニラも崩壊させない葉である。
```

### `tiers:` の由来(旧コメントの保存)

```
tier(=スキルツリー側 dedicated-effects[].value)ごとの一括伐採上限本数。
元は旧small-tree-fell(8本)/large-tree-fell(64本)の配置(woodcutting.yml B/D)を移行した値
(2026-07-25 §6 Q1)。2026-07-31 N2 で葉の上限列 leaves-max を追加
(tier1=128/tier2=256/tier3=512/tier4=1024)。
max-extra-logs が0以下の行は従来どおり行ごとスキップされる(既存ymlの意味を変えないため)が、
leaves-max の省略/非正値は「グローバルの leaves-max へフォールバック」の意味で警告も出ない。
```

### 直後: `drop-tables:`

```
伐採ドロップテーブル(2026-07-23 stat-gate-overhaul §4): 葉(LEAVES系)破壊時、または原木破壊時
(一括伐採のトリガーになった1本のみ、連鎖破壊分は対象外)に、各カテゴリ独立でtrigger-chance-percent判定→
重み付き抽選。旧 apple-drop/golden-apple-drop/crystal-apple-drop の個別consumerを置換したもの
(確率は旧値を移植、要調整)。perkゲートは drop:woodcutting:<catId> / drop:woodcutting:item:<itemId>
で参照済みカテゴリ/アイテムのみ解放制御される。未参照は誰でも解放。
```
