---------------------------------------------------------------------------

### `break-vanilla-exp`（破壊時バニラEXP。機械突き合わせで判明した未収録キー）

```
break-vanilla-exp:
  base-exp: 0.25
  per-skill-base-exp: {}
  chain-max-blocks: 64
```

2026-08-18 ユーザー要望「もらえるバニラ経験値が多すぎる。現状の1/4程度にして設定もできるようにして」。
スキルツリーの `feature:break-vanilla-exp-<スキル>` を解放したプレイヤーが採取扱いのブロックを
壊したときに落ちる**バニラのEXPオーブ**の量。TFのスキルEXPとは別物。

- `base-exp`: 1回の破壊あたりのベース量。実際の付与量は `base-exp × (1 + 倍率ステの合計)`。
  `0.25` = 旧実装(`1.0`)の1/4。`0` にすると解放しても一切増えない(機能OFFと同じ)。
  小数を書いてよい — `giveExp` は整数しか受け取れないが、端数はプレイヤーごとに持ち越して
  1貯まったぶんだけ渡す(`0.25` なら「4回壊して1EXP」)。四捨五入ではないので、小さな値にしても
  「常に0に丸められて機能が死ぬ」ことは無い。
- `per-skill-base-exp`: 採取スキル別の上書き(省略可)。書いたスキルだけ `base-exp` より優先される。
  例: 採掘だけ多めにする → `per-skill-base-exp: { MINING: 0.5 }`
- `chain-max-blocks`: 連鎖破壊分にも配る上限ブロック数(2026-08-19 W-143 実サーバ報告「一括伐採発動時に
  1個分しか経験値が入らない」)。一括伐採／一括破壊／範囲収穫の連鎖分にも破壊時バニラEXPを配る。
  1バースト(＝同tick・同プレイヤー＝斧1振りぶん)でここまでのブロック数を数える。
  `0` を書くと連鎖分には配らない(＝2026-07-28以来の旧挙動へ戻る)。上限を設けている理由:
  無制限にすると一括破壊がそのままバニラEXP増殖装置になる(これが旧仕様で連鎖分を切っていた理由
  そのもの)。`64` の根拠: 出荷 tier の一括伐採は tier1=16 / tier2=64 / tier3=128 本なので、通常の
  伐採はほぼ全部数えつつ、最上位の1振りでも64ブロック分で止まる。段階破壊される葉はそもそも採取
  扱いにならない(出荷ymlに葉の行が無い)ので数に入らない。

### 直後: `level-diminishing:`（2026-07-26 EXP調整タスク3、既定OFF）

```
【2026-07-26 EXP調整タスク3】後半ヌルゲー化への栓: スキルレベル逓減カーブ(既定OFF)
---------------------------------------------------------------------------
レベルが上がるほど1回あたりのEXP取得量を減らしたい場合に使う。既定は gathering-enabled/
combat-enabled とも false = 常に倍率1.0(現行挙動そのまま)。「使うかどうかはユーザーが決める」
方針でオプトインにしてある。有効にすると "後半の伸びが鈍る"(同じ作業を繰り返しても
得られるEXPが徐々に減っていく)効果になる — 後半ヌルゲー化対策として使うことを想定している。
  gathering-enabled : MINING/FARMING/WOODCUTTING/DIGGING(タスク1の採取系)へ適用するか。
  combat-enabled    : HEAVY_WEAPONS/LIGHT_WEAPONS/ARCHERY/HEAVY_ARMOR/LIGHT_ARMOR/ARS_MAGIC
                       (武器討伐・弓術・防具被弾・魔法討伐/ブロック破壊)へ適用するか。
                       どちらか片方だけ有効化することもできる。
  formula           : exp_level_curve と同じ書式(%level% が現在レベルに置き換わる四則演算/べき乗式)。
                       評価結果がそのまま倍率になる(1.0=減衰なし)。既定は
                       "1 / (1 + %level% / 50)" — レベル0で1.0、レベル50で0.5、レベル150で0.25と、
                       なだらかに減っていく緩やかな逓減カーブ。急に0まで落ちない設計。
  floor             : 倍率の下限(これ未満には下がらない)。既定0.2 = どれだけレベルが上がっても
                       最低20%のEXPは入り続ける(完全に稼げなくなることを防ぐ安全弁)。
```

## 2026-07-26 追加: オーバーワールドEXP開放とTT対策

ymlヘッダ側にあるためコメント移設の対象外だが、editor保存でymlコメントが消えるのは同じなのでここに控える。

### `dungeon-only-exp` / `dungeon-exp-rate` / `outside-dungeon-exp-rate`

```
dungeon-only-exp: false          # 従来 true。true なら従来どおりダンジョン外は完全遮断(rateは無視)
dungeon-exp-rate: 0.375          # ダンジョン内の戦闘スキルEXP倍率(2026-08-21 新設。既定 1.0)
outside-dungeon-exp-rate: 0.1875 # ダンジョン外の戦闘スキルEXP倍率
```

**⚠️ プレイヤーが体感する「ダンジョンは外の何倍か」は、この2つの値の比。**
2026-08-21 のユーザー指示「オーバーワールドの討伐EXPを現在の3/4、ダンジョンを2倍(現在は4倍)」は
外 `0.25 → 0.1875`(＝3/4)、内 `1.0 → 0.375`(＝外の2倍)として入れた。
`dungeon-exp-rate` が無かった頃はダンジョン内が **1.0 固定**で、比は常に「外の4倍」だった。
片方だけ書き換えると比が変わるので、**倍率を決め直すときは必ず2つセットで書く**
(この関係は `SkillExpWorldRateTest#shippedConfigMakesDungeonExactlyTwiceTheOverworld` が縛る)。

キーを書かなければ `dungeon-exp-rate` は 1.0 へ落ちる ＝ 旧挙動。両方とも [0,1] にクランプされる。

合成規則は `SkillExpConfig.worldExpRate(boolean inDungeonWorld)` の1箇所に閉じている。
呼び出し側で「フラグを見てから倍率も見る」と書くと、片方を忘れた経路が静かに全額付与になり
エラーも出ないため、意図的に分岐を持たせていない。

対象は **軽/重武器(討伐) / 弓術 / 防具(被弾) / 魔法(討伐・ブロック破壊)**。
採取/釣り/クラフト等の非戦闘EXPは元から対象外。

### `daily-diminishing`(日次逓減。機械突き合わせで判明した未収録キー)

```
daily-diminishing:
  enabled: true
  window-hours: 24
  lock-release-hours: 24
  reset-id: "2026-08-19-w154"
  per-amount: 100000
  decay-per-amount: 0.9
  floor: 0.5
  exempt-skills: []
```

直近 `window-hours` 時間にそのスキルで稼いだ量に応じて取得量を薄める。`per-amount` を稼ぐたびに
1段落ち、1段ごとに `decay-per-amount` 倍になり `floor` で止まる。`spot-diminishing`(同一地点対策)とは
別勘定で、こちらは「総量の頭打ち」を担当する(`spot-diminishing` は「1箇所に固定して稼ぐことの相対的な
不利」だけを担当し、総量は縛らない)。

**W-154(2026-08-19、ユーザー指示「一度かかったら24時間で強制解除(100%)に戻す。修正時に全員の既に
かかっているロックを解除したい」)で追加した2キー**:

- `lock-release-hours`: 逓減が**発動した時刻**から数えて、この時間が経ったら蓄積ごとゼロに戻し
  取得量を100%へ戻す。0を書くと期限なし(＝下の指数減衰だけで戻る従来の挙動)。
  `window-hours`(指数減衰の時定数)だけでは**戻り切らない** — 24時間放置しても `e^-1 ≒ 37%` が
  残るので、一度下がった人はいつまでも下がったままに感じる。これがその報告への対処。
  数え始めは「最後にEXPを得た時刻」ではなく「逓減が発動した時刻」。稼ぎ続けていても24時間経てば
  必ず解除される(ユーザー選択)。等倍へ自然回復した時点で時計は捨てる。
- `reset-id`: この文字列を書き換えると、次回起動時に**全員の蓄積を1回だけ**削除する。適用済みの値を
  DBへ記録するので、再起動を繰り返しても2度は消えない。フラグ(true/false)ではなく合言葉にして
  あるのは、true のままだと再起動のたびに消えて逓減が永久に効かなくなり、false へ戻し忘れても
  その事故が誰にも気づかれないため。もう一度全員解除したくなったら、日付など別の文字列へ書き換える。

### `spot-diminishing`(TT・放置対策)

```
spot-diminishing:
  enabled: true
  radius: 16              # 「同じ場所」とみなす半径(ブロック)
  window-seconds: 300     # 直近何秒ぶんの撃破を数えるか
  threshold: 80           # ここまでは倍率1.0のまま
  decay-per-kill: 0.02    # しきい値超過1体あたりの減少幅
  floor: 0.4              # 倍率の下限(0にしない = 「稼げない」ではなく「割に合わない」に留める)
  exempt-dungeon-worlds: true
```

出荷値の意味: 同じ場所で5分以内に80体まではフルEXP。81体目から2%ずつ落ち、110体目で下限40%。
（Java 側のフォールバック既定は `radius: 24.0` / `threshold: 30` / `decay-per-kill: 0.05` / `floor: 0.1` で、
出荷 yml とは別物。**キーを消すと逓減が旧設定に戻る**ので、無効化したいときは `enabled: false` を書く。）

**2026-08-19 W-117 で緩和した。** 旧値(30体で減衰開始・48体で下限10%)は、エンドのエンダーマンや
ネザーのピグリンを「集めて刈る」正常なプレイが普通に届く密度で、TT を作っていないプレイヤーが
下限に張り付いていた。`outside-dungeon-exp-rate: 0.25` と掛かるため、重量Lv39で25レベのピグリン
≒170EXP が `170 × 0.25 × 0.1 ≒ 4EXP` まで落ちる（実サーバ報告「1〜10しか貰えない」と一致）。
**この機構は総量の頭打ちではない** —— 総量は `daily-diminishing` の役目で、こちらは
「1箇所に固定して稼ぐことを相対的に不利にする」だけを担当する。下限を上げたのはそのため。

**カウンタを増やすのは撃破のみ。** 被弾(防具EXP)や弓の命中では増えない。
呼ぶたびに記録する実装だと、5体を相手に各6発もらうだけで30件に達し、
正常なプレイでEXPが減り始めてしまうため(2026-07-26 のレビューで修正)。
倍率自体は武器/防具/魔法討伐/バニラ経験値オーブが読む — 経路ごとに別勘定にすると、
経路を混ぜるだけで逓減を回避できてしまうので、カウンタは1本で共有する。

`exempt-dungeon-worlds: true`(既定)はダンジョンを対象外にする。
ダンジョンは湧き潰しではなく有限のスポーンを消化する場所で、アリーナ型だと1箇所に留まって
戦うのが正常な遊び方なので、ここで逓減させると本来推奨したい遊び方を罰することになる。
