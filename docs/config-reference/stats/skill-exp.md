config-editor で保存すると本文コメントは復元されないため([tools/config-editor/lib/yamlio.js](../../tools/config-editor/lib/yamlio.js) 参照)、運用ドキュメントとしてここに退避している。
**設定値そのもの(キー/値)はymlの方を参照。ここはコメント本文のみを収録し、移設前後でキー・値が完全一致することをスクリプトで検証済み。**

### 直後: `gathering: / exp-mode: drop_sum`（2026-07-26 EXP調整タスク1）

```
【2026-07-26 EXP調整タスク1】採取EXPの算出方式
---------------------------------------------------------------------------
鉱石側の値(skills/base/mining_progression.yml の experience.mining_break、47種類)は元々
存在するが、旧実装は「ブロックが対象として登録されているか」の判定だけに使い、実際に付与する量は
常に「ドロップ品(素材側)の値の合計」だった。そのため DIAMOND_ORE(ブロック側400) も
DEEPSLATE_DIAMOND_ORE(ブロック側600) も、ドロップが同じ DIAMOND(素材側200) なのでどちらも
200になり、「深層岩バリアントは掘るのが大変な分EXPが高い」という設計が死んでいた。
exp-mode でこれを選べるようにする(採取全スキル=MINING/FARMING/WOODCUTTING/DIGGING 共通)。
  drop_sum(既定)   : 従来どおりドロップ品の値の合計。現行の実サーバ挙動と完全に同じ結果になる。
  block_value       : ブロックそのものに設定された値をそのまま使う(DEEPSLATE系が高くなる等、
                       ブロック側の意図がそのまま反映される)。
  max               : ドロップ合計とブロック値の大きい方。
どのモードでも次の2点は変わらない(壊さないこと、という制約どおり):
  ・同一素材のドロップは1回だけ加算(スタック数は無視=幸運エンチャで増殖しない)
  ・素手等、要求ツールを満たさずドロップが空になった破壊はEXP 0
```

### 直後: `combat: / mode: flat`（2026-07-26 EXP調整タスク2）

```
【2026-07-26 EXP調整タスク2】戦闘EXPを与ダメージ比例+モブレベル係数にする
---------------------------------------------------------------------------
旧実装は命中1回で常に exp-per-hit の固定値(既定1.0)——与えたダメージ量にもモブの強さにも
一切連動していなかった。mode: damage_scaled に切り替えると、1ヒットのEXPが
  (与ダメージ × damage-scale) × (1 + モブレベル × mob-level-scale)
で決まるようになる。モブレベルは EliteMobs/ダンジョン連携が使っているのと同じ MobData の
レベル(PDC)を読む。レベル情報を持たないモブ(平地の通常モブ等)は0扱い=倍率1.0。
  mode: flat(既定)         : 従来どおり exp-per-hit / by-skill の固定値。実サーバ挙動は不変。
  mode: damage_scaled       : 上記の与ダメージ比例+モブレベル係数。
damage-scale/mob-level-scale は mode: damage_scaled のときのみ使われる。既定値の根拠:
  damage-scale=0.1     : TF標準武器の与ダメージは概ね5〜10前後(item-stats.yml参照)なので、
                          1ヒットあたり0.5〜1.0程度になり、旧来のexp-per-hit=1.0と近い体感値になる
                          ように選んだ(「いきなり別ゲーにならないように」の指示どおり)。
  mob-level-scale=0.02  : モブレベル50で+100%(2倍)、レベル100で+200%(3倍)。ダンジョン深部の
                          強モブほど旨みが出るが、極端な指数爆発は避けた保守的な値。
```

### 直後: `level-diminishing:`（2026-07-26 EXP調整タスク3、既定OFF）

```
【2026-07-26 EXP調整タスク3】後半ヌルゲー化への栓: スキルレベル逓減カーブ(既定OFF)
---------------------------------------------------------------------------
レベルが上がるほど1回あたりのEXP取得量を減らしたい場合に使う。既定は gathering-enabled/
combat-enabled とも false = 常に倍率1.0(現行挙動そのまま)。「使うかどうかはユーザーが決める」
方針でオプトインにしてある。有効にすると "後半の伸びが鈍る"(同じ作業を繰り返しても
得られるEXPが徐々に減っていく)効果になる — 後半ヌルゲー化対策として使うことを想定している。
  gathering-enabled : MINING/FARMING/WOODCUTTING/DIGGING(タスク1の採取系)へ適用するか。
  combat-enabled    : HEAVY_WEAPONS/LIGHT_WEAPONS/ARCHERY/HEAVY_ARMOR/LIGHT_ARMOR/ARS_MAGIC
                       (タスク2の武器命中+既存の防具被弾+魔法詠唱)へ適用するか。
                       どちらか片方だけ有効化することもできる。
  formula           : exp_level_curve と同じ書式(%level% が現在レベルに置き換わる四則演算/べき乗式)。
                       評価結果がそのまま倍率になる(1.0=減衰なし)。既定は
                       "1 / (1 + %level% / 50)" — レベル0で1.0、レベル50で0.5、レベル150で0.25と、
                       なだらかに減っていく緩やかな逓減カーブ。急に0まで落ちない設計。
  floor             : 倍率の下限(これ未満には下がらない)。既定0.2 = どれだけレベルが上がっても
                       最低20%のEXPは入り続ける(完全に稼げなくなることを防ぐ安全弁)。
```

## 2026-07-26 追加: オーバーワールドEXP開放とTT対策

ymlヘッダ側にあるためコメント移設の対象外だが、editor保存でymlコメントが消えるのは同じなのでここに控える。

### `dungeon-only-exp` / `outside-dungeon-exp-rate`

```
dungeon-only-exp: false        # 従来 true。true なら従来どおりダンジョン外は完全遮断(rateは無視)
outside-dungeon-exp-rate: 0.25 # ダンジョン外の戦闘スキルEXP倍率。ダンジョン内は常に 1.0
```

合成規則は `SkillExpConfig.worldExpRate(boolean inDungeonWorld)` の1箇所に閉じている。
呼び出し側で「フラグを見てから倍率も見る」と書くと、片方を忘れた経路が静かに全額付与になり
エラーも出ないため、意図的に分岐を持たせていない。

対象は **武器(命中) / 防具(被弾) / 魔法(詠唱)** の3経路。
魔法は 2026-07-26 まで実装側でゲートされておらず素通りしていたが、
`ArsProgressionBridge.grantMagicExp` で倍率を掛けるよう修正済み。
採取/釣り/クラフト等の非戦闘EXPは元から対象外。

### `spot-diminishing`(TT・放置対策)

```
spot-diminishing:
  enabled: true
  radius: 24.0            # 「同じ場所」とみなす半径(ブロック)
  window-seconds: 300.0   # 直近何秒ぶんの撃破を数えるか
  threshold: 30           # ここまでは倍率1.0のまま
  decay-per-kill: 0.05    # しきい値超過1体あたりの減少幅
  floor: 0.1              # 倍率の下限(0にしない = 「稼げない」ではなく「割に合わない」に留める)
  exempt-dungeon-worlds: true
```

既定値の意味: 同じ場所で5分以内に30体まではフルEXP。31体目から5%ずつ落ち、48体目で下限10%。

**カウンタを増やすのは撃破のみ。** 被弾(防具EXP)や命中(武器EXP)では増えない。
呼ぶたびに記録する実装だと、5体を相手に各6発もらうだけで30件に達し、
正常なプレイでEXPが減り始めてしまうため(2026-07-26 のレビューで修正)。
倍率自体は武器/防具/バニラ経験値オーブの3経路すべてが読む — 経路ごとに別勘定にすると、
経路を混ぜるだけで逓減を回避できてしまうので、カウンタは1本で共有する。

`exempt-dungeon-worlds: true`(既定)はダンジョンを対象外にする。
ダンジョンは湧き潰しではなく有限のスポーンを消化する場所で、アリーナ型だと1箇所に留まって
戦うのが正常な遊び方なので、ここで逓減させると本来推奨したい遊び方を罰することになる。
