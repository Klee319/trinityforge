# 管理者ガイド: 設定リファレンス

全設定ファイルを、ドメイン別に「キー・既定値・意味」の表で網羅します。プレイヤーバランス調整の入口です。

## このページでわかること

- TrinityForge / ArsPaper / EliteMobs(改造版) の全設定ファイルのキーと既定値
- 各設定が「何を」「どう」変えるのか
- 数値は暫定であること、編集後の反映方法(reload)

> **共通の前提**
> - 特記なき限り、設定編集後は **`/trinityforge reload`(ArsPaper側は `/ars reload`)** で反映されます。反映されない例外(マナ回復間隔・エンチャ登録など)は [導入とコマンド](10-管理者ガイド-導入とコマンド.md) の §6 を参照。
> - percent 値はコード内では分数表現(0.20 = 20%)です。以下の表もその表記に従います。
> - `importmobs` は `mob-import.yml` / `themes.yml` 編集後、**reload → 再import** の順で実行してください([導入とコマンド](10-管理者ガイド-導入とコマンド.md) §6.3)。
> - **このページは「バランス調整で触る値」を中心にまとめた案内**です。全キーの網羅一覧はリポジトリの
>   `docs/config-reference/` が一次情報で、そちらの方が常に新しいです。ここと食い違ったら
>   `docs/config-reference/` と出荷 yml のコメントを信じてください。
> - 設定の多くは GUI 設定エディタ(`tools/config-editor`)からも編集できます。

# 第1部: TrinityForge

## 1. combat(戦闘)

### 1.1 `combat/damage.yml` — ダメージ計算の中核

物理/魔法は同じ8ステップの対称パイプラインを通ります(詳細は [戦闘のしくみ](02-戦闘のしくみ.md))。

| キー | 既定値 | 意味 |
|---|---|---|
| `physical.base-coefficient` | 1.0 | 物理の基礎ダメージ全体倍率 |
| `physical.min-component-damage` | 1.0 | 物理の最小ダメージ床(必ずこれだけは通る) |
| `magical.base-coefficient` | 1.0 | 魔法の基礎ダメージ全体倍率 |
| `magical.min-component-damage` | 1.0 | 魔法の最小ダメージ床 |
| `magical.scale-with-combat-level` | true | 魔法にも `level-scaling` を掛けるか |
| `magical.attack-power-scale` | 1.0 | 触媒(杖・魔導書)の攻撃力が魔法ダメージへ乗る割合 |
| `level-scaling.per-level` | **0.01** | `base *= (1 + per-level × 戦闘レベル)`。**装備非依存の唯一の生ダメージ成長源**(Lv100 で ×2.0) |
| `melee-charge.enabled` / `min-multiplier` / `exponent` | true / 0.1 / 1.6 | 近接の「溜め」。クールダウン中に振ると最低 10% まで落ち、`exponent` が大きいほど溜め切りの価値が上がる |
| `attack-speed.min-effective` | 0.1 | 攻撃速度の実効下限 |
| `attack-speed.reconcile-interval-ticks` | 10 | 攻撃速度の再計算間隔 |
| `defense.max-mitigation-rate` | 0.9 | 防御率%・耐性%・被ダメ軽減%を**それぞれ個別に**上限クランプ(合算上限ではない)。3種は掛け算で重なるので合計軽減は90%を超えうる |
| `defense.max-dodge-chance` | 0.9 | 回避率の上限 |
| `defense.max-crit-reduction` | 1.0 | 防具強度(=会心軽減率)の上限。1.0=上限なし |
| `defense.enchant-protection-scale` | 0.5 | バニラのダメージ軽減エンチャントを何割の重みで効かせるか |
| `bleed.tick-interval-ticks` / `bleed.ticks` | 20 / 5 | 出血の間隔と回数(既定=1秒ごとに5回) |
| `aoe.hit-players` | false | 範囲攻撃がプレイヤーにも当たるか |
| `vanilla-armor.defense-rate-per-point` | **0.015** | バニラ防具1点あたりの防御率% |
| `vanilla-armor.defense-rate-max` | 0.8 | 上記の上限 |
| `vanilla-armor.armor-strength-per-point` | **0** | バニラ armor_toughness から会心軽減へ変換する量。現在は0(=変換しない) |

**PvP**(`pvp:`) — 有効ではありますが、事実上ダメージが通りません。

| キー | 既定値 | 意味 |
|---|---|---|
| `pvp.enabled` | true | プレイヤー間ダメージの計算自体を通すか |
| `pvp.damage-multiplier` | **0.001** | PvP ダメージの倍率 |
| `pvp.max-damage-percent-of-max-health` | **0.25** | 1発で削れる相手の最大体力の割合上限 |

**日光炎上**(`sunlight-burn:`) — 日光で燃えるモブのダメージを%HP化します。`mobs:` に列挙した EntityType だけが対象で、火属性の着火と区別できないため**ホワイトリスト必須**です。

| キー | 既定値 |
|---|---|
| `sunlight-burn.enabled` | true |
| `sunlight-burn.damage-percent-of-max-health` | 0.1 |
| `sunlight-burn.mobs` | ゾンビ系・スケルトン系・ファントム・馬系の10種 |

**序盤補正**(`early-level-attack:`) — 戦闘レベル 0 付近の火力を抑えます。

| キー | 既定値 | 意味 |
|---|---|---|
| `early-level-attack.enabled` | true | 有効化 |
| `early-level-attack.until-level` | 10 | この戦闘レベルまで補正を掛ける |
| `early-level-attack.level-0-multiplier` | 0.7 | 戦闘レベル0での倍率(以降 Lv10 で 1.0 へ線形回復) |

**レベル差の足きり**(`level-cutoff:`) — 自分より格下の敵から報酬を得にくくします。詳しくは [育成と解放](08-育成と解放.md)。

| キー | 既定値 | 意味 |
|---|---|---|
| `under-level.exp-threshold` | 15 | この差までは減衰なし。**「相手のレベルが自分より高い」方向の差**を測る点に注意 |
| `under-level.exp-decay-per-level` | 0.067 | 閾値を超えた1レベルごとの減衰(15+15=30 差で 0 になる) |
| `under-level.item-threshold` | 20 | ドロップ側の閾値 |
| `under-level.drop-rate` | -1 | -1 = ドロップ側の足きりは無効 |
| `over-level.threshold` | -1 | -1 = 格上側の足きりは無効 |

**ダンジョンの挑戦レベル報酬**(`dungeon-level-reward:`) — 推奨レベルより高い/低いダンジョンへ挑んだときの増減。

| キー | 既定値 | 意味 |
|---|---|---|
| `pivot-level` / `step` | 35 / 5 | 基準レベルと1段の幅 |
| `drop-bonus-per-step` | 0.08 | 1段ごとのドロップ増減(±8%) |
| `drop-bonus-cap` / `drop-penalty-cap` | 0.5 / 0.3 | ドロップ増減の上限(+50% / −30%) |
| `exp-bonus-per-step` | 0.04 | 1段ごとのEXP増減(±4%) |
| `exp-bonus-cap` / `exp-penalty-cap` | 0.25 / 0.2 | EXP増減の上限(+25% / −20%) |

**耐久ペナルティ**(`durability:`) — 被弾・死亡で装備が削れます。**既定ではダンジョン内だけ**です。

| キー | 既定値 | 意味 |
|---|---|---|
| `durability.dungeon-only` | true | ダンジョン内のみ適用 |
| `durability.respect-unbreaking` | true | 耐久力(Unbreaking)エンチャントを尊重する |
| `durability.prevent-break` | true | この機構では壊れない(残り1で止まる) |
| `durability.on-hit.percent-of-max` | 0.001 | 被弾1回あたり最大耐久の0.1%(最低1)。オフハンドも対象 |
| `durability.on-death.percent-of-max` | 0.1 | 死亡時に最大耐久の10%(最低1)。手持ちも対象 |

**武器基礎値の式**(`weapon-base-formula:`) は `enabled: false` で無効です(有効化すると `a`/`b` から武器の基礎攻撃力を式で出します)。

**攻撃スタットキー写像**(武器PDC→AttackStats。文字列キー名の対応表。通常変更不要):

| キー | 既定値 |
|---|---|
| `attack-stat-keys.flat-bonus-damage` | "flat-bonus-damage" |
| `attack-stat-keys.percent-bonus-damage` | "percent-bonus-damage" |
| `attack-stat-keys.crit-chance` | "crit-chance" |
| `attack-stat-keys.crit-damage` | "crit-damage" |
| `attack-stat-keys.penetration` | "penetration" |
| `attack-stat-keys.damage-modifier` | "damage-modifier" |
| `attack-stat-keys.fixed-damage` | "fixed-damage" |

**防御スタットキー写像**(防具PDC→DefenseStats):

| キー | 既定値 | 意味 |
|---|---|---|
| `defense-stat-keys.phys-resistance` | "phys-resistance" | 物理耐性(typed) |
| `defense-stat-keys.magic-resistance` | "magic-resistance" | 魔法耐性(typed) |
| `defense-stat-keys.phys-flat-defense` | "phys-flat-defense" | 物理守備力(step6・物理のみ引き算) |
| `defense-stat-keys.magic-flat-defense` | "magic-flat-defense" | 魔法守備力(step6・魔法のみ引き算) |
| `defense-stat-keys.damage-reduction` | "damage-reduction" | 被ダメ軽減(共通) |
| `defense-stat-keys.dodge-chance` | "dodge-chance" | 回避(共通) |
| `defense-stat-keys.armor-strength` | "armor-strength" | 防具強度=会心軽減率(step2・会心の上乗せ分のみ減) |

> 防御率%(armor-defense-rate)だけは `defense-stat-keys` に**ありません**。これはバニラの armor から読むためで、ここに書くと二重計上になります。防具強度(armor-strength)はアイテム由来ぶんをここで読み、加えてバニラ armor_toughness(頑丈さ)からも会心軽減として少量が上乗せされます(`vanilla-armor.armor-strength-per-point`)。守備力は物理・魔法で別キーに分かれました(旧 `flat-defense` は廃止)。

### 1.2 `combat/mob-defaults.yml` — プロファイル無しモブの既定防御

すべて 0.0(バニラベースライン)。このフォールバックが実際に使われるのは**非LivingEntity**の被弾のみで、素のバニラモブは実際にはバニラ防具ミラーを使います。

| キー | 既定 | 範囲 |
|---|---|---|
| `physical.defense-rate` / `resistance` / `damage-reduction` | 0.0 | [0,1] |
| `physical.flat-defense` | 0.0 | [0,100000] |
| `magical.defense-rate` / `resistance` / `damage-reduction` | 0.0 | [0,1] |
| `magical.flat-defense` | 0.0 | [0,100000] |
| `armor-strength`(両タイプ共通) | 0.0 | [0,100000] |

### 1.3 `combat/mob-import.yml` — EliteMobs→モブプロファイル変換ポリシー

`/tf importmobs` の変換ルール。既定はすべて 0.0(バニラベースライン、ハードコードのバランスなし)。各防御値は `base + per-level * level` で算出されます。

| キー | 既定 | 意味 |
|---|---|---|
| `level.source` | `ELITEMOBS` | level の出所。`ELITEMOBS`(モブ自身のlevel) か `FIXED` |
| `level.fixed` | 1 | `source=FIXED` 時に使う固定level |
| `level.default` | 1 | `source=ELITEMOBS` で level が非数値時の既定 |
| `theme.default` | "" | 全変換モブに付与するテーマ(空=なし) |
| `physical.*` (defense-rate/resistance/damage-reduction/flat-defense) | `{base:0.0, per-level:0.0}` | 物理防御ramp |
| `magical.*` (同上) | `{base:0.0, per-level:0.0}` | 魔法防御ramp |
| `armor-strength` | `{base:0.0, per-level:0.0}` | 防具強度ramp(共通) |

> `combat/mob-profiles.yml` は `importmobs` が生成し、手編集で「逆張り」モブを追加できます。手編集エントリは再importでも温存されます。

**モブ系はこの3ファイルが実バランスの本体です**(`mob-import.yml` は変換ポリシーにすぎません)。

| ファイル | 中身 |
|---|---|
| `combat/mob-types.yml` | バニラモブの種族別ステータス(HP・攻撃・物理/魔法比率)。**「敵がどれくらい強いか」の一次情報** |
| `combat/mob-overrides.yml` | ダンジョン(EliteMobs スコープ)ごとの上書き。攻撃係数・最大体力倍率・特殊攻撃はここ |
| `combat/mob-level-table.yml` | モブレベル→基礎値のテーブル |
| `combat/mob-abilities.yml` | 特殊攻撃(能力)の定義 |
| `combat/stat-caps.yml` | ステータスの上限(TF寄与分に対する上限) |
| `combat/display.yml` | ダメージ表示・頭上表示の設定 |

### 1.4 `combat/base-stats.yml` — プレイヤー基礎ステータス

全プレイヤーに一律で加算される基礎ステータスの初期値。装備・スキル・ロールバフ等の合算に「もう1レイヤ」として加わります。**出荷時は全ステが 0 で列挙されており、`crit-chance: 0.05`(会心率5%)と `crit-damage: 0.5`(会心ダメージ+50%)の2つだけが 0 以外**です。つまり素手でも会心は出ます。

| キー | 既定 | 意味 |
|---|---|---|
| `base-stats.<stat>` | ほぼ全て 0 | ステ名(`lore.yml` のステ名。例 `crit-chance` / `phys-flat-defense` / `max-health`)→ 基礎値 |
| `base-stats.crit-chance` | **0.05** | 全プレイヤー共通の会心率 |
| `base-stats.crit-damage` | **0.5** | 全プレイヤー共通の会心ダメージ |

- 値の書き方は `item-stats.yml` と同じ(PERCENT系は「5」=5%、FLAT系はそのままの数値)。編集後は `/trinityforge reload` で即反映。
- 体力・移動速度・攻撃速度・リーチ・ノックバック耐性などの属性系キーはバニラAttribute経路へ、それ以外は合算マップへ、それぞれ二重計上なく適用されます(近接・魔法の両経路に対称に加算)。
- ⚠ `attack-power`(攻撃力) だけは特殊で、ここに基礎値を入れると全プレイヤーの素手/バニラ武器の基本ダメージが置き換わり、ダメージ系エンチャントも無効化されます。**通常は空欄のまま**にしてください(設定するとロード時に警告が出ます)。綴り間違いなど、プレイヤーに効かないキーもロード時に警告されます。
- 上限クランプはありません(全員一律の運営判断として意図的)。

> このファイルは config-editor の「プレイヤー基礎ステータス」画面からも編集できます(空欄=バニラ)。

## 2. stats(ステータス・厳選)

ステータスは不変ベイクされず、PDCには **rollSeed(long) と quality(int) の2値だけ**が保存され、表示・攻撃・防御の値はすべてテーブルから毎回導出されます。だからテーブルを編集して reload すれば既存アイテムも再バランスされます(詳細は [ステータスと厳選](03-ステータスと厳選.md))。

### 2.1 `stats/item-stats.yml` — アイテム個別ステ定義

`stats/roll.yml` と `stats/material-base.yml` は廃止済みで、現在は **`stats/item-stats.yml` が唯一のステ定義元**です。Material名(例 `DIAMOND_SWORD`)または `Material#CustomModelData`(例 `EMERALD#5104`)をキーに、アイテム1品ずつステを設定します。CMDを持たない素の Material エントリは、そのMaterialの全品(素のバニラ品含む)に適用されます。

各アイテムのエントリは3層構成です。

| 層 | 意味 |
|---|---|
| `fixed` | ステ値を直接指定(上書き)。rollSeedの有無に関係なく全アイテムに適用 |
| `per-quality` | 品質1段あたりの増分。最終値 ＝ fixed ＋ (step × 品質Lv) |
| `random` | ランダムロール層(段2)。`{<stat>: {min, max}}` 形式。ここに書いたステ「だけ」が、そのレンジを対象に品質に応じたロール分布(§2.2参照)で抽選され、fixed／per-quality の上に加算される(物理・魔法共用)。抽選値はアイテムの rollSeed で決定的。fixed/per-quality 未設定のステに random だけ書いた場合は基礎0にロール分だけ加算 |

> **2026-08-22 時点で `item-stats.yml` は空の雛形ではありません。** 約 490 エントリ(バニラ装備＋TF/Ars のカスタム装備)が実値入りで出荷されています。以下の表は書き方の例で、実際の値は出荷 yml か GUI 設定エディタで確認してください。

以下は「このように設定する」という**書き方の例**です。

**攻撃系(武器)の設定例**:

| スタット | fixed例 | random例(min〜max) | 意味 |
|---|---|---|---|
| crit-chance | 0.0 | 0.0〜0.15 | クリティカル率 |
| crit-damage | **0.5** | 0.0〜0.5 | クリティカルダメージ(fixedで+50%を持つ例外設定) |
| penetration | 0.0 | 0.0〜0.3 | 防御貫通 |
| flat-bonus-damage | 0.0 | 0.0〜4.0 | 固定追加ダメージ |
| percent-bonus-damage | 0.0 | 0.0〜0.2 | 割合追加ダメージ |
| bleed-chance | 0.0 | 0.0〜0.1 | 出血発動確率 |
| bleed-damage | 0.0 | 0.0〜2.0 | 出血1tickあたりの物理ダメージ |

**防御/属性ミラー系(武器以外＝防具、vanilla attribute へミラー)の設定例**:

| スタット | fixed例 | random例(min〜max) | ミラー先 |
|---|---|---|---|
| armor-defense-rate | 0.0 | 0.0〜3.0 | armor |
| max-health | 0.0 | 0.0〜4.0 | max_health(2.0=ハート1個) |
| knockback-resistance | 0.0 | 0.0〜0.1 | knockback_resistance |
| move-speed | 0.0 | 0.0〜0.05 | movement_speed(分数表記。0.05=+5%) |

> `armor-strength`(防具強度) は会心軽減率%へ役割変更したため、**もはや armor_toughness へはミラーされません**(TF独自の会心軽減として下の防御系で消費)。

**TF専用防御系(防具、attribute化しない)の設定例**:

| スタット | fixed例 | random例(min〜max) | 意味 |
|---|---|---|---|
| phys-resistance | 0.0 | 0.0〜0.05 | 物理耐性%(typed・貫通不可) |
| magic-resistance | 0.0 | 0.0〜0.05 | 魔法耐性%(typed・貫通不可) |
| phys-flat-defense | 0.0 | 0.0〜2.0 | 物理守備力(step6・物理ダメージのみ引き算) |
| magic-flat-defense | 0.0 | 0.0〜2.0 | 魔法守備力(step6・魔法ダメージのみ引き算) |
| armor-strength | 0.0 | 0.0〜0.2 | 防具強度=会心軽減率(step2・会心の上乗せ分のみ減。通常ダメージ不干渉) |
| damage-reduction | 0.0 | 0.0〜0.03 | 被ダメージ軽減% |
| dodge-chance | 0.0 | 0.0〜0.02 | 回避率(攻撃全体を無効化) |

> 上表は `crit-damage` を除き全 fixed が 0.0 の設定例です。random に書いたステだけがオプトインでロール対象になる点に注意してください(書かなければロールされません)。

### 2.2 `stats/quality.yml` — 品質モデル

品質は次の2段の split-normal(上下非対称な正規分布)で決まります。

- **段1 = 品質ティア抽選(0..maxQuality)**: mode(期待品質)を中心に、上側は `spread-up`、下側は `spread-down` のσで正規分布抽選し [0, maxQuality] にクランプ。mode はクラフト/ドロップ/釣りで決まる(§2.3, §2.6参照)。
- **段2 = ランダムロール層の到達分布**: `item-stats.yml` の `random` に書いたステが対象。到達割合 R∈[0,1] を、品質比例の中心(qNorm=品質/maxQuality)を mode とする split-normal で抽選し、上側は `roll-spread-up`、下側は `roll-spread-down` のσを使う。

| キー | 既定値 | 意味 |
|---|---|---|
| `max-quality` | 9 | 品質段数の**フォールバック**。実際の段数は `quality-tiers.yml` のエントリ数が決めるので、現行は **品質0〜15(16段)** です |

### 2.6 `stats/lore.yml` — Lore(説明文)生成

| キー | 既定値 | 意味 |

| `layout.line-template` | `<gray><icon><name>：<value></gray>` | 1行のMiniMessageテンプレ(プレースホルダ icon/name/value) |

### 2.7 `stats/craft-quality.yml` — クラフト品質

クラフト時: カテゴリに対応する生産スキルの最高Lvから品質の中心(mode)を決めます。`mode = base-quality + bestLevel / skill-levels-per-quality`、最終品質は mode を中心に `quality.yml` の `spread-up`／`spread-down` で split-normal 抽選しクランプして決まります(±spread の一様ぶれではありません)。

|---|---|---|
| `mode.skill-levels-per-quality` | 10 | 品質+1に必要なスキルレベル数 |
| `mode.base-quality` | 0 | クラフトの基準品質 |
| `drop.enabled` | true | 敵ドロップの品質を「敵の強さ駆動」にするか。false だと一様分布 |
| `drop.strength-per-quality` | 10 | 敵の強さ(エリートレベル)いくつで品質+1か |
| `drop.base-quality` | 0 | ドロップの基準品質 |
| `workbench.upswing-scale` / `upswing-flat` | 1.0 / 0.0 | 作業台クラフトの上振れσを、ステ `workbench_upswing_bonus` から何倍＋いくつ動かすか |
| `workbench.downswing-reduction-scale` / `-flat` | 1.0 / 0.0 | 作業台クラフトの下振れσをどれだけ削るか |
| `ritual.upswing-scale` ほか4キー | 1.0 / 0.0 | 儀式クラフト側の同じ4つ。**2026-08 に作業台と分離**され、鍛冶ツリーのパークが儀式へ漏れなくなった |

### 2.8 属性写像 — TFスタット→バニラAttribute写像

PDCが数値の真実で、対応物を持つものだけをバニラAttributeへミラーします。これは現行では**固定実装**であり、`stats/attribute-map.yml` は存在しません。変更は設定ファイルではなく実装変更が必要です。

| キー | attribute | operation | scale |
|---|---|---|---|
| knockback_resistance | knockback_resistance | ADD_NUMBER | 1.0 |
| armor_defense_rate | armor | ADD_NUMBER | 1.0 |
| max_health | max_health | ADD_NUMBER | 1.0 |
| move_speed | movement_speed | ADD_SCALAR | 1.0 |
| attack_speed | attack_speed | ADD_NUMBER | 1.0 |
| attack_reach | entity_interaction_range | ADD_NUMBER | 1.0 |

> `armor_strength`(防具強度) はかつて `armor_toughness` へミラーしていましたが、会心軽減率%へ役割変更したため**この表から除外**されました。現在はバニラAttributeへは写像せず、TF独自の会心軽減(step2)としてのみ働きます。

> `attack_power` は `item-stats.yml` 由来のステで、武器の追加ダメージ系(flat-bonus-damage 等)は PDC-only で combat パイプラインが消費します。バニラ attribute へはミラーされ**ません**(attack_damage との二重計上を避けるため、意図的にこの表から除外)。詳細は [実装状況と注意点](12-実装状況と注意点.md)。
>
> `attack_speed`(攻撃速度=毎秒の手数)はバニラ attack_speed 属性への加算です(既定基礎4.0、剣などは内部でマイナス補正)。攻撃を当てた直後にその武器を一定秒数だけ使用不可にする**アイテムCT**(`item-cooldown`)は別軸で、attribute へは写像せず TF 側のクールダウン機構(`Player#setCooldown`、近接のみ)で処理します(表示は `lore.yml` の `item-cooldown`)。

### 2.9 `items/catalog.yml` — カスタムアイテム定義

武器、長槍、杖、ソース系素材・装備、圧縮ブロックなどの本番用定義を含みます。実際の一覧はこのYAMLが正本です。

- フィールド: `material`(必須), `display-name`(任意MiniMessage), `custom-model-data`(任意int), `bind-type`(任意、既定 MATERIAL_TRADEABLE), `use-level-requirement`(任意、0=無制限), `use-skill`(任意)。
- ランダム味付けはここに書かず、build時に item-stats.yml + quality.yml からライブ導出されます。
- **ArsPaper の魔道防具もここへ移りました**。3系統(Guardian/Arcane/Weaver) × 5ティア(novice/apprentice/archmage/sage/starseer) × 4部位 = **60品**が `mage_<系統>_<ティア>_<部位>` のIDで定義されています(旧 ArsPaper `armors.yml` は廃止)。
- `use-skill` は**分類マーカーではありません**。採取ツールにも付いているので、これをそのまま「EXPの付与先スキル」として使うと斧で殴って伐採EXPが入ります。
- 関連: `items/material-lists.yml`(素材グループ)、`items/equipment-assets.yml`(モデル/テクスチャ)、`items/external-items.yml`(ArsPaper 側IDの登録。**ここが空だとレシピ帳に出るのに永久にクラフト不可**)。

## 3. progression(育成)

### 3.1 `progression/role-buffs.yml` — ロール(職業)

戦闘ロール3種と補助ロール5種を定義します。ロールは `/tf status` から選び、**一度決めると既定では変更できません**(`role-change.allow-change: false`)。

**戦闘ロール**:

| id | 表示名 | 効果 |
|---|---|---|
| `swordfighter` | 剣闘士 | 物理ダメージが敵の防御率を **20% 貫通**(`penetration: 0.2`) |
| `mage` | 魔術師 | 魔法ダメージに **割合追加ダメージ +30%**(`percent-bonus-damage: 0.3`) |
| `tank` | 守衛 | **被ダメージ −10%**、**ヘイト 1.5倍**(`hate-threat-multiplier`) |

**補助ロール**(対応スキルのEXP倍率＋常時ポーション効果):

| id | 表示名 | EXP倍率 | 常時効果 |
|---|---|---|---|
| `farmer` | 農家 | FARMING ×1.25 | 村人との取引が有利(HERO_OF_THE_VILLAGE) |
| `fisher` | 漁師 | FISHING ×1.35 | 幸運(LUCK) |
| `miner` | 鉱夫 | MINING ×1.15 | 採掘速度上昇(HASTE) |
| `digger` | 土工 | DIGGING ×1.35 | 移動速度上昇(SPEED) |
| `woodcutter` | きこり | WOODCUTTING ×1.15 | 火炎耐性(FIRE_RESISTANCE) |

| キー | 既定値 | 意味 |
|---|---|---|
| `role-change.allow-change` | **false** | ロールの変更を許可するか |
| `role-change.cooldown-minutes` | 120 | 変更を許可したときの再変更クールダウン |
| `role-change.first-choice-free` | true | 初回選択はクールダウン対象外 |
| `role-change.nearby-enemy-radius` | 0 | 近くに敵がいると変更を拒否する半径(0=無効) |

### 3.2 `progression/combat-level.yml` — 戦闘レベル算出

戦闘レベル = `round(scale × max(上位N個の柱))` を [min,max] にクランプする **max-of-pillars(LD-7)** 方式。各柱 = 「上位 top 個のスキルレベル合計 ÷ divisor」。旧・加重平均モデルは廃止。**gear非依存**(装備tierは一切参照しない)。

| キー | 既定値 | 範囲/検証 | 意味 |
|---|---|---|---|
| `skills.<KEY>` | (開放式) | 数値でない値は warn+skip | 柱の算出に入れるTFネイティブスキルidと相対重み。未知キーは無視 |
| `pillars` | top1/div**1.5**, top2/div**2.0**, top3/div**2.5**, top4/div**3.0** | — | 柱の定義。各柱の「上位何個(top)を合計し、いくつ(divisor)で割るか」。複数柱の最大値を採用 |
| `curve.scale` | 1.0 | finite かつ 0以上 | 採用した柱に掛ける倍率 |
| `curve.min-level` | 0 | min<=max | 戦闘レベル下限 |
| `curve.max-level` | 100 | min<=max | 戦闘レベル上限 |
| `cache.ttl-seconds` | 3 | 0–300(範囲外は3へフォールバック+warn) | スキルレベル読取キャッシュTTL(秒)。0でキャッシュ無効 |

既定の対象スキルは**6種**(すべて重み 1.0):

| skills キー | 分類 |
|---|---|
| `LIGHT_WEAPONS` / `HEAVY_WEAPONS` / `ARCHERY` | 物理 |
| `ARS_MAGIC` | 魔法 |
| `LIGHT_ARMOR` / `HEAVY_ARMOR` | 防具(**2026-08 に追加**。以前は意図的に除外していた) |

> ⚠️ **1本だけ Lv100 まで伸ばしても戦闘レベルは 100 になりません。** 現行の除数では
> `top1 ÷ 1.5` なので **純特化 Lv100 → 戦闘レベル 67** です。100 に届かせるには
> 2技能100/100(→100)、3技能84×3(→100)のように複数を伸ばす必要があります。
> `combat-level.yml` の冒頭コメントにある「純特化(100)=100」という例は**除数1.0時代の古い記述**です。

## 4. dungeon(ダンジョン) / hate(ヘイト)

### 4.1 `dungeon/gates.yml` — ダンジョン入場ゲート

行き先(ワールド名/ダンジョンid)でキーする「戦闘レベル要求 + 任意の鍵アイテム消費」ゲート。**2026-08-01 に全ダンジョン分が投入済みで、2026-08-22 時点で 28 本**あります。

| フィールド | 既定 | 意味 |
|---|---|---|
| `display-name` | (なし) | GUI・メッセージに出す表示名 |
| `required-combat-level` | 0 | 必要戦闘レベル(0=level gate無効) |
| `key-item` | (なし) | 入場時に消費する鍵アイテムID。TFカタログID → ArsPaper ID → バニラMaterial の順で解決 |
| `key-amount` | 1 | 鍵の必要個数(最低1) |
| `content-package` / `aliases` | (なし) | EliteMobs のコンテンツパッケージ名。インスタンスダンジョンはこれでゲートする |
| `region` | (なし) | 同一ワールド内の区画ダンジョン境界(`world` / `min` / `max`)。歩いて出入りするたびに鍵を消費する点に注意 |
| `entry-location` | (なし) | 鍵の右クリック→潜入確認GUIで確定したときの転送先(`x`/`y`/`z` 必須) |

**踏むと痛い落とし穴が3つあります。**

- **`gates:` が1本でも書かれていると fail-close** になります。書き漏らしたダンジョンは一般プレイヤーが二度と入れません(`trinityforge.admin` だけ素通り)。鍵を掛けないダンジョンも `required-combat-level: 0` で必ず列挙してください。EliteMobs へダンジョンを増やしたら必ず1本足すこと(足し忘れは `ShippedDungeonGateCoverageTest` が検出します)。
- **`key-item` に `custom:` 接頭辞を付けない。** 付けると「ゲートは有効なのに所持判定が永久に0個」になり、鍵を持っていても入れなくなります。
- **鍵アイテムIDが解決できないときは fail-open**(その鍵ゲートだけ無効化＝素通り)になり、警告ログが1回だけ出ます。永久ロックにはなりません。

現行は `required-combat-level` を**世界を繋ぐ者の聖所(40)以外すべて 0** に統一しています。EliteMobs 側に最低レベル制限が無く、`contentLevel: -1` の level-sync が入場後の強さを合わせるため、**鍵の入手難度が実質のゲート**という設計です。鍵は `key_*`(28種)として `items/catalog.yml` に定義されています。

> EliteMobs 側にも別系統のゲート(`trinityforge.yml` の `dungeon-entry-gate`、content-package名ベース)があり、**2系統が別々に存在**します。詳細は [実装状況と注意点](12-実装状況と注意点.md)。

### 4.2 `dungeon/themes.yml` — ダンジョンテーマ(耐性プリセット)

テーマ = defense-bias プリセット。level連動 ramp(`値 = base + per-level * level`)で、`importmobs` 時にモブへ適用されます。

**現行の出荷値は `themes: {}`(空)です。** ダンジョンごとの硬さ・攻撃の型は、テーマではなく
`combat/mob-overrides.yml` のダンジョン別スコープで直接指定する方式へ移りました
(→ [モブとダンジョン](09-モブとダンジョン.md))。テーマ機構自体は生きているので、
独自ダンジョンを一括で色付けしたいときに使えます。

| フィールド | 意味 |
|---|---|
| `<テーマ名>.physical.defense-rate` / `resistance` / `flat-defense` / `damage-reduction` | 物理側の `{base, per-level}` |
| `<テーマ名>.magical.*` | 魔法側の同じ4つ |
| `<テーマ名>.armor-strength` | 会心軽減(共通)の `{base, per-level}` |

### 4.3 `hate/rates.yml` — ヘイト(敵対度)システム

漏れ制御のメカニズムのみで、実バランス(タンク/獣使い係数など)は未エンコード。既定は decay off・caps 寛容で balance-neutral。

| キー | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| `limits.max-tracked-mobs` | 5000 | [1, 1000000] | 追跡する最大モブ数(超過はLRUで追い出し) |
| `limits.max-attackers-per-mob` | 64 | [1, 10000] | 1モブあたりの最大攻撃者数 |
| `decay.enabled` | false | boolean | ヘイト減衰の有効化 |
| `decay.per-second` | 0.0 | [0.0, 1.0] | 秒あたり減衰率 |
| `eviction.entry-ttl-seconds` | 600 | [0, 86400] | 放置エントリの生存秒数(600=10分) |
| `sweep.interval-ticks` | 1200 | [20, 72000] | 掃除の実行間隔(1200=60秒) |
| `threat.per-damage` | 1.0 | [0.0, 1000.0] | ダメージ1あたりのヘイト蓄積量 |

> EliteMobs フォークのターゲティングは、この `HateService` に委譲するよう**統一済み**です。TFが存命の間はフォークは自分のテーブルへ記録せず(TF側 `HateListener` の一本記録のみ)、フォークは読み取りだけ行うため**二重計上は起きません**。フォーク独自の簡易テーブルは、TF不在または読み取り失敗時のフォールバックとしてのみ使われます。実効の詳細は [実装状況と注意点](12-実装状況と注意点.md)。

## 6. `glyphs.yml` — グリフ(呪文部品)定義

グリフはForm(形態)/Effect(効果)/Augment(増強)の3種で、呪文はグリフの並びです。合計マナコスト=各グリフの `mana-cost` の単純合計。全グリフの一覧・数値は [呪文グリフ一覧](06-呪文グリフ一覧.md) を参照。ここでは**構造**のみ示します。

各グリフエントリの主なフィールド:

| フィールド | 意味 |
|---|---|
| `tier` | 1=Novice / 2=Apprentice / 3=Archmage。ブック/ワンドのティア制限に使う |
| `mana-cost` | 発動時のマナ消費 |
| `max-augments` | 増強の種別ごとの最大スタック数(超増強は1個=2個分としてカウント) |
| `params` | 効果ごとの数値パラメータ(base-damage / duration など) |
| `unlock-cost` | 解放に必要な経験値レベル + 素材 |

> **重要**: 増強の互換性(どのグリフにどの増強を付けられるか)は**ソースコードにハードコード**されており、glyphs.yml の互換フィールドは参照されません。glyphs.yml で有効なのは `max-augments` と `params` のみです。glyphs.yml を削除・破損させるとコード内フォールバック既定値に落ちます(yml値と乖離がある箇所あり)。

## 7. ゲート系YAML

> **重要**: 「空だからゲートが無い」とは限りません。**グリフの使用ゲートの正本は TrinityForge のスキルツリー側へ移りました。**

### 7.1 `unlock-gate.yml` — 解放ゲート(クラフト/儀式)

| キー | 既定 | 意味 |
|---|---|---|
| `recipe-perks` | `{}`(空) | レシピID→必要perkID。未定義レシピはゲート無し |
| `ritual-perks` | `{}`(空) | 儀式ID→必要perkID |
| `repair-ritual.enabled` | true | Ars修繕儀式の有効化(バニラ修繕廃止の抜け道防止) |
| `repair-ritual.extra-source-cost` | 0 | 修繕儀式に上乗せする追加Sourceコスト(負値は0クランプ) |

### 7.2 `usage-gate.yml` — 使用ゲート(グリフ)

| キー | 既定 | 意味 |
|---|---|---|
| `glyph-perks` | `{}`(空) | グリフキー→必要perkID |

> ⚠️ **このファイルが空でも、グリフの使用ゲートは効いています。** glyph→perk 対応は
> TrinityForge のスキルツリー(`skilltree/*.yml` の `dedicated-effects:` に書いた `glyph:<key>`)側が正本で、
> ランタイムは両者を OR で判定します。2026-08-22 時点で **57 個のグリフ**がスキルツリーのノードに紐づいており、
> 対応ノードを取るまで使えません。判定は作成時ブロック + 発動時不発の二段です。
> グリフを新しくゲートしたいときは、**このファイルではなくスキルツリー側に書く**のが現行の作法です。

### 7.3 品質(厳選)の決定方式 — `selection.yml` は廃止済み

> 旧方式の `selection.yml`(品質分布からの抽選)は削除済みです。現在は**クラフト時にクラフトしたプレイヤーの生産スキルレベルで品質が決まる**方式(craft-quality一本化)に統合されています。

- Ars装備・触媒(魔導書等)は `ARS_SMITHING` スキルレベルに応じて品質**0〜15**(split-normal)が決まります。品質段階・ティア名の詳細は[ステータスと厳選](03-ステータスと厳選.md)を参照してください。
- 適用経路は2つ: バニラ作業台クラフト(`CraftQualityListener`)と儀式クラフト(`TrinityForgeBridge.stampCraftedQuality`)。素材・消耗品には刻印されません(一意rollSeed刻印がスタック不能化を招くため)。
- `/ars give` 等のコマンド付与や非クラフト生成は生成者スキルが無いため品質0(baseline)になります。

### 7.4 `ban.yml` — スペルBAN

| キー | 既定 | 意味 |
|---|---|---|
| `banned-spells` | **4件** | 全ワールドで使用不可にするグリフ。`arspaper:<key>` 形式 |

| グリフ | 理由(推定) |
|---|---|
| `arspaper:solar`(日輪) | 防御無視の継続ダメージが強すぎる |
| `arspaper:lunar`(月輪) | 同上 |
| `arspaper:sonic_boom`(ソニックブーム) | 射程20の貫通ビーム |

> ワールド別のBANは `/ars world ban` の GUI からも設定できます。GUI 上では全体BANのグリフが別色で表示されます。

## 10. `threads.yml` / `thread-sets.yml` — スレッド

スレッドは**防具と武器**のスレッドスロットにセットして効果を発揮します(以前は防具専用でした)。
**2026-08-22 時点で `threads.yml` に 75 種、`thread-sets.yml` に 73 のセット効果**が定義されています。

| フィールド | 意味 |
|---|---|
| `<id>.<効果キー>` | 効果量。enum既定値を threads.yml が上書きします(config優先) |
| `<id>.stackable` | 同じスレッドを重ねられるか(未記載は false) |
| `<id>.max` | 重ねられる最大数(未設定は無制限) |

代表例:

| id | 効果キー | 値 | stackable / max |
|---|---|---|---|
| `mana_regen` | regen-bonus | 2 /tick | true / 3 |
| `mana_boost` | mana-bonus | 20 | true / 3 |
| `hit_mana_recovery` | recovery | 10 | true / 2 |
| `damage_mana_recovery` | recovery | 5 | true / 2 |
| `spell_cost_down` | cost-reduction | 8% | true / 1(全装備合算100%上限) |
| `backpack` | slots | 27 | true / 2 |
| `speed` / `jump_boost` / `night_vision` ほかポーション系 | (各効果) | — | false(重複不可) |

- `thread-sets.yml` は「同じセットのスレッドを複数付けたときの追加効果」を定義します。セット効果の倍率は
  ステータスのレイヤを通して掛かるため、攻撃力%が二重に乗ることはありません。
- スレッド枠の上限は儀式で最大 5 まで拡張できます(→ [儀式とソース魔力](07-儀式とソース魔力.md))。
- `spell_power` / `water_breathing` スレッドは削除済みです。

## 11. `items.yml` — レシピ(作業台/儀式)

カスタムアイテムのクラフト定義(16エントリ)と `ritual_effects:`(儀式の効果定義)。`method: workbench`(作業台)と `method: ritual`(儀式、台座+儀式コア+Source供給)を横断ローダが登録します。主要レシピと Source コストは [儀式とソース魔力](07-儀式とソース魔力.md) を参照。

- 作業台の登録キー = `new NamespacedKey(plugin, id)`。これが `unlock-gate.yml` のレシピIDと一致します。
- 儀式ID = `RitualRecipe.id()`。
- ⚠️ `custom:<ArsのID>` を素材に使うレシピは、TF 側の `items/external-items.yml` へ登録しないと
  **レシピ帳に出るのに永久にクラフト不可**になります。
- ⚠️ カスタム素材の `MaterialChoice` 登録は、**同じ形の バニラレシピを無言で潰します**(作業台が作れなくなった事例あり)。

## 12. `sourcelinks.yml` — ソースリンク(魔力生成)と転送

各機械ブロックが消費する素材と生成量、およびソースの**転送**設定を定義します。

| セクション | 中身 |
|---|---|
| `transfer.sourcelink` | 個々のリンクの転送間隔(100tick)・1回の最大転送(50)・バッファ上限・検知半径 |

| `transfer.infinity-core` | インフィニティコアの効果半径(5)・転送倍率(2.0)・バッファ倍率(2.0) |
| `volcanic` | FURNACE。燃料を消費(棒/板/スラブ=1、原木=3、石炭/木炭=5、ブレイズロッド=10、石炭ブロック=45、溶岩バケツ=100) |
| `mycelial` | SMOKER。食料を消費(生=1、加工=3、シチュー=7、金人参=15、ウサギシチュー/パンプキンパイ=30、金リンゴ=75) |
| `alchemical` | BLAST_FURNACE。醸造素材を消費(基本=1、醸造=3、ポーション=5、スプラッシュ=8、ガストの涙/経験値瓶=15、ドラゴンブレス=30) |

|---|---|
| `vanilla-loot` | **true** |
| `random-loot` / `special-loot` / `elite-scroll` / `vanilla-loot-multiplier` / `currency-shower` / `boss-unique-loot` / `treasure-chest-loot` / `arena-loot` | false |

> EliteMobs 独自の通貨・スクロール経済をまるごと切り、ドロップは TF 側の品質付きアイテムに一本化する構成です。
> TFのゲート(`dungeon/gates.yml`、行き先名＋鍵)とforkのゲート(`trinityforge.yml`、content-package名＋レベル)は
> **別系統**なので、同じダンジョンを両方でゲートしたい場合は両方に設定が必要です。
> 詳細は [実装状況と注意点](12-実装状況と注意点.md)。

## 15. ここに載せきれない設定ファイル

TrinityForge には他にも設定ファイルがあります。**全キーの網羅一覧はリポジトリの `docs/config-reference/`** を参照してください。

| ファイル | 中身 |
|---|---|
| `skills/base/*_progression.yml`(16本) | スキルごとのEXP曲線・最大レベル・プレステージ |
| `skilltree/*.yml`(16本) | スキルツリーのノード定義。**グリフ・レシピ・儀式の解放ゲートもここ** |
| `progression/achievements.yml` / `collection.yml` | アチーブメントと図鑑 |
| `progression/crafting-features.yml` / `use-requirements.yml` | クラフト機能の解放、装備の使用要求 |
| `progression/special-rewards.yml` / `level-broadcast.yml` | 特別報酬、レベルアップ告知 |
| `gacha.yml` | ガチャ(券の種類と排出) |
| `afk.yml` | AFK判定とEXP停止 |
| `network.yml` | サーバー間テレポート(`/tpto` `/tphere`) |
