# 管理者ガイド: 設定リファレンス

全設定ファイルを、ドメイン別に「キー・既定値・意味」の表で網羅します。プレイヤーバランス調整の入口です。

## このページでわかること

- TrinityForge / ArsPaper / EliteMobs(改造版) の全設定ファイルのキーと既定値
- 各設定が「何を」「どう」変えるのか
- 数値は暫定であること、編集後の反映方法(reload)

> **共通の前提**
> - 特記なき限り、設定編集後は **`/trinityforge reload`(ArsPaper側は `/ars reload`)** で反映されます。反映されない例外(マナ回復間隔・エンチャ登録など)は [導入とコマンド](10-管理者ガイド-導入とコマンド.md) の §6 を参照。
> - **数値は基本的にすべて暫定(調整中)** です。コード内に「PROVISIONAL / バランス調整フェーズで確定」と明記されています。
> - percent 値はコード内では分数表現(0.20 = 20%)です。以下の表もその表記に従います。
> - `importmobs` は `mob-import.yml` / `themes.yml` 編集後、**reload → 再import** の順で実行してください([導入とコマンド](10-管理者ガイド-導入とコマンド.md) §6.3)。

# 第1部: TrinityForge

## 1. combat(戦闘)

### 1.1 `combat/damage.yml` — ダメージ計算の中核

物理/魔法は同じ8ステップの対称パイプラインを通ります(詳細は [戦闘のしくみ](02-戦闘のしくみ.md))。

| キー | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| `physical.base-coefficient` | 1.0 | [0,100] | 物理の基礎ダメージ全体倍率 |
| `physical.min-component-damage` | 1.0 | [0,1000] | 物理の最小ダメージ床(必ずこれだけは通る) |
| `magical.base-coefficient` | 1.0 | [0,100] | 魔法の基礎ダメージ全体倍率 |
| `magical.min-component-damage` | 1.0 | [0,1000] | 魔法の最小ダメージ床 |
| `level-scaling.per-level` | 0.05 | [0,10] | `base *= (1 + per-level*戦闘レベル)`。**装備非依存の唯一の生ダメージ成長源** |
| `defense.max-mitigation-rate` | 0.9 | [0,1] | 防御率%・耐性%・被ダメ軽減%を**それぞれ個別に**この値で上限クランプ(合算上限ではない)。3種は掛け算で重なるので合計軽減は90%を超えうる。完全免疫を防ぐのは別途の最小ダメージ床(min-component-damage) |
| `defense.max-crit-reduction` | 1.0 | [0,1] | 防具強度(=会心軽減率)の上限。既定1.0=上限なし(会心の上乗せを最大100%まで打ち消せる)。1未満にすると、どれだけ防具強度を積んでも会心の上乗せが一定割合は必ず残る |
| `bleed.tick-interval-ticks` | 20 | [1,1200] | 出血の適用間隔(20tick=1秒) |
| `bleed.ticks` | 5 | [1,200] | 出血の適用回数(既定5秒間) |
| `vanilla-armor.defense-rate-per-point` | 0.04 | [0,1] | バニラ防具1点あたりの防御率% |
| `vanilla-armor.defense-rate-max` | 0.8 | [0,1] | 上記防御率%の上限(ネザライトフル≒20点で頭打ち) |
| `vanilla-armor.armor-strength-per-point` | 1.0 | [0,100] | バニラの armor_toughness(頑丈さ)1点あたりに与える防具強度=会心軽減率。バニラ防具の頑丈さが会心軽減へ変換される量 |

**攻撃スタットキー写像**(武器PDC→AttackStats。文字列キー名の対応表。通常変更不要):

| キー | 既定値 |
|---|---|
| `attack-stat-keys.flat-bonus-damage` | "flat-bonus-damage" |
| `attack-stat-keys.percent-bonus-damage` | "percent-bonus-damage" |
| `attack-stat-keys.crit-chance` | "crit-chance" |
| `attack-stat-keys.crit-damage` | "crit-damage" |
| `attack-stat-keys.penetration` | "penetration" |
| `attack-stat-keys.damage-modifier` | "damage-modifier" |
| `attack-stat-keys.fixed-damage` | "fixed-damage" |

**防御スタットキー写像**(防具PDC→DefenseStats):

| キー | 既定値 | 意味 |
|---|---|---|
| `defense-stat-keys.phys-resistance` | "phys-resistance" | 物理耐性(typed) |
| `defense-stat-keys.magic-resistance` | "magic-resistance" | 魔法耐性(typed) |
| `defense-stat-keys.phys-flat-defense` | "phys-flat-defense" | 物理守備力(step6・物理のみ引き算) |
| `defense-stat-keys.magic-flat-defense` | "magic-flat-defense" | 魔法守備力(step6・魔法のみ引き算) |
| `defense-stat-keys.damage-reduction` | "damage-reduction" | 被ダメ軽減(共通) |
| `defense-stat-keys.dodge-chance` | "dodge-chance" | 回避(共通) |
| `defense-stat-keys.armor-strength` | "armor-strength" | 防具強度=会心軽減率(step2・会心の上乗せ分のみ減) |

> 防御率%(armor-defense-rate)だけは `defense-stat-keys` に**ありません**。これはバニラの armor から読むためで、ここに書くと二重計上になります。防具強度(armor-strength)はアイテム由来ぶんをここで読み、加えてバニラ armor_toughness(頑丈さ)からも会心軽減として少量が上乗せされます(`vanilla-armor.armor-strength-per-point`)。守備力は物理・魔法で別キーに分かれました(旧 `flat-defense` は廃止)。

### 1.2 `combat/mob-defaults.yml` — プロファイル無しモブの既定防御

すべて 0.0(バニラベースライン)。このフォールバックが実際に使われるのは**非LivingEntity**の被弾のみで、素のバニラモブは実際にはバニラ防具ミラーを使います。

| キー | 既定 | 範囲 |
|---|---|---|
| `physical.defense-rate` / `resistance` / `damage-reduction` | 0.0 | [0,1] |
| `physical.flat-defense` | 0.0 | [0,100000] |
| `magical.defense-rate` / `resistance` / `damage-reduction` | 0.0 | [0,1] |
| `magical.flat-defense` | 0.0 | [0,100000] |
| `armor-strength`(両タイプ共通) | 0.0 | [0,100000] |

### 1.3 `combat/mob-import.yml` — EliteMobs→モブプロファイル変換ポリシー

`/tf importmobs` の変換ルール。既定はすべて 0.0(バニラベースライン、ハードコードのバランスなし)。各防御値は `base + per-level * level` で算出されます。

| キー | 既定 | 意味 |
|---|---|---|
| `level.source` | `ELITEMOBS` | level の出所。`ELITEMOBS`(モブ自身のlevel) か `FIXED` |
| `level.fixed` | 1 | `source=FIXED` 時に使う固定level |
| `level.default` | 1 | `source=ELITEMOBS` で level が非数値時の既定 |
| `theme.default` | "" | 全変換モブに付与するテーマ(空=なし) |
| `physical.*` (defense-rate/resistance/damage-reduction/flat-defense) | `{base:0.0, per-level:0.0}` | 物理防御ramp |
| `magical.*` (同上) | `{base:0.0, per-level:0.0}` | 魔法防御ramp |
| `armor-strength` | `{base:0.0, per-level:0.0}` | 防具強度ramp(共通) |

> `combat/mob-profiles.yml` は既定で `profiles: {}`(空)です。個別モブは `importmobs` が生成するか、手編集で「逆張り」モブを追加します。手編集エントリは再importでも温存されます。

### 1.4 `combat/base-stats.yml` — プレイヤー基礎ステータス

全プレイヤーに一律で加算される基礎ステータスの初期値。装備・スキル・ロールバフ等の合算に「もう1レイヤ」として加わります。**既定は空 `base-stats: {}` = 全バニラ(加算なし)**。

| キー | 既定 | 意味 |
|---|---|---|
| `base-stats.<stat>` | (空) | ステ名(`lore.yml` のステ名。例 `crit-chance` / `phys-flat-defense` / `max-health`)→ 基礎値。未記載=加算なし(バニラ) |

- 値の書き方は `item-stats.yml` と同じ(PERCENT系は「5」=5%、FLAT系はそのままの数値)。編集後は `/trinityforge reload` で即反映。
- 体力・移動速度・攻撃速度・リーチ・ノックバック耐性などの属性系キーはバニラAttribute経路へ、それ以外は合算マップへ、それぞれ二重計上なく適用されます(近接・魔法の両経路に対称に加算)。
- ⚠ `attack-power`(攻撃力) だけは特殊で、ここに基礎値を入れると全プレイヤーの素手/バニラ武器の基本ダメージが置き換わり、ダメージ系エンチャントも無効化されます。**通常は空欄のまま**にしてください(設定するとロード時に警告が出ます)。綴り間違いなど、プレイヤーに効かないキーもロード時に警告されます。
- 上限クランプはありません(全員一律の運営判断として意図的)。

> このファイルは config-editor の「プレイヤー基礎ステータス」画面からも編集できます(空欄=バニラ)。

## 2. stats(ステータス・厳選)

ステータスは不変ベイクされず、PDCには **rollSeed(long) と quality(int) の2値だけ**が保存され、表示・攻撃・防御の値はすべてテーブルから毎回導出されます。だからテーブルを編集して reload すれば既存アイテムも再バランスされます(詳細は [ステータスと厳選](03-ステータスと厳選.md))。

### 2.1 `stats/item-stats.yml` — アイテム個別ステ定義

`stats/roll.yml` と `stats/material-base.yml` は廃止済みで、現在は **`stats/item-stats.yml` が唯一のステ定義元**です。Material名(例 `DIAMOND_SWORD`)または `Material#CustomModelData`(例 `EMERALD#5104`)をキーに、アイテム1品ずつステを設定します。CMDを持たない素の Material エントリは、そのMaterialの全品(素のバニラ品含む)に適用されます。

各アイテムのエントリは3層構成です。

| 層 | 意味 |
|---|---|
| `fixed` | ステ値を直接指定(上書き)。rollSeedの有無に関係なく全アイテムに適用 |
| `per-quality` | 品質1段あたりの増分。最終値 ＝ fixed ＋ (step × 品質Lv) |
| `random` | ランダムロール層(段2)。`{<stat>: {min, max}}` 形式。ここに書いたステ「だけ」が、そのレンジを対象に品質に応じたロール分布(§2.2参照)で抽選され、fixed／per-quality の上に加算される(物理・魔法共用)。抽選値はアイテムの rollSeed で決定的。fixed/per-quality 未設定のステに random だけ書いた場合は基礎0にロール分だけ加算 |

同梱の既定 `item-stats.yml` は全バニラ装備64種が**空の雛形(`MATERIAL: {}`)**として同梱されており、組込みの固定ステ値・ロール範囲・素材ベースは**ありません**。数値は運営が記入する方式です。

以下は「このように設定する」という**推奨設定例(目安)**です。

**攻撃系(武器)の設定例**:

| スタット | fixed例 | random例(min〜max) | 意味 |
|---|---|---|---|
| crit-chance | 0.0 | 0.0〜0.15 | クリティカル率 |
| crit-damage | **0.5** | 0.0〜0.5 | クリティカルダメージ(fixedで+50%を持つ例外設定) |
| penetration | 0.0 | 0.0〜0.3 | 防御貫通 |
| flat-bonus-damage | 0.0 | 0.0〜4.0 | 固定追加ダメージ |
| percent-bonus-damage | 0.0 | 0.0〜0.2 | 割合追加ダメージ |
| bleed-chance | 0.0 | 0.0〜0.1 | 出血発動確率 |
| bleed-damage | 0.0 | 0.0〜2.0 | 出血1tickあたりの物理ダメージ |

**防御/属性ミラー系(武器以外＝防具、vanilla attribute へミラー)の設定例**:

| スタット | fixed例 | random例(min〜max) | ミラー先 |
|---|---|---|---|
| armor-defense-rate | 0.0 | 0.0〜3.0 | armor |
| max-health | 0.0 | 0.0〜4.0 | max_health(2.0=ハート1個) |
| knockback-resistance | 0.0 | 0.0〜0.1 | knockback_resistance |
| move-speed | 0.0 | 0.0〜0.05 | movement_speed(分数表記。0.05=+5%) |

> `armor-strength`(防具強度) は会心軽減率%へ役割変更したため、**もはや armor_toughness へはミラーされません**(TF独自の会心軽減として下の防御系で消費)。

**TF専用防御系(防具、attribute化しない)の設定例**:

| スタット | fixed例 | random例(min〜max) | 意味 |
|---|---|---|---|
| phys-resistance | 0.0 | 0.0〜0.05 | 物理耐性%(typed・貫通不可) |
| magic-resistance | 0.0 | 0.0〜0.05 | 魔法耐性%(typed・貫通不可) |
| phys-flat-defense | 0.0 | 0.0〜2.0 | 物理守備力(step6・物理ダメージのみ引き算) |
| magic-flat-defense | 0.0 | 0.0〜2.0 | 魔法守備力(step6・魔法ダメージのみ引き算) |
| armor-strength | 0.0 | 0.0〜0.2 | 防具強度=会心軽減率(step2・会心の上乗せ分のみ減。通常ダメージ不干渉) |
| damage-reduction | 0.0 | 0.0〜0.03 | 被ダメージ軽減% |
| dodge-chance | 0.0 | 0.0〜0.02 | 回避率(攻撃全体を無効化) |

> 上表は `crit-damage` を除き全 fixed が 0.0 の設定例です。random に書いたステだけがオプトインでロール対象になる点に注意してください(書かなければロールされません)。

### 2.2 `stats/quality.yml` — 品質モデル

品質は次の2段の split-normal(上下非対称な正規分布)で決まります。

- **段1 = 品質ティア抽選(0..maxQuality)**: mode(期待品質)を中心に、上側は `spread-up`、下側は `spread-down` のσで正規分布抽選し [0, maxQuality] にクランプ。mode はクラフト/ドロップ/釣りで決まる(§2.3, §2.7参照)。
- **段2 = ランダムロール層の到達分布**: `item-stats.yml` の `random` に書いたステが対象。到達割合 R∈[0,1] を、品質比例の中心(qNorm=品質/maxQuality)を mode とする split-normal で抽選し、上側は `roll-spread-up`、下側は `roll-spread-down` のσを使う。

| キー | 既定値 | 意味 |
|---|---|---|
| `max-quality` | 9 | 品質段数のフォールバック(通常は quality-tiers.yml のエントリ数10で品質0..9が決まる)。範囲[1,100] |
| `spread-up` | 1.5 | 段1(品質ティア抽選)の上振れ側σ。大きいほど高品質へ跳ねやすい。クラフト・敵ドロップ共通 |
| `spread-down` | 1.5 | 段1の下振れ側σ。大きいほど低品質へ落ちやすい。クラフト・敵ドロップ共通 |
| `roll-spread-up` | 0.15 | 段2(ランダムロール到達分布)の上振れ側σ(到達割合[0,1]単位。0.15で品質相応の中心を頂点にした釣鐘型。0.3超で両端に確率が溜まり山型が崩れる) |
| `roll-spread-down` | 0.15 | 段2の下振れ側σ(到達割合[0,1]単位) |
| `give-default-quality` | 3 | `/tf giveitem` で品質省略時のデフォルト |

### 2.6 `stats/lore.yml` — Lore(説明文)生成

| キー | 既定値 | 意味 |
|---|---|---|
| `layout.line-template` | `<gray><icon><name>：<value></gray>` | 1行のMiniMessageテンプレ(プレースホルダ icon/name/value) |
| `layout.score-line-template` | `<tier><gray>:</gray>  <aqua><score>pt</aqua>` | 品質スコア行のMiniMessageテンプレ(プレースホルダ tier=色付き【ティア名】 / tier-name / score) |

> **スコアの導出**: `<score>` は 0〜100 の純粋なrandomロール性能値。実際に付与された各randomステについて `(ロール実値 - min) / (max - min)` を0〜1へ正規化し、その単純平均×100で算出する。fixed / per-quality は対象外で、`max == min` の定数rangeと付与されなかったステは種類数にも含めない。値の単位やrange幅が異なるステも同じ重みで評価される。
> ステータスカテゴリ区切りの `====` 行は、バニラフォントのピクセル幅換算で最長のlore行に合わせて自動生成される(ツールチップの横幅は広げない)。
| `layout.positive-color` | white | 正の値の色 |
| `layout.negative-color` | red | 負の値の色 |
| `layout.header` / `footer` | `[]`(空) | 前後の固定行 |

各スタットの表示定義(name / format / decimals / order / category)は `lore.yml` の `stats:` 以下で定義します。現在は戦闘・防御・魔法(ars)・採取(gathering)・クラフト(craft)・汎用(utility)・その他(other)の7カテゴリにわたり**約70種**が登録されています。表示名は日本語、icon は全スタットで空文字(リソースパックのグリフを貼る想定)、`hide-when-zero=true`(0に丸まる行は非表示)。表示順はカテゴリ内の `order`(小さいほど上)。

以下は代表的な一部の現行定義です(全一覧は `lore.yml` 参照)。

| スタット | 表示名 | format | 小数 | order |
|---|---|---|---|---|
| attack-power | 攻撃力 | FLAT | 1 | 1 |
| attack-speed | 攻撃速度 | FLAT | 1 | 2 |
| damage-modifier | ダメージ補正 | PERCENT | 0 | 4 |
| percent-bonus-damage | 追加ダメ | PERCENT | 0 | 11 |
| crit-chance | 会心率 | PERCENT | 1 | 30 |
| crit-damage | 会心ダメージ | PERCENT | 0 | 31 |
| penetration | 貫通率 | PERCENT | 0 | 40 |
| bleed-damage | 出血ダメージ | FLAT | 1 | 42 |
| armor-defense-rate | 防御力 | FLAT | 1 | 50 |
| armor-strength | 防具強度 | PERCENT | 1 | 51 |
| max-health | 体力増強 | FLAT | 1 | 52 |
| phys-flat-defense | 物理守備力 | FLAT | 1 | 62 |
| magic-flat-defense | 魔法守備力 | FLAT | 1 | 63 |
| dodge-chance | 回避率 | PERCENT | 0 | 66 |

> **旧仕様との違い**: `armor-strength`(防具強度) は表示が PERCENT(会心軽減率%)に変わりました(旧: INTEGER の Toughness)。守備力は `flat-defense` 一本から `phys-flat-defense`／`magic-flat-defense` の2キーに分割されました。このほか採取・クラフト・汎用系の多数のスタットが追加されています。

### 2.7 `stats/craft-quality.yml` — クラフト/釣り品質

クラフト時: カテゴリに対応する生産スキルの最高Lvから品質を決めます。`mode = base-quality + bestLevel / skill-levels-per-quality`、最終品質は mode を中心に `quality.yml` の `spread-up`／`spread-down` で split-normal 抽選しクランプして決まります(±spread の一様ぶれではありません)。敵ドロップ(`drop:` 節)も同じ spread-up/spread-down を使いますが、上振れパークはクラフト限定です。

| キー | 既定値 | 意味 |
|---|---|---|
| `category-skill.weapon` | SMITHING | 武器クラフトの参照スキル |
| `category-skill.armor` | SMITHING | 防具クラフトの参照スキル |
| `category-skill.tool` | MINING | ツールクラフトの参照スキル |
| `category-skill.ars-gear` | ARS_SMITHING | Ars装備クラフトの参照スキル |
| `mode.skill-levels-per-quality` | 10 | 品質+1に必要なスキルレベル数 |
| `mode.base-quality` | 0 | 基準品質 |
| `ars-smithing.exp-per-craft` | 10.0 | Ars装備クラフト時に付与する ARS_SMITHING EXP |
| `fishing.luck-per-quality` | 1 | 釣り: 宝運+1あたりの品質上昇 |
| `fishing.base-quality` | 0 | 釣りの基準品質 |
| `fishing.spread` | 1 | 釣り品質のぶれ幅(±の一様ぶれ。釣りは quality.yml の spread-up/spread-down には未統合) |

> `mode.spread` は廃止済みです。品質のσ(ばらつき)は `stats/quality.yml` の `spread-up`／`spread-down` に一元化されました。`fishing.spread` のみ従来どおり残っており、釣りは正規化されていません。

> 釣り品質は生産スキルではなく**宝運**(竿の Luck of the Sea レベル + プレイヤーの LUCK 属性)で決まります。

### 2.8 属性写像 — TFスタット→バニラAttribute写像

PDCが数値の真実で、対応物を持つものだけをバニラAttributeへミラーします。これは現行では**固定実装**であり、`stats/attribute-map.yml` は存在しません。変更は設定ファイルではなく実装変更が必要です。

| キー | attribute | operation | scale |
|---|---|---|---|
| knockback_resistance | knockback_resistance | ADD_NUMBER | 1.0 |
| armor_defense_rate | armor | ADD_NUMBER | 1.0 |
| max_health | max_health | ADD_NUMBER | 1.0 |
| move_speed | movement_speed | ADD_SCALAR | 1.0 |
| attack_speed | attack_speed | ADD_NUMBER | 1.0 |
| attack_reach | entity_interaction_range | ADD_NUMBER | 1.0 |

> `armor_strength`(防具強度) はかつて `armor_toughness` へミラーしていましたが、会心軽減率%へ役割変更したため**この表から除外**されました。現在はバニラAttributeへは写像せず、TF独自の会心軽減(step2)としてのみ働きます。

> `attack_power` は `item-stats.yml` 由来のステで、武器の追加ダメージ系(flat-bonus-damage 等)は PDC-only で combat パイプラインが消費します。バニラ attribute へはミラーされ**ません**(attack_damage との二重計上を避けるため、意図的にこの表から除外)。詳細は [実装状況と注意点](12-実装状況と注意点.md)。
>
> `attack_speed`(攻撃速度=毎秒の手数)はバニラ attack_speed 属性への加算です(既定基礎4.0、剣などは内部でマイナス補正)。攻撃を当てた直後にその武器を一定秒数だけ使用不可にする**アイテムCT**(`item-cooldown`)は別軸で、attribute へは写像せず TF 側のクールダウン機構(`Player#setCooldown`、近接のみ)で処理します(表示は `lore.yml` の `item-cooldown`)。

### 3.1 `progression/role-buffs.yml` — ロールバフ

戦闘職と補助職を定義します。既定では剣闘士・魔術師が与ダメージ+12%、タンクが守備力+40・被ダメージ軽減5%・ヘイト1.5倍です。補助職は斥候（ARCHERY EXP+20%＋速度）、農夫（FARMING EXP+20%＋跳躍）、採掘夫（MINING EXP+20%＋採掘速度）を定義します。

## 3. progression(育成)

### 3.2 `progression/combat-level.yml` — 戦闘レベル算出

戦闘レベル = `round(scale × max(上位N個の柱))` を [min,max] にクランプする **max-of-pillars(LD-7)** 方式。各柱 = 「上位 top 個のスキルレベル合計 ÷ divisor」。旧・加重平均モデルは廃止。**gear非依存**(装備tierは一切参照しない)。

| キー | 既定値 | 範囲/検証 | 意味 |
|---|---|---|---|
| `skills.<KEY>` | (開放式) | 数値でない値は warn+skip | 柱の算出に入れるTFネイティブスキルidと相対重み。未知キーは無視 |
| `pillars` | top1/div1.0, top2/div1.5, top3/div2.1, top4/div2.8 | — | 柱の定義。各柱の「上位何個(top)を合計し、いくつ(divisor)で割るか」。複数柱の最大値を採用 |
| `curve.scale` | 1.0 | finite かつ 0以上 | 採用した柱に掛ける倍率 |
| `curve.min-level` | 0 | min<=max | 戦闘レベル下限 |
| `curve.max-level` | 100 | min<=max | 戦闘レベル上限 |
| `cache.ttl-seconds` | 3 | 0–300(範囲外は3へフォールバック+warn) | スキルレベル読取キャッシュTTL(秒)。0でキャッシュ無効 |

既定の対象スキル(すべて重み 1.0):

| skills キー | 重み | 分類 |
|---|---|---|
| `LIGHT_WEAPONS` | 1.0 | 物理柱 |
| `HEAVY_WEAPONS` | 1.0 | 物理柱 |
| `ARCHERY` | 1.0 | 物理柱 |
| `ARS_MAGIC` | 1.0 | 魔法柱 |

> 防具スキル(LIGHT_ARMOR / HEAVY_ARMOR)は**意図的に除外**されています。全値は暫定プレースホルダです。max-of-pillars では未修得スキルが下位に落ちて希薄化せず、純特化100→100、2技能75/75→100、3技能70/70/70→100となります。

## 6. `glyphs.yml` — グリフ(呪文部品)定義

グリフはForm(形態)/Effect(効果)/Augment(増強)の3種で、呪文はグリフの並びです。合計マナコスト=各グリフの `mana-cost` の単純合計。全グリフの一覧・数値は [呪文グリフ一覧](06-呪文グリフ一覧.md) を参照。ここでは**構造**のみ示します。

|---|---|

## 10. `threads.yml` — スレッド(防具強化パーツ)

スレッドは防具のスレッドスロットにセットして効果を発揮します。enum既定値を threads.yml が上書きします(config優先)。

| id | 効果キー | threads.yml値 | stackable / max |
|---|---|---|---|
| mana_regen | regen-bonus | 2 /tick | true / 3 |
| mana_boost | mana-bonus | 20 | true / 3 |
| hit_mana_recovery | recovery | 10 | true / 2 |
| damage_mana_recovery | recovery | 5 | true / 2 |
| spell_cost_down | cost-reduction | 8% | true / 1(全装備合算100%上限) |
| health_boost | (体力増強) | — | true / 3 |
| backpack | slots | 27 | true / 2 |
| speed / jump_boost / night_vision / fire_resistance / dolphins_grace / conduit_power / hero_of_the_village / flight | (各ポーション/特殊効果) | — | false(重複不可) |

- `stackable` 未記載は false、max 未設定は無制限。
- `mana-max-percent` / `regen-percent` の読込キーは存在しますが現行threads.ymlでは未使用(=0)。
- `spell_power` / `water_breathing` スレッドは削除済みです。

## 11. `items.yml` — レシピ(作業台/儀式)

カスタムアイテムのクラフト定義。`method: workbench`(作業台)と `method: ritual`(儀式、台座+儀式コア+Source供給)を横断ローダが登録します。主要レシピと Source コストは [儀式とソース魔力](07-儀式とソース魔力.md) を参照。

- 作業台の登録キー = `new NamespacedKey(plugin, id)`。これが `unlock-gate.yml` のレシピIDと一致します(防具は `armor_<itemId>`)。
- 儀式ID = `RitualRecipe.id()`。

## 12. `sourcelinks.yml` — ソースリンク(魔力生成)の投入物

各機械ブロックが消費する素材と生成量を定義します。

| リンク | ブロック | 消費物と生成量(例) | config |
|---|---|---|---|
| volcanic | FURNACE | 燃料: 棒/板/スラブ=1, 原木=3, 石炭/木炭=5, ブレイズロッド=10, 石炭ブロック=45, 溶岩バケツ=100 | volcanic |
| mycelial | SMOKER | 食料: 生=1, 加工=3, シチュー=7, 金人参=15, ウサギシチュー/パンプキンパイ=30, 金リンゴ=75 | mycelial |
| alchemical | BLAST_FURNACE | 醸造素材: 基本=1, 醸造=3, ポーション=5, スプラッシュ=8, ガストの涙/経験値瓶=15, ドラゴンブレス=30 | alchemical |

> Botanical(BEEHIVE)と Vitalic(BARREL)はコンパイル時定数でハードコードされており、`sourcelinks.yml` では設定できません(Botanical=成長イベントで5/成長、Vitalic=5/tick基礎 + kill15)。

# 第3部: EliteMobs(改造版) `trinityforge.yml`

TF連携の全トグルと設定を保持します。全 getter は「TF利用可能 かつ トグルON」でのみ有効。TF不在時は全機能 no-op。

## 13. 連携トグル

| トグル | 既定 | 機能 |
|---|---|---|
| `gear-neutralization` | true | 装備の与ダメ/被ダメ倍率を1.0で短絡(装備tierによる強弱を排除) |
| `combat-delegation` | true | 最終ダメージ計算をTFの対称パイプラインに委譲。バニラRESISTANCEの二重軽減も除去 |
| `combat-level-mapping` | true | EliteMobsの戦闘レベルをTFの `combatLevelOf` に差し替え(失敗時はEliteMobsネイティブへフォールバック) |
| `spawn-profile-stamp` | true | エリート spawn 時にモブ耐性プロファイルをPDCスタンプ |
| `loot-stat-stamp` | true | エリートlootに rollSeed + quality をスタンプ(品質は敵の強さ駆動の正規分布(split-normal)。`drop.enabled=false` のときのみ一様分布) |
| `hate-targeting` | true | TFの`HateService`でターゲットを上書き（TF不在時のみフォーク簡易表へフォールバック） |
| `repair-disabled` | true | エリート装備の金床/砥石/mend修繕を無効化(scrap修繕も) |
| `soulbind-bridge` | true | EliteMobsのSoulbindをTF ItemDataに BindType.SOULBOUND + owner でミラー |
| `dungeon-entry-gate` | **false** | content-package名ベースのダンジョン入場ゲート(level要求のみ、鍵消費なし) |
| `use-level-restriction` | **false** | 装備使用レベル制限(戦闘レベルで代用の粗い実装、fail-open) |

## 14. 各機能の設定

| キー | 意味 |
|---|---|
| `dungeon-entry-gate.enabled` | ゲート有効化(既定false) |
| `dungeon-entry-gate.required-combat-level` | ダンジョン名(content-package)→必要戦闘レベルのマップ(既定空) |
| `dungeon-entry-gate.message` | 拒否メッセージ(`{required}`/`{current}` プレースホルダ可) |
| `use-level-restriction`(各設定) | 装備使用制限の詳細(既定 off、fail-open) |

> 主要トグルは既定 true ですが、**入場ゲートと使用レベル制限は既定 false**です。有効化するには上記を明示的に設定してください。TFのゲート(`gates.yml`、world名)とforkのゲート(`trinityforge.yml`、content-package名)は別系統なので、同じダンジョンを両方でゲートしたい場合は両方に設定が必要です。詳細は [実装状況と注意点](12-実装状況と注意点.md)。
