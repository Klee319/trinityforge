# 実装状況と注意点

## このページでわかること

- 各システムが「実際にどこまで動いているか」（実装済み／作りかけ／未実装）
- 設計（仕様）と実装が食い違っているところ、二重に作られているところ
- プレイヤー・管理者が誤解しやすいポイント

このページは、**実際のソースコードと設定ファイルを読んで確認した事実**にもとづいています。仕様書に「こうする」と書いてあっても、コードで動いていなければ「未実装」として正直に記載します。他ページの明るい説明を鵜呑みにする前に、ここで実態を確認してください。

> **全体の前提**：このサーバーは開発中です。土台（TrinityForge）とその上の戦闘・ステータス・厳選・魔法は形になっていますが、数値は「調整前の暫定値」で、いくつかの機能はまだ結線されていません。「設定を入れれば動く」休眠状態のものと、「コード自体がまだ無い」ものを区別して書きます。

## 1. 戦闘まわり

### ✅ 動いているもの
- 対称ダメージパイプライン（8ステップ）は稼働。物理攻撃（近接・矢など）はここを通る。
- 出血（Bleed）は近接ヒットで発動し、20tick間隔×5回でダメージ。
- 軽減の上限（max-mitigation-rate＝0.9）などの安全装置が効いている。

### ✅ 実装済み（以前の記述を訂正）
- **会心（クリティカル）は機能する**：以前「全呼び出しが `plain(0)` で会心が効かない」と書いていたが、これは不正確だった。近接武器の会心は元々 `AttackStatBridge` 経由で武器（厳選）の会心率が判定に渡されて機能している。さらに今回、魔法側も触媒（ワンド/スペルブック）由来の会心が連携され機能するようになった。会心率が0のときだけ会心しない。
- **魔法ダメージの触媒ステが連携済み（B1）**：魔法ダメージは以前 `AttackStats.plain(0)` 固定で、杖・触媒由来の会心・貫通が乗らなかった。今回、触媒（ワンド/スペルブック）由来の会心/貫通ステをTFの対称パイプラインに乗せるよう配線した。→ 触媒を厳選すれば魔法ダメージにも会心・貫通が反映される。
- **防具強度が「会心軽減率」に役割変更**：以前は step6 で決まった数を引く防御だったが、今は step2 で**会心の上乗せ分だけを減らす会心軽減率**になった。通常（会心でない）ダメージには効かない。上限は `defense.max-crit-reduction`（既定1.0=上限なし）。バニラ防具の頑丈さ（Toughness）も会心軽減の材料として少量取り込まれる。
- **守備力が物理／魔法に分割**：旧 `flat-defense`（物理魔法共通）が `phys-flat-defense`／`magic-flat-defense` の2種に分かれ、step6でそれぞれの属性ダメージだけを引き算するようになった。

### 🟡 注意すべき点
- **無属性（TYPELESS）チャネルは未実装**：属性判定できない攻撃を「無属性」として素通しする設計（LD-12）はコード未追加。
- **本当のハイブリッド攻撃（物理＋魔法同時の一撃）は未対応**。
- **出血のHP直接減算**：BleedのtickはバニラのダメージイベントではなくHPを直接減らすため、ノックバック・無敵時間・不死のトーテム・吸収ハートなどをバイパスする可能性。コードに「live-server smoke test が必要」と明記。
- **バニラのジャンプ攻撃（×1.5）**の扱いが対称パイプラインで未定義（OPEN_DECISIONS C12）。
- **プレイヤー防御の「防具スキル分」が未結線**：装備アイテム由来の防御は反映されるが、防具スキル（軽装甲・重装甲）のperkをTF防御ステに反映する部分が未接続（C1b）。
- Paper 1.21 で `DamageModifier` が非推奨。新APIへの移行TODOあり。

## 2. ステータス・アイテムまわり

### ✅ 動いているもの
- ステータスは焼き付けされず、rollSeed＋品質からライブ導出（設定を直して reload すれば既存装備も再調整される）。
- 品質は0〜9の10段階、素材tierのベース値、ロール範囲、Lore表示すべて稼働。
- クラフト品質（生産スキル依存）・釣り品質（宝運依存）・`/trinityforge give` の3経路が動く。
- ツールエンチャント（efficiency/unbreaking/fortune/luck of the sea）の品質連動付与が動く。
- **プレイヤー基礎ステータス**（`combat/base-stats.yml`）が動く。全プレイヤー一律の基礎ステ初期値を運営が設定でき、装備・スキル・バフの合算にもう1レイヤとして加わる（空欄=バニラ＝加算なし）。近接・魔法の両経路に二重計上なく反映され、`/trinityforge reload` で即反映。攻撃力だけは武器の基本ダメージを置き換える特殊ステなので通常は空欄推奨。

### 🟡 注意すべき点
- **バインドの取引制限は仕様外**：`SOULBOUND` / `OWNER_BOUND` は PDC に刻まれるが、取引を禁止する処理は**意図的に実装しない**。
- **使用レベル制限は既定オン**：`progression/use-requirements.yml` は `enforce: true`。近接・弓/クロスボウ/トライデント・ツールに加え、防具は装備直後に取り外し、Ars触媒は詠唱前に、TF進行DBのスキルLvで判定する。要件なしまたは `use-level-requirement: 0` は無制限。
- **属性写像は固定実装**：旧 `attribute-map.yml` は廃止済みです。武器の `attack_power` はバニラの `attack_damage` にはミラーされず、TF内部（PDC）の戦闘パイプラインだけで使われます（意図的な二重計上防止）。
- **Ars装備の品質はクラフト時のスキル依存に統一**：旧方式の `selection.yml`（品質分布抽選）は廃止済み。現在は、ArsPaperのカスタム装備・触媒（魔導書等）をクラフトしたプレイヤーの `ARS_SMITHING` スキルレベルに応じて、品質0〜9が正規分布で抽選される（craft-quality一本化）。バニラ作業台クラフトは `CraftQualityListener`（CraftItemEvent）、儀式クラフトは `TrinityForgeBridge.stampCraftedQuality` 経由で刻印。→ `/ars give` 等のコマンド付与や非クラフト生成は生成者スキルが無いため品質0（baseline）になる。
- **`catalog.yml` は本番用の多数のアイテム定義を含む**：武器、長槍、杖、ソース系素材・装備、圧縮ブロック等が定義されている。エディタ用のカテゴリ／順序には未定義IDも混在するため、表示上の空欄や欠落は別途実機確認が必要。
- **データバージョンのマイグレーションは未実装**（保存形式のバージョン枠はあるが読み替え処理なし）。
- **reloadの反映範囲**：装備中の防具・手に持ったアイテム・ログイン時にしか再計算されない。インベントリの奥にしまったアイテムは、手に取るまで古いままになる。
- 全数値が「暫定（M7で調整）」。バランスは未確定。

## 3. 育成・解放まわり

### ✅ 動いているもの
- combatレベルの max-of-pillars 計算、TFネイティブスキルレベル読取、使用レベル制限の述語はユニットテスト付きで稼働。
- `/trinityforge stats` で戦闘レベル・スキルレベル・派生ステが確認できる。

### ✅ 実装済み（以前の記述を更新）
- **combatレベルは純特化と複数育成を両立する柱方式**：`combat = round(scale × max(上位1/1.0, 上位2合計/1.5, 上位3合計/2.1, 上位4合計/2.8))` を [min,max] にクランプします。上位N個・除数・倍率（scale）は `progression/combat-level.yml` の `pillars:` で設定可能です。純特化100→100、2技能75/75→100、3技能70/70/70→100。数値は暫定です。
- **ARS_MAGIC のEXPが結線済み**：呪文の詠唱成功時に `ars-magic.exp-per-cast(=2.0) + exp-per-mana(=0.1)×消費マナ` のEXPが入るよう配線した（TF `ArsBridge.grantMagicExp` ＋ ArsPaper の SpellCaster 側）。ARS_SMITHING は従来どおりArs装備クラフトでEXPが入る。→ 魔法柱（ARS_MAGIC）が詠唱で育つようになった。

### 🟡 注意すべき点
- **解放ゲートは PerkMirror 経由で有効**：TF SQLiteのunlocked perkが`PlayerData.heldPerks`に同期され、ArsPaperのUsageGate / UnlockGateが参照する。
- **ロールの戦闘バフは実装済み**：`progression/role-buffs.yml` の既定では、剣闘士・魔術師は与ダメージ+12%、タンクは守備力+40・被ダメージ軽減5%・ヘイト1.5倍。斥候はARCHERY EXP+20%と速度、農夫はFARMING EXP+20%と跳躍、採掘夫はMINING EXP+20%と採掘速度を定義する。`/tf role set <combat> [support]` で、半径16ブロック以内にMonsterがいなければ変更できる。
- **補助職の効果はロール変更時にも同期される**：変更・解除・ログイン・復活時に、既存の補助職由来ポーション効果を消して選択中ロールの効果だけを付与する。斥候→農夫→採掘夫の変更で効果を重ねることはできない。
- **補助職のEXP+20%は全プレイヤー起点のネイティブEXP付与へ適用される**：斥候のARCHERYだけでなく、農夫のFARMING・採掘夫のMININGを含む採取／生産EXPも倍率を参照する。

## 4. 魔法（ArsPaper）まわり

### ✅ 動いているもの
- 呪文の組み立て（フォーム＋効果＋増強）、約8フォーム・多数の効果・24＋の増強、マナ、フォーム別クールダウン、儀式、ソースリンク、追加エンチャントが稼働。
- ダメージ呪文は TF の対称パイプライン（`magicalFinalDamage`）を通す。魔法ダメージは MAGICソースで適用され、TFの物理再計算に横取りされない。

### ✅ 実装済み（以前の記述を更新）
- **触媒の攻撃ステが連携済み**（1章と同じ）：触媒（ワンド/スペルブック）由来の会心・貫通が魔法ダメージに乗るよう配線した（B1）。
- **マナの戦闘連動回復が有効**：被弾/攻撃/非戦闘時のマナ回復（`mana.recovery.*`）を非0に設定（被弾3%／攻撃3%／非戦闘1%）。→ 戦闘の動きに応じてもマナが戻る。数値は暫定。
- **孤立グリフが登録済み**：`flare`・`sense_magic`・`toss`・`reset` を `glyphs.yml` とレジストリに登録し、ゲーム内で入手・使用できるようにした。`wall` フォームは廃止のまま（入手不可）。
- **Ars装備の品質はクラフト時に決まる**：クラフト者の `ARS_SMITHING` スキルレベルに応じて品質0〜9が抽選される（`selection.yml` 方式は廃止済み。2章参照）。

### 🟡 注意すべき点
- **残るゲート系YAMLは空出荷**：`unlock-gate.yml`／`usage-gate.yml`／`ban.yml` は中身が空のまま（品質はクラフト時に生成者のスキルレベルから決まる方式に統合されたため、この3ファイルとは無関係）。→ perkゲート無効・スペルBAN無しの休眠状態。機構は完成しているので、管理者がYAMLを埋めれば動く。
- **ダメージ経路の非対称**：`ignite`（燃焼）・`hex`（追撃）・`explosion`（バニラ爆発）・`solar`／`lunar`（防御無視）・`fangs`（牙エンティティ）は TFの対称パイプラインを通らない。solar/lunarは意図的な「防御無視」。バランス上の重要ポイント。
- **フォーム別CTが未調整**：`config.yml` の `form-cooldowns` は `projectile:0, self:0` のみ。実質すべて計算CT（0.5秒基準）にフォールバック。
- **コード既定値とglyphs.ymlの数値がズレている効果が多い**：実際に動くのは同梱YAMLの値。glyphs.ymlを削除・破損させるとコード内の別の既定値にフォールバックするので注意（harm・solar・lunar・invisibility・beam射程 など）。
- **一部の呪文にコードとドキュメントの不一致**：`cold_snap`の威力上限、`lightning`の増幅上限、`snare`（実際はスロウ255固定で増幅無効）など。挙動を過信しないこと。

## 5. モブ・ダンジョン・ヘイトまわり

### ✅ 動いているもの
- ダンジョンテーマ（physical_fortress / arcane_ward / balanced）3種の耐性プリセット。
- モブ防御プロファイル（2層）とEliteMobsインポート（`/trinityforge importmobs`）。
- EliteMobsフォークのTF連携（与ダメの装備倍率を無効化、combatレベルをTF基準に差替、二重軽減除去、最終ダメージ委譲、spawn時プロファイルスタンプ、修繕廃止、ソウルバインド連携、ドロップの厳選スタンプ）。

### ✅ 実装済み（以前の記述を更新）
- **ヘイトをTFの `HateService` に統一（二重計上も解消）**：以前はTF本体の高機能ヘイト（上限・減衰・TTL・sweep・決定的な優先順位）がフォークから呼ばれず孤立し、さらにフォークが全被弾を影で二重記録していた。今回、**フォーク側は狙いの判定をTFの `HateService` に委譲**し、かつ**TFが存命の間はフォーク自身のテーブルへは一切記録しない**よう修正した（記録はTF側の一本のみ、フォークは読み取りだけ）。フォーク独自の簡易テーブルは、TFが不在または読み取り失敗のときだけフォールバックとして使われる。

### 🟡 / ❌ 注意すべき点
- **タンクのヘイト倍率は実装済み**：タンクは最終ダメージ×1.5でヘイトが蓄積する。一方、挑発・固定化・被ダメージ由来のヘイト、獣使い／ペット連携は未実装で、狙い操作は限定的。
- **ダンジョン入場ゲートは TF 一本化**：`dungeon/gates.yml` が正本。`content-package` / `aliases` で EliteMobs の blueprint 名も同じ gate に紐付け。EliteMobs fork は `TrinityForge.dungeonGateService()` に委譲（`trinityforge.yml` の `dungeon-entry-gate.required-combat-level` は非推奨）。
- **ポータル/その場ダンジョンは非対応**：TFのゲートはクロスワールドのテレポートのみ対象。ポータル移動や同一ワールド内の区画ダンジョンは取りこぼす（world-topology の決定待ち D3）。
- **EliteMobsのloot品質は敵強度ベース**：`craft-quality.yml` の `drop.enabled` が有効で敵レベルを取得できる場合、敵の強さをmodeとするsplit-normal抽選を行う。受取人の `power_mobdropbonus_add` はmodeを加算する。TF不在・敵強度不明・drop無効時だけ一様分布へフォールバックする。
- **EliteMobsの一様フォールバック品質はユニットテスト済み**：現行の`uniformQuality(long, int)`に対して、決定性・範囲・乱数seed規則を検証する。
- **フォークの使用レベル制限は粗い代用**：本来スキルツリーレベルで判定すべきところ、TFの公開APIがまだ無いためcombatレベルで代用（既定off）。
- **ダンジョン3層構成は概念のみ**：TFに「どの層か」を区別するコードは無い。
- **ペット連携は完全未実装**：ダメージ属性・ヘイト参加・ダメージ計算補正の3点すべてコードが無い。依存する外部ペットPLも未選定（Pt1）。
- **EliteMobsのYAMLキー名は逆コンパイル由来の仮定**：実jarでキー名がズレるとインポート変換の調整が必要。

---

## 6. 運用上の注意（管理者向け）

- **ValhallaMMOは不要**：旧JARと設定フォルダは配置しない。
- **ロード順**：TrinityForge → ArsPaper。
- **importmobsはreloadの後に**：`/trinityforge importmobs` はメモリ上のポリシーを使う。`mob-import.yml` を編集したら先に `/trinityforge reload` してから importmobs する。
- **連携トグルとYAMLの投入**：EliteMobsフォークの連携は `trinityforge.yml` のトグル、ArsPaperのゲートは各YAMLに定義を入れて初めて機能する。既定では多くが休眠・fail-open。
- **数値は全部「調整前の暫定」**：バランスはこれから。
- くわしくは [管理者ガイド（設定リファレンス）](11-管理者ガイド-設定リファレンス.md)。

## 7. 「設計はあるが決着していない」主な論点

開発中に洗い出された未決事項のうち、プレイに影響しうる代表例（ソース内コメント・意思決定ログより）：

- combatレベルの数値調整（max-of-pillarsの上位N個・除数・倍率・上限の最終バランス。式自体は実装・config化済み）
- 防具スキル（軽装甲・重装甲）由来の防御をどう重ねるか（加算だと飽和して完全免疫になる懸念）。※守備力の物理/魔法分割そのものは実装済み
- バインドの発生タイミング（クラフト時／ドロップ時／取得時／装備時）と代行クラフトの可否
- ヘイトの適用範囲（EliteMobs限定かバニラmobのターゲットも奪うか）・減衰式・ログアウト時の扱い
- 修繕儀式の回数上限や耐久逓減（「耐久＝有限リソース」との整合）
- ワールド脅威（距離レベル）の新規プレイヤー保護・パワーレベリング減衰
- 品質から味付け分布への正式な変換表
