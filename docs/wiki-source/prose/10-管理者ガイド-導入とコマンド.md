# 管理者ガイド: 導入とコマンド

対象読者はサーバー運営者です。TrinityForge (TF) サーバーの構成・導入手順・全コマンド・ホットリロードの反映範囲をまとめます。用語は正確に扱いますが、各設定が「何のためか」も一言添えます。

## このページでわかること

- 4つのプラグインの依存関係とロード順、導入に失敗しないための必須条件
- TrinityForge / ArsPaper / EliteMobs(改造版) の全コマンドと権限
- `/trinityforge reload` で反映されるもの・されないもの(再起動が必要なもの)
- 連携を実際に動かすために管理者が投入すべきトグルとYAMLの注意点

---

## 1. サーバー構成

このサーバーは4つのプラグインを組み合わせた統合MMOです。

| プラグイン | 役割 | 種別 |
|---|---|---|
| **TrinityForge (TF)** | スキル進行・ダメージ計算・ステータス・厳選・ヘイト・ダンジョン等を一元管理 | 自作 |
| **ArsPaper** | 魔法プラグイン(呪文・マナ・儀式・ソース・魔道具) | 自作フォーク |
| **EliteMobs (改造版)** | 強敵(エリート)とダンジョン。EliteMobs 10.3.0 (MagmaGuy) ベースのフォーク | 改造フォーク |

- 動作対象: **Paper 1.21.11 / Java 21**。
- クロスプレイ対応(Java版 + 統合版/Geyser)、**PvPなし**の協力型PvE。
- 各プラグインは各リポジトリの Gradle でビルドします(成果物 jar を `plugins/` へ)。

---

## 2. 依存関係とロード順

### 2.1 依存の宣言(paper-plugin.yml)

| プラグイン | main クラス | 依存 |
|---|---|---|
| TrinityForge | `com.trinityforge.TrinityForge` | 外部進行プラグインへの依存なし |
| ArsPaper | `com.arspaper.ArsPaper`(bootstrapper `com.arspaper.enchant.ArsBootstrap`) | **TrinityForge に依存**(load BEFORE / required / join-classpath) |
| EliteMobs(改造版) | (EliteMobs本体) | TrinityForge を **softdepend**(任意依存) |

### 2.2 正しいロード順

```
TrinityForge  →  ArsPaper
                     ↑
              EliteMobs(改造版) は softdepend
```

> ArsPaper はTrinityForgeに依存するため、TrinityForgeを先に配置してください。ValhallaMMOは不要です。

> EliteMobs(改造版) は TF を softdepend にしているため、TF が無くても起動はします。ただしその場合は連携機能がすべて no-op(何もしない状態)になり、単体の EliteMobs として劣化動作します。

### 2.3 権限のデフォルト

| 権限 | 既定 | 用途 |
|---|---|---|
| `trinityforge.admin` | op のみ | `/trinityforge` 全サブコマンド |
| `arspaper.use` | 全員 true | 魔法の一般使用 |
| `arspaper.admin` | op のみ | `/ars` の管理系サブコマンド |

## 3. TFネイティブ進行

16スキル、ARS_MAGIC、ARS_SMITHING、Perk、PrestigeはTrinityForge内で動作し、
`plugins/TrinityForge/player_progression.db` に保存されます。旧プレイヤーデータは取り込みません。

- ARS_MAGIC の EXP は ArsPaper の呪文詠唱イベントから付与される設計です(TF内に in-class の EXP リスナはありません)。
- ARS_SMITHING の EXP は Ars装備クラフト時に `+10`(既定)付与され、そのレベルが Ars装備のクラフト品質を決めます。
- 戦闘レベルは **装備の強さではなくスキルツリーのレベル**で決まります(gear非依存)。詳しくは [育成と解放](08-育成と解放.md) を参照。

---

## 4. Geyser / クロスプレイ設定

統合版(Bedrock)プレイヤーを Geyser 経由で受け入れる場合の設定です。

| 設定 | 場所 | 推奨 |
|---|---|---|
| `geyser.disable-custom-model-data` | ArsPaper `config.yml` | **リソースパック未使用なら `true`** に |

- ArsPaper の魔道具・スレッド・防具はカスタムモデルデータ(CMD)でアイコンを出し分けます。統合版はJava版のCMDを解釈できないため、リソースパックを配布していないなら `true` にして無効化します。
- 魔法の作成GUIやスレッドGUIは**全てクリックベース**で設計されており、統合版でも操作可能です。
- ツールエンチャント(採掘速度など)はクライアント計算のため Geyser でも動作します(パケットベースの採掘速度は統合版でデシンクするため回避されています)。

## 5. コマンド一覧

### 5.1 TrinityForge `/trinityforge`(alias `/tf`)

管理操作は `trinityforge.admin`（既定opのみ）、プレイヤー向け操作は
`trinityforge.use`（既定全員）でゲートされます。

| コマンド | 機能 | 備考 |
|---|---|---|
| `/tf reload` | 全設定のホットリロード | 反映範囲は §6 参照 |
| `/tf giveitem <item> [quality]` | `items/catalog.yml` のアイテムを付与 | quality 省略時は既定3(実行時読取)。インベントリ満杯なら足元にドロップ |
| `/tf importmobs <source>` | EliteMobs custombosses を変換して `mob-profiles.yml` へ | メモリ内ポリシー使用。**reload後に実行**(§6.3) |
| `/tf importmobs theme <name> <source>` | テーマ適用付きインポート | name はタブ補完。同時実行は1本まで |
| `/tf dungeon themes` | 定義済みダンジョンテーマの一覧表示 | `dungeon/themes.yml` を参照 |
| `/tf progression level <player> <skill> <set\|add\|subtract> <amount> [prestige]` | オンラインプレイヤーの任意スキルLvを上書き・加算・減算 | 範囲外、および消費済みポイントを維持できないPOWER減算は拒否。`prestige`は省略時維持、指定時は絶対回数。レベル低下時は要求Lvを下回った通常ノードを剥奪し現行costを返還。POWER/ポイントと永続tierも原子的に同期 |
| `/tf progression exp <player> <skill> <amount>` | 任意スキルのEXPを増減 | 小数・負数も指定可能 |
| `/tf progression reset <player>` | 対象のTF進行データを初期化 | スキル、ポイント、perkを削除 |
| `/tf progression save` | 進行DBをcheckpoint | 保存失敗はコンソールを確認 |
| `/tf stats` | 自分の戦闘レベル・スキルLv・装備派生ステを表示 | read-only デバッグ。本人のみ。プレステージ/ロールは表示しない |
| `/skills [skill]`（alias `/s`） | Valhalla互換の9×5スキルツリーGUIを表示 | `/tf skills`でも同じGUIを表示 |

> `/skills` でスキルツリーGUI、`/tf stats` で戦闘レベルと装備派生値を確認できます。

### 5.2 ArsPaper `/ars`(alias `/arspaper`)

| コマンド | 権限 | 機能 |
|---|---|---|
| `/ars give <itemId> [count] [player]` | admin | カスタムアイテム付与。`enchant_book.<eid>.<lv>` でエンチャント本も付与可 |
| `/ars reload [reset]` | admin | 設定リロード(`reset` 付きで初期化)。厳選/使用ゲートの再読込も呼ぶ |
| `/ars glyph unlockall / lockall` | admin | グリフの全解放 / 全ロック |
| `/ars world ban` | admin | ワールド別スペルBAN の GUI |
| `/ars world maxmana/maxrgmana/fixmana/fixrgmana <value>` | admin | ワールド別のマナ上限・回復量設定 |
| `/ars world info` | admin | ワールドのマナ設定情報 |
| `/ars pvp <on/off>` | admin | PvPトグル |
| `/ars cleanup` / `debug` / `fixmana [player]` | admin | クリーンアップ / デバッグ情報 / マナ修正 |
| `/ars mana` / `mana notify` | 全員 | マナ情報表示 / 通知トグル |
| `/ars status` | 全員 | ステータス表示 |
| `/ars backpack` | 全員 | バックパックGUI |
| `/ars recipes` | 全員 | レシピブラウザGUI |
| `/ars ranking glyphs / mana` | 全員 | ランキング表示 |
| `/ars spell list / set <slot> <def> / bind <slot> / unbind` | 全員 | スペルの管理・スロットバインド |

### 5.3 EliteMobs(改造版) `/elitemobs`(alias `/em`), `/adventurersguild`(alias `/ag`)

EliteMobs 本体のコマンド体系をそのまま継承します。

| コマンド | 概要 |
|---|---|
| `/em`(`/elitemobs`) | エリートモブ・ダンジョン・設定などの管理親コマンド |
| `/ag`(`/adventurersguild`) | 冒険者ギルド(ギルドハブへの移動・ランク等) |

- TF連携のオン/オフは**コマンドではなく `trinityforge.yml` のトグル**で制御します(§7 と [設定リファレンス](11-管理者ガイド-設定リファレンス.md))。

## 6. ホットリロードの反映範囲

`/trinityforge reload`(および ArsPaper 側は `/ars reload`)は、多くの設定を再起動なしで反映します。ただし**反映されないもの**があるので注意してください。

### 6.1 reload で反映されるもの

- ダメージ計算の係数・各種スタットキー・**プレイヤー基礎ステータス**(`combat/*.yml`。`combat/base-stats.yml` を含む)
- 厳選テーブル・品質モデル・素材ベース値・lore・ツールエンチャント(`stats/*.yml`)。**ステータスはベイクされず rollSeed+quality から毎回導出する**ため、テーブルを編集して reload すると既存アイテムも再バランスされます。
- 戦闘レベルの重み・カーブ(`progression/combat-level.yml`)
- **スキル進行曲線・行動EXP**(`skills/base/*_progression.yml`)と**スキルツリー**(`skilltree/*.yml`)。いずれも候補全体の検証に成功したときだけ原子的に差し替え、壊れた1ファイルで稼働中ツリーを消さない。曲線/cap変更後は保存total EXPからレベルを再計算する。
- **戦闘武器・Ars 付与EXP**(`stats/skill-exp.yml`)。武器ヒットEXPの権威はここ（skills/base の旧戦闘行動表は未使用）。
- ダンジョンゲート・テーマ・ヘイトレート・モブ既定/プロファイル(`dungeon/*.yml`, `hate/*.yml`, `combat/mob-*.yml`)
- ArsPaper のマナ量・コスト・エンチャ値・ゲート系YAML(`config.yml` の一部, `*-gate.yml`, `ban.yml` 等)。品質はクラフト時に生成者のスキルレベルから決まる方式のため、reload対象は主に生産スキル側のカーブ設定です。

### 6.2 reload で反映されないもの(再起動が必要)

> **再起動が必要な代表例**
> - **マナ回復間隔**(`mana.regen-interval-ticks`): ManaManager 構築時に固定されるため reload では変更できません。
> - カスタムエンチャントの**登録**(ArsPaper): registry freeze 前のブートストラップで行うため、追加・変更はサーバー再起動が必要です。
> - ロード順・依存関係そのものの変更。

> **既存インベントリ内アイテムは「触るまで」反映されません。**
> reload 成功ごとにテーブル世代(generation)が更新されますが、既存アイテムへの再導出は次の3イベントでのみ発生します。
> - 手に持つ(ホットバーのスロット選択切替)
> - 防具の着脱
> - ログイン(join。主手+全防具を再適用)
>
> つまり**インベントリの奥で装備も選択もしていないアイテムは、触られるまで古い値のまま**です。全体を確実に反映させたい場合は、プレイヤーの再ログインが最も確実です。

### 6.3 importmobs の運用注意

> `/tf importmobs` は「**メモリにロード済みのポリシー**」(`mob-import.yml` の変換ルール)を使います。`mob-import.yml` や `themes.yml` を編集したら、必ず **`/tf reload` してから importmobs** を実行してください。順序を逆にすると古いポリシーで変換されます。
>
> インポートは **Merge(統合)方式**です。今回のrunで生成したidだけを置換し、他ダンジョンのidや手編集した「逆張り」モブは温存します。既存の出力ファイルが不正YAMLの場合は、手編集破壊を防ぐためインポートを中止します。

## 7. 連携を「実際に動かす」ために(重要な注意)

機構はコードに実装済みでも、**管理者がトグルやYAMLを投入するまで休眠している**部分が多数あります。導入直後の素の状態を誤解しないでください。

- **EliteMobs連携トグル**: `trinityforge.yml` のトグルで各連携(gear中立化・combat委譲・戦闘レベル写像・spawn耐性スタンプ・loot品質スタンプ・ヘイトターゲティング・修繕廃止・soulbind)が制御されます。gear中立化などの主要トグルは既定 true ですが、**ダンジョン入場ゲート(`dungeon-entry-gate`)と装備使用レベル制限(`use-level-restriction`)は既定 false** です。
- **ArsPaper のゲート系YAMLは空出荷**です。`unlock-gate.yml` / `usage-gate.yml` / `ban.yml` は空のままで、**初期状態ではレシピ/儀式のperkゲート無し・グリフ使用のperkゲート無し・スペルBAN無し**です。なお品質(厳選)は旧 `selection.yml` 方式を廃止し、**クラフト時にクラフト者の `ARS_SMITHING` スキルレベルから品質0〜9が抽選される**方式に統合済みで、これらのゲート系YAMLとは無関係です。
- **TFのダンジョンゲート(`dungeon/gates.yml`)も空出荷**(`gates: {}`)で、初期状態は fail-open(素通り)です。
- 戦闘レベル・厳選の数値は**すべて暫定(調整中)**とコード内に明記されています。バランス調整前提です。

> これら「未投入」「未実装」「二重実装」の詳細は専用ページに集約しています。導入前に必ず一読してください: [実装状況と注意点](12-実装状況と注意点.md)

## 8. 導入チェックリスト

1. Paper 1.21.11 / Java 21 環境を用意する。
2. TrinityForgeの`-all.jar` → ArsPaper の順で `plugins/` に配置。EliteMobs(改造版)も配置。
3. 起動後、コンソールで TrinityForge / ArsPaper が正常 enable したか確認する。
4. `/skills`と`/tf progression diagnose <player>`で進行DBを確認する。
5. Geyser 併用時は ArsPaper `config.yml` の `geyser.disable-custom-model-data` を設定する。
6. `trinityforge.yml`(EliteMobs側)のトグル、`gates.yml`・各ゲートYAML(`unlock-gate.yml`/`usage-gate.yml`/`ban.yml`)等を運用方針に合わせて投入する。

旧Valhalla導入済みワールドでは、削除済みレシピがプレイヤーのRecipe Book NBTに残る場合があります。
サーバーを完全停止してバックアップを取り、`tools/scripts/purge_valhalla_recipe_book.py`を使用してください。
この移行は`recipeBook.recipes`と`toBeDisplayed`内の`valhallammo:`キーだけを削除し、
インベントリ内の既存アイテム現物には触れません。
7. バランス数値(`combat/`, `stats/`, `combat-level.yml` 等)を [設定リファレンス](11-管理者ガイド-設定リファレンス.md) を見ながら調整する。
