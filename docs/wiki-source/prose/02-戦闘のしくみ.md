# 戦闘のしくみ

## このページでわかること

- 攻撃が「物理」か「魔法」かは、**何で攻撃したか**（武器か呪文か）で決まる。
- どんな攻撃も同じ8ステップの計算（対称ダメージパイプライン）を通ってダメージが決まる。
- 攻める側・守る側のステータスが、それぞれどこで効くのか。
- 連打減衰・命中回数の上限・反射・モブの魔法攻撃・日光炎上・PvP など、パイプライン以外の重要な仕組み。

> このページの数値は現在調整中（暫定）のものが多いです。今後のアップデートで変わることがあります。

---

## 1. まず結論: 攻撃の属性は「攻撃源」で決まる

TrinityForge（このサーバーのダメージを一手に管理する土台プラグイン）では、攻撃は必ず**物理**か**魔法**のどちらかに分けられます。どちらになるかは、あなたが持っている道具ではなく「**何で攻撃したか**」で自動的に決まります。

| 攻撃の手段 | 属性 | 例 |
|---|---|---|
| 武器・道具での近接攻撃 | 物理 | 剣・斧・素手で殴る |
| 弓・トライデントなどの発射体 | 物理 | 矢を射る、トライデントを投げる |
| 触媒（ワンドや魔法書）で放つ呪文 | 魔法 | 呪文グリフを組んだ攻撃 |

> 補足: 呪文（触媒で放つ攻撃）は「魔法」ダメージとして、武器の物理ダメージと同じ8ステップの計算を通ります。魔法ダメージの結線は済んでおり、触媒（ワンド／魔法書）由来の会心・貫通も反映されます（詳しくは[魔法のしくみ](05-魔法のしくみ.md)）。

**モブも魔法で攻撃してくることがあります。** 詳しくは[7. モブも魔法で殴ってくる](#7-モブも魔法で殴ってくる)を見てください。

## 2. 「対称ダメージパイプライン」ってなに?

物理も魔法も、**まったく同じ計算の流れ**を通ってダメージが決まります。この「同じ流れ」のことを対称ダメージパイプラインと呼びます。

- 「対称」＝物理と魔法を差別しない、という意味。
- 計算のプログラム自体は攻撃が物理か魔法かを見ていません。
- 違うのは「入れる数字」（耐性の種類や係数）だけ。流れは共通です。

つまり、物理攻撃を強くするのも魔法攻撃を強くするのも、**同じルールで考えられる**ということです。覚えることが一つで済みます。

## 3. ダメージ計算の8ステップ

攻撃が当たってから最終ダメージが出るまで、決まった順番で処理が進みます。**守備力が会心判定より先に引かれる**のがこのサーバーの一番の特徴で、順番がとても大事です。

| 順番 | 名前 | この段でやること（やさしく） |
|---|---|---|
| 0 | 回避（かいひ） | 守る側が「よけた」かを最初に判定。よけたらダメージは0で終了 |
| 1 | 基礎ダメージ作り | もとのダメージに「固定追加」と「割合追加」を足す |
| 2 | 守備力 | 決まった値をダメージから引き算する（物理・魔法べつべつ）。**会心の判定より先** |
| 3 | 会心（クリティカル） | 会心が出たらダメージを上乗せ。守る側の**防具強度**があると、この上乗せ分だけ減らされる |
| 4 | 防御率 | 守る側の防御率で割引く。ただし**貫通で減らせる** |
| 5 | 耐性 | 守る側の耐性で割引く。こちらは**貫通できない** |
| 6 | 補正・被ダメ軽減 | 攻める側の補正で増やし、守る側の軽減で減らす |
| 7 | 最小クランプ | ダメージが下がりすぎても「最低ライン」で下げ止める |
| 8 | 固定ダメージ加算 | **守備力・防御率・耐性・軽減・最小クランプのすべてを無視して**、決まった量をそのまま上乗せする |

計算の最後に残った数字が、実際に相手へ与えるダメージです。

### 各ステップをもう少しくわしく

- **Step0 回避**: 攻撃の一番はじめに1回だけ判定します。よけられたら、後の計算はぜんぶ飛ばしてダメージ0。
- **Step1 基礎作り**: 「もとのダメージ＋固定追加＋（もとのダメージ×割合追加）」。ここで攻撃の土台を作ります。
- **Step2 守備力**: 割合ではなく「決まった数」を引き算します。小さいダメージほど痛手になります。守備力は**物理と魔法で別々**にあり、物理攻撃には物理守備力、魔法攻撃には魔法守備力が使われます。**この引き算は会心判定より前に行われる**ので、守備力は通常攻撃も会心も等しく削ります（後段の%軽減で薄まりません）。
- **Step3 会心**: 会心が出ると「会心ダメージ」の分だけダメージが上乗せされます。ここで守る側の**防具強度**が働き、**上乗せされた分だけ**を割引きます（例: 防具強度40%なら、会心の上乗せ分が6割になる）。防具強度は「会心の上乗せ」だけに効き、通常ダメージには一切影響しません。会心の上乗せ量がマイナスになる（＝会心が回復になる）ことはありません。
- **Step4 防御率**: 相手の守りで割引。ここは**貫通が効く**ので、貫通が高いほど防御率を無視できます。
- **Step5 耐性**: 相手の守りで割引。ここは**貫通がまったく効きません**。硬い相手はここでしっかり守られます。
- **Step6 補正・軽減**: 攻める側の「ダメージ補正」は100%を基準にした endpoint（例: 80%→0.8〜1.0、120%→1.0〜1.2）の範囲を毎攻ランダムに掛けます。そのあと守る側の「被ダメージ軽減」で減らします。
- **Step7 最小クランプ**: 引き算しすぎて0や下がりすぎになっても、最低ダメージ（既定は1.0）で止めます。
- **Step8 固定ダメージ**: 守備力・防御率・耐性・被ダメージ軽減・最小クランプ、**防御に関わるものを何ひとつ考慮しない純粋な加算**です。「flatが削った分だけ還付する」という古い仕様は廃止されています。相手に守備力や耐性がまったく無くても、固定ダメージは同じ量だけ乗ります。

> 式で見たい人へ（補足）: Step1 `base = 基礎 + 固定追加 + 基礎×割合追加` / Step2 `base -= 守備力` / Step3 `base ×= (1 + 会心ダメージ×(1-防具強度))` / Step4 `base ×= (1 - 防御率×(1-貫通))` / Step5 `base ×= (1 - 耐性)` / Step7 `base = max(base, 最小ダメージ)` / Step8 `base += 固定ダメージ`。まずは上の日本語の意味だけ分かればOKです。

## 4. 攻める側のステータス（どう効くか）

攻撃を強くするステータスです。かっこ内はどのステップで効くかです。

| ステータス | 何をするか | 効くステップ | ひとこと |
|---|---|---|---|
| 会心率 | 会心（クリティカル）が出る確率 | 0（判定） | 0だと絶対に会心しない |
| 会心ダメージ | 会心したときの上乗せ量 | 3 | 例: 0.5で+50% |
| 固定追加ダメージ | ダメージに決まった数を足す | 1 | 弱い攻撃ほど恩恵が大きい |
| 割合追加ダメージ | 基礎ダメージの割合で足す | 1 | もとが大きいほど効く |
| 貫通（かんつう） | 相手の防御率を無視する | 4 | 耐性には効かない |
| 固定ダメージ | 防御を一切無視してそのまま上乗せする | 8 | 相手の守備力・防御率・耐性がどれだけ高くても関係なく通る |

> 会心について: 近接武器の会心は、武器（厳選）の会心率が判定に渡されて機能します。魔法（呪文）の会心も、触媒（ワンド／魔法書）由来の会心率が連携され機能します。会心率0のときだけ会心しません（詳しくは[実装状況と注意点](12-実装状況と注意点.md)）。

## 5. 守る側のステータス（どう守るか）

ダメージを減らすステータスです。かっこ内はどのステップで効くかです。

| ステータス | 何をするか | 効くステップ | ひとこと |
|---|---|---|---|
| 防御率 | 割合でダメージを減らす | 4 | 貫通で無効化されることがある |
| 耐性（物理・魔法別） | 割合でダメージを減らす | 5 | 貫通で減らせない。属性ごとに別々 |
| 被ダメージ軽減 | 割合でさらにダメージを減らす | 6 | 攻撃の種類を問わず効く |
| 守備力（物理・魔法別） | 決まった数を引き算する | 2 | **会心より先に引かれる**。物理と魔法で別々に持てる |
| 防具強度 | 会心の上乗せ分だけを減らす | 3 | 主に厳選・装備ステから作られる。通常ダメージには効かない（現行設定ではバニラの頑丈さからの変換は無効） |
| 回避 | 一定確率で攻撃をまるごと無効化 | 0 | よければダメージ0 |

補足: 耐性は「物理耐性」と「魔法耐性」が別々にあります。物理攻撃には物理耐性、魔法攻撃には魔法耐性が使われます。

## 6. 三すくみ（物理・魔法・防御）を壊さない設計

このサーバーは「攻めが強すぎて守りが無意味」「守りが硬すぎて攻めが通らない」にならないよう、複数の軸がじゃんけんのように釣り合う設計になっています。

| ルール | 意味 | どうバランスが保たれるか |
|---|---|---|
| 耐性は貫通できない | Step5の耐性は貫通が一切効かない | 守り（耐性）を積んだ相手には貫通ゲーが通じない |
| 防御率は貫通できる | Step4の防御率は貫通で無視できる | 攻め（貫通）を積めば硬い相手も削れる |
| 守備力は会心より先に引かれる | Step2で先取りするので%軽減で薄まらない | 弱い攻撃を確実に止めつつ、大きな一撃には無力化されすぎない |
| 固定ダメージは防御を無視する | Step8はどの防御ステータスも参照しない純加算 | 守備力をどれだけ積んだ相手にも、固定ダメージ分は必ず通る |

つまり、「一つのステータスを積めば全部解決」にはなりません。相手に合わせて攻め方を変えるのがこのサーバーの戦闘の面白さです。

### 大事な安全装置

| 安全装置 | 値 | 意味 |
|---|---|---|
| 割合軽減の上限 | 90% | 防御率・耐性・被ダメージ軽減は、**それぞれ**最大90%までしか効かない。1つの守りだけで完全には防げない |
| 最小ダメージ | 1.0 | どれだけ守りを固めても、当たれば最低このダメージは必ず通る（下げ止まり） |

割合の軽減は「それぞれ最大90%まで」なので、複数を重ねれば通るダメージはかなり小さくできます。ですが最後に**最小ダメージ**の下げ止まりがあるため、どんなに硬い相手でも「完全に無敵」にはなりません。必ずダメージを与える道が残ります。

> ここで大事なのは「1つの守りだけで完封はできない」ことです。耐性は貫通されませんが、それ単体では最大90%まで。守りには必ず穴があります。

## 7. モブも魔法で殴ってくる

一部のモブは、通常攻撃（近接・投射）の一部または全部を**魔法ダメージ**として解決します。物理耐性だけを積んでいると、これらのモブの攻撃はそのまま通ります。

| 魔法の割合 | 対象モブ |
|---|---|
| 1.0（すべて魔法） | 魔女、エヴォーカー、イリュージョナー |
| 0.9（ほぼ魔法） | エルダーガーディアン、ガスト、ガーディアン、ウィザー |
| 0.8（大半が魔法） | ブレイズ、シュルカー |
| 0.7（半分以上が魔法） | ブリーズ、エンダードラゴン |
| 0.6（半分強が魔法） | ウォーデン |

上記以外の敵対モブ（ゾンビ・スケルトン・クリーパー・ピグリン等）は完全物理のままです。中間値のモブは、物理成分と魔法成分に分けてそれぞれ8ステップの計算を通ります（回避ロールは1回で両方に効きます）。

## 8. 連打減衰（melee-charge）

**攻撃をためきる前に振ると、威力が最大10分の1まで落ちます。** バニラの「攻撃クールダウン」の考え方をそのまま採用し、振り遅れではなく**振り急ぎ**にペナルティを付けています。

- 倍率 = `min-multiplier + t^exponent × (1 - min-multiplier)`（`t` = クールダウンの経過割合、既定 `min-multiplier: 0.1` / `exponent: 1.6`）
- 振り切った直後（`t = 1`）なら倍率1.0（減衰なし）
- 振り切る直前に連打すると、倍率は最低0.1（=威力10分の1）まで落ちる

**重い武器が「一撃を当てる」ことを重視する設計になっているのは、この減衰があるからです。** 連打で手数を稼ごうとしても、振り切る前の攻撃はほとんど威力が出ません。

## 9. 命中回数の上限（無敵時間）

被弾した側には**10tick（0.5秒）の無敵時間**があります。この間はどんな攻撃を当てても追加ダメージが入りません。

つまり、攻撃速度（attack-speed）をどれだけ積んでも、**実際に通る攻撃は1秒あたり最大2発**が上限です。手数特化の軽武器で攻撃速度を高くしても、無敵時間の壁で頭打ちになります（[8. 連打減衰](#8-連打減衰melee-charge)と組み合わせて、重武器の一撃重視・軽武器の手数という設計が成り立っています）。

## 10. 反射（棘の鎧の系統）

反射は「受けたダメージに比例して跳ね返す」方式では**ありません**。

- **反射率＝発動確率**です。被弾するたびにこの確率で反射が発動するかどうかを判定します。
- 発動したときに相手へ与えるダメージは、**被弾した側の武器の素殴りダメージ**（会心やパワーアタックなどの上乗せを一切含まない基礎値）です。被ダメージの大きさとは無関係です。
- バニラの「棘の鎧」イベントは最優先（LOWEST）で丸ごとキャンセルしており、TF側の反射と二重に発動することはありません。

以前は「受けたダメージ×反射率」を毎回跳ね返す仕様でしたが、大ダメージを受けるほど反射も青天井に伸びてしまう問題があったため、現在の「確率で発動・跳ね返す量は自分の素殴り」方式に変更されています。

## 11. 日光炎上

対象モブ（ゾンビ・ゾンビビレジャー・ドラウンド・ジャイアント・スケルトン・ストレイ・ボーグド・ファントム・ゾンビホース・スケルトンホースの10種）が日光で燃えるダメージは、**最大体力の10%**です。バニラの一律ダメージとは別枠のしくみに置き換わっています。

## 12. 出血・毒・ウィザー（継続ダメージ）

近接攻撃には、一定確率で相手を出血させる仕組みがあります。出血・毒・ウィザーはどれも「じわじわ続くダメージ（DoT）」ですが、**通常の8ステップパイプラインとはまったく別の、専用の軽い計算**を通ります。

| 項目 | 内容 |
|---|---|
| 発動する攻撃 | 出血は近接攻撃のみ（弓や呪文では出ない）。毒・ウィザーはポーション効果として通常どおり付与される |
| 発動条件（出血） | 武器が「出血確率」と「出血ダメージ」を両方持っているとき、確率で発動 |
| ダメージの間隔 | 20tick（＝1秒）ごと（既定） |
| 続く回数（出血） | 5回（＝既定で約5秒間） |
| 重ねがけ（出血） | 同じ相手には出血1個まで。もう一度当てても、加算ではなく**時間がリセット**される |

**⚠️ 出血・毒・ウィザーのダメージは、「被ダメージ軽減」以外の防御をいっさい通りません。** 回避・防御率・耐性・守備力・防具強度は一切参照されず、被ダメージ軽減（%）だけがそのまま適用されます。8ステップパイプラインの守備力や耐性をどれだけ積んでいても、継続ダメージそのものは軽くなりません。

> 注意: 継続ダメージは相手のHPへ直接書き込まれる方式のため、ノックバックや被弾モーション、トーテムなどの一部の挙動と噛み合わない可能性があります。挙動の細かい検証は今後の課題です（詳しくは[実装状況と注意点](12-実装状況と注意点.md)）。

## 13. PvP（プレイヤー同士の戦い）

**PvPはできますが、抑制されています。**

| 項目 | 内容 |
|---|---|
| ダメージ倍率 | 通常の0.5倍（半分） |
| 1発の上限 | 相手の最大体力の15%まで |

サーバーの主眼はあくまで協力プレイ（PvE）ですが、プレイヤー同士で殴り合っても不意打ちで一撃死することはない、という設計です。

## 14. 強さの土台は「戦闘レベル」＋装備ステ

このサーバーのダメージは、**戦闘レベル（combatレベル）による成長**と、**装備に載るステータス（攻撃力など）**の両方が効きます。

- 戦闘レベルは、戦闘スキルツリーのレベルから計算されます（[育成と解放](08-育成と解放.md)）。
- レベルが1上がるごとに、基礎ダメージが少しずつ伸びます（既定はレベルあたり **+1%**）。
- あわせて、武器などの `attack-power`（攻撃力）や会心・貫通といった装備ステも基礎ダメージや各ステップに乗ります。品質による厳選は、この装備ステの上振れに効きます。

| 項目 | 内容 |
|---|---|
| 戦闘レベルの決まり方 | 対象スキル（軽量武器・重量武器・弓術・Ars魔法）のうち「伸びている上位スキル」から算出（[育成と解放](08-育成と解放.md)で詳説） |
| レベル成長 | 戦闘レベル（装備の品質とは別枠） |
| レベルあたりの伸び | +1%（既定・調整中） |
| 装備の役割 | 攻撃力・会心・貫通などのステを載せる（厳選で個体差が出る） |
| レベルの範囲 | 0〜100（既定） |

つまり「スキルを育てつつ、良い個体の装備を厳選する」のが強さの両輪です。育成の詳しい話は[育成と解放](08-育成と解放.md)を見てください。

## 15. まとめ

- 攻撃の属性は攻撃源で決まる（武器＝物理、呪文＝魔法）。モブの一部は魔法混じりの攻撃をしてくる。
- 物理も魔法も同じ8ステップを通る（対称ダメージパイプライン）。**守備力は会心より先に引かれる**。
- 貫通は防御率に効き、耐性には効かない。固定ダメージは防御を完全に無視する純加算。
- 軽減は最大90%まで。最低1割は必ず通る。
- 連打減衰（最大威力1/10）と無敵時間（毎秒2発上限）が、重武器＝一撃重視／軽武器＝手数、という設計を支えている。
- 出血・毒・ウィザーの継続ダメージは被ダメージ軽減しか通らない。反射は発動確率＋素殴りダメージで、被ダメージには比例しない。
- ダメージは戦闘レベル成長（既定+1%/Lv）と装備ステ（攻撃力など）の両方で決まる。
- PvPはできるが、ダメージ半分・上限15%で抑制されている。
- 会心は近接武器の会心率で機能し、魔法ダメージも触媒ステが連携済み。各機能の現状は[実装状況と注意点](12-実装状況と注意点.md)を参照。
