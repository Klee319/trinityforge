## 1. 4重抑制の役割分担（時間軸・経路で濫用を分担）

攻撃魔法は実装するが、以下4機構で別々の濫用を塞ぐ。各抑制が「何を」抑えるかを固定し、数値調整時に役割が混線しないようにする。

| 抑制 | 抑える濫用 | 担当層 |
|---|---|---|
| ①form別CT | **瞬間バースト**（同一formの連射コンボ） | アドオン（`ArsSpellCastEvent` cancel） |
| ②gear非依存 | **装備tierでの青天井スケール** | EliteMobs fork（既存 calc 1.0短絡、DESIGN v0.4） |
| ③触媒ステ依存 | （②の裏返し）魔法火力を伸ばす経路を**触媒1点に限定** | COMBAT デフォルトダメージ式 |
| ④マナ＋解放ゲート | **継続DPS**（撃ち続け）と**全グリフ即使用** | ArsPaper fork（mana / use-gate） |

- **時間軸の分担**: ①CT＝単発バースト制限、④マナ＝持続DPS制限。両方残すのは冗長ではなく、別軸の濫用を塞ぐため（確定）
- **経路の分担**: ②で装備スケールを殺し、③で触媒のみを唯一の火力レバーにする（gear非依存と触媒ステ依存は矛盾せず、対象が別）

## 2. 増強/減衰グリフの二重計上回避（層分離方式）— COMBAT §8解決

Ars NativeのAmplify(増強)/Dampen(減衰)グリフと、COMBAT式の`割合追加ダメージ%`/`ダメージ補正%`の二重計上を**層分離**で防ぐ。

### 2.1 計算層の分離

| 計算層 | 担当する増減 |
|---|---|
| **デフォルト魔法ダメージの内側**（COMBAT §2.2 「Arsスペル攻撃力(Ars config値)」に作用） | Ars増強/減衰グリフ |
| **アドオン式**（COMBAT §2.1 step1 `割合追加ダメージ%` / step5 `ダメージ補正%`） | 触媒・装備ステータス由来のみ |

### 2.2 帰結

- Ars増強グリフは**スペルビルドの深度**として残る（追加マナを消費する正規の威力レバー）
- 厳選ステ（触媒攻撃力・割合追加ダメージ%）の伸びは**別レーン**となり、増強グリフと乗算で二重に乗らない
- COMBAT §2.2の魔法デフォルトダメージ式：
  `デフォルト魔法ダメージ = Arsスペル攻撃力(Ars config × 増強/減衰グリフ) + 触媒の攻撃力ステータス × attack-power-scale`
  ← 増強/減衰は左項の内側で閉じる

### 2.3 実装上の補足（2026-07-31 D6）

- 右項の「触媒」は **`spellbooks.yml` の `catalysts:` 登録品に限らない**。実際に詠唱に使ったアイテム
  （バインド詠唱で右クリックした手持ち品）が **`use-skill: ARS_MAGIC` を持てば**その攻撃力が乗る。
  TFカタログの杖11本（`BLAZE_ROD#400002`〜`#400014` 等）は `catalysts:` に載っていないため、
  以前はここが魔導書に化けて杖の攻撃力（最上位 10584）が完全に落ちていた。
- `use-skill` で絞るのは、任意アイテムにバインドできる仕様上、剣やツルハシの近接ステが
  魔法へ乗ってしまうのを防ぐため。魔導書を直接右クリックして詠唱する経路は攻撃力0のまま。
- `attack-power-scale` は `combat/damage.yml` の `magical.attack-power-scale`（既定 **1.0** = 本節の
  仕様どおり100%加算、範囲 0.0〜10.0）。魔法は範囲/伝播/残留で1詠唱から複数回ダメージが出るため、
  近接との釣り合いは杖の `attack-power` を触らずこの係数だけで一括調整できる。
- グリフ別ダメージ倍率（TF `glyph_damage_multiplier_bonus` / `stats/glyph-damage-boost.yml`）は
  **上記の合成後の基礎ダメージ**へ掛かる（守備力減算より前）。グリフ基礎だけに掛けると、
  杖の攻撃力が支配的な高レベル帯で倍率が実質無効になるため。

## 3. form別CT機構

### 3.1 構造パラメータ（方式・非数値）

| パラメータ | 決定 |
|---|---|
| 判定層 | `ArsSpellCastEvent`でform判定 → 該当formがCT中なら`setCancelled(true)`。**マナ消費前**に弾く（β発動時不発と同じフック点） |
| トラッカー粒度 | **formごとに独立**（Projectile撃ってもTouch/Self/AOEは撃てる）→ form多様性を強制し、①の狙いを満たす |
| CT起点 | **詠唱成立時**（命中ベースは外し撃ちで回避可能なため不採用） |

### 3.2 ARS_SPEC側の構造ギャップ（要追記・TODO）

- 現状`ArsSpellCastEvent`は`getPrimaryEffectId()`（＝効果ID）しか持たず、**form（Projectile/Touch/Self/AOE/Beam/Wall等）取得アクセサが無い**
- form別CTの判定に **`getCastForm()`（または`getFormId()`）アクセサの追加**が必要 → `ARS_SPEC.md` §6.1 に1項目追記（§6で反映）
- CT状態はプレイヤー×form のマップでアドオン側が保持（永続化不要・短命。再起動でリセットでよい）

### 3.3 CT短縮レバーの所在（方式のみ）

- form CTの短縮は**限定経路のみ**で許可（全form一律短縮は①を無効化するため不可）
- 短縮の供給源候補：特定perk／触媒の限定ステータス（どの軸に置くかは数値調整フェーズで確定）

## 4. Tierの定義 = (c) 両方モデル

Ars魔法ツリーのメインラインA-E（UNLOCK §5.9注）が上げる「利用可能Tier」は、以下**両方**を担う。

| Tierが上げるもの | 内容 |
|---|---|
| (a) スロット数 | 1スペルに組めるグリフ総数の上限が拡張 |
| (b) グリフ属性ゲート | 各グリフのTier属性により、高Tierグリフ（超増強系・炸裂・照射等）が高ツリーレベルで初めて使用解放（UNLOCK §5.9 C-3が該当） |

- (b)は**使用ゲート（Model Y）**と同じ判定経路に乗せる：高Tierグリフは「scribe自由・使用にperk必要」かつ「Tier条件も満たす」
- スロット数(a)はArsPaperの`グリフ配置数`ステ（メインラインperk）として`addManaModifier`類似のmodifierで加算（実装方式は実装フェーズで確定）

## 5. 確定事項サマリ

- 4重抑制の役割分担（①CT=バースト/④マナ=持続/②gear非依存/③触媒ステ依存）を固定
- 増強/減衰グリフ＝**層分離**（デフォルト魔法ダメージの内側に隔離）→ COMBAT §8の二重計上を解消
- form別CT＝**form独立トラッカー＋詠唱成立時起点**、`ArsSpellCastEvent`でマナ消費前cancel
- Tier＝**(c) スロット数拡張＋高Tierグリフ属性ゲートの両方**
