## 2. ダメージ計算パイプライン（統一・対称）

与ダメージ・被ダメージを**同一の対称パイプライン**で処理する（攻撃者が敵でも自分でも同じ式）。
1回の攻撃を **物理成分 / 魔法成分** に分解し、各成分を独立に通してから合算する。

### 2.1 成分ごとの処理順

> **2026-07-25 改訂（守備力の前倒し）**: 旧仕様は守備力(flat)を%軽減の**後**（旧step6）で減算していたため、
> %軽減が全て掛かった後の小さな値からさらに大きな固定値を引く形になり、帯適正の防具なら被弾が
> 床値に張り付いて実質無敵、防具を外す/帯を間違えると即死という二値状態に陥っていた。
> 本改訂で守備力を**減算段の最初（%軽減より前）**へ移動し、固定ダメージ（旧: flatが削った分の還付）を
> **全防御ステータス貫通の純加算**へ意味論変更した。

```
（デフォルトダメージ > 0 の成分のみ実行）

1. base   = デフォルトダメージ + 固定追加ダメージ + デフォルトダメージ × 割合追加ダメージ%
2. 守備力 : flat = 守備力[該当type]（防具強度は含まない）
            base -= flat
            base = max(base, 0)                       ← ここでの0クランプは「0未満」にのみ効く。
                                                          defense.min-flat を負に運用している場合、
                                                          守備力が負値だと base -= 負値 で base が
                                                          増える(＝防具が被ダメを増幅する)が、この
                                                          クランプは0未満のみを切るので増幅は妨げない
3. 会心   : 会心率で判定 → 成立時 base ×= (1 + 会心ダメージ% × (1 - min(1, 防具強度)))
                                                          ← 防具強度(会心軽減率)は会心の上乗せ分のみを削る。
                                                          守備力を会心の前に置くことで「守備力＝通常も会心も
                                                          等しく削る」「防具強度＝会心の上乗せ分だけ削る」と
                                                          役割が分離する（守備力を会心の後段に置くと会心倍率で
                                                          希釈され、防具強度と役割が重複してしまうため）
4. 防御率 : base ×= (1 - 防御率% × (1 - 貫通率%))
5. 耐性   : base ×= (1 - 該当耐性%[物理/魔法])          ← 貫通は効かない
6. 補正   : 攻撃側 base ×= Uniform[min(1, endpoint), max(1, endpoint)]  ※endpoint=ダメージ補正% vs 100%（1.0/0/未設定→×1.0固定）
            防御側 base ×= (1 - 被ダメージ軽減%)
7. クランプ: base = max(base, 1)                        ← 成分ごとに 0以下にしない（この 1 は既定値でconfig可変＝ `min-component-damage`）
8. 固定ダメ: base += 固定ダメージ                        ← 守備力・防御率・耐性・被ダメージ軽減・step7の床、
                                                          すべてを貫通する無条件の純加算（旧「flatが削った分だけ
                                                          還付する」意味論は廃止）

総ダメージ = Σ(物理成分, 魔法成分)
```

### 2.2 デフォルトダメージの定義

| 攻撃源 | デフォルトダメージ |
|---|---|
| 物理（武器・ツール） | **バニラ与ダメージ基準**（attackDamage、mob levelスケール反映） |
| 魔法（触媒・スペル） | **Arsスペル攻撃力(Ars config値) + 触媒の攻撃力ステータス** |

- 攻撃タイプ（物理/魔法）は**攻撃源で確定**: 武器=物理、触媒/スペル=魔法
- ハイブリッド攻撃（物理武器＋魔法エンチャ等）のタイプ判定は未定（§8）

### 2.3 固定ダメージの性質

- `固定ダメージ` は **全ての防御ステータス（守備力・防御率%・耐性%・被ダメージ軽減%・step7の床）を貫通する無条件の純加算**（step8）
- 旧仕様（flatが削った分だけ還付し、preFlatを超えない）は**廃止**。守備力の有無・大小に関わらず常に加算される
- 防具が薄い相手にも、重装甲の相手にも同じ値がそのまま乗る（対重装甲カウンター専用ではなくなった）

### 2.4 貫通の適用範囲

- `貫通率%` は **`防御率%` のみ無視**する（step4）
- `耐性%`（step5）・`守備力(flat)`（step2）には効かない（三すくみを貫通で崩さないため）

## 3. ステータス一覧（3ファミリー）

> **更新（LD-13, 2026-07-14 / `OPEN_DECISIONS.md`）— 防御 typing 改訂**: 本章以下の防御ステの物理/魔法の分け方を改訂した。**耐性%のみ typed（物理耐性/魔法耐性で別）。守備力(flat)・防御率%・被ダメージ軽減%・防具強度・回避 は共通（type非依存＝物理・魔法の両方に効く）**。従って **vanilla armor/toughness は物理・魔法の両成分を軽減**する。これにより下記 §3.3（「バニラ装備限定＝物理守備力/物理耐性」）・§3.4（「Ars装備限定＝魔法守備力」で魔法は装甲非依存の含意）・§4（「守備力・耐性を typed に一本化」）・§2.1 step6 の `守備力[該当type]` 表記は**本注記で上書き**される。魔法耐性は追加の特化層。物理装甲寄り/魔法耐性寄りの差はアイテム設計（typed耐性を積む）で出す。
>
> ※実装は本注記に準拠済み（`SymmetricCombatService.resolveDefender` が vanilla armor を両成分へ適用、`DefenseStatBridge` が耐性のみ typed）。※mobのPDCプロファイルは per-type の守備力/防御率/軽減を持ちうる（player由来値は共通）＝mob/player 非対称は許容（LD-13 M4）。

## 4. 命名規約（混同防止）

| 用語 | 意味 |
|---|---|
| 防御率% | vanilla armor由来の%軽減。**貫通の対象** |
| 守備力（物理 / 魔法・flat） | typeごとのflat減算 |
| 防具強度（全体flat） | type非依存のflat減算。固定ダメージcap相殺の対象 |
| ダメージ補正%（攻撃） / 被ダメージ軽減%（防御） | 乗算補正の攻守ペア |

- **（LD-13で改訂）** `耐性` のみ typed（物理耐性/魔法耐性）。`守備力`（flat）は**共通**（物理・魔法両方に効く）。旧「守備力・耐性を typed に一本化」方針は §3冒頭の更新注記で上書き済み

## 5. バニラ要素のマッピング

| バニラ要素 | 写像先 | 備考 |
|---|---|---|
| 攻撃力上昇(Strength) / 弱体(Weakness) | デフォルト物理ダメージに内包 | バニラがattackDamageを増減 → そのまま流入 |
| 耐性(Resistance) | **無効化し `防御率%` へ統合** | バニラ独自の最終軽減を残すと二重軽減になるため |
| armor | 防御率% | 使い回し |
| armor toughness | 防具強度 | 使い回し |
| attackDamage | 攻撃力（物理） | 使い回し |
| knockback_resistance | ノックバック耐性 | 使い回し |

- **パイプライン畳み込み対象外**（バニラ挙動をそのまま残す）: `BLOCKING`（盾）／`ABSORPTION`（衝撃吸収）／`HARD_HAT`／`FREEZING`。**ゼロ化（無効化して本式へ統合）するのは `ARMOR` と `RESISTANCE` のみ**（実装がこの方針に修正済み）
- **敵の防御率%の決定優先順位**（§6と整合）: ① PDCプロファイルあり（`MobData.hasProfile()`）→ そのPDC値を使用　② PDCプロファイル無し → バニラ `armor` attribute を上表の写像で防御率%へ変換
- **未定義（要確認）**: バニラのジャンプクリティカル（打撃×1.5）の扱いは本パイプラインで未定義。扱い自体は `OPEN_DECISIONS.md` に未決事項として登録済み

## 6. バニラ敵の扱い

- **バニラ敵にもデフォルトstatプロファイルを付与**して式を全敵に一貫適用する
  - 耐性0 / 守備力0 / level = エリア基準
  - **防御率%は§5の優先順位に従う**: PDCプロファイルがあればPDC値、無ければバニラ`armor` attributeを§5の写像で防御率%へ変換（armor属性を持たない/0のバニラモブは結果的に防御率0になる）
- これによりバニラ/EliteMobsで戦闘感が割れない

---

## 7. 修繕廃止との関係

- 修繕は廃止（DESIGN方針）。よって `耐久力` は**有限の厳選・消耗リソース**として機能する
- 鍛冶/錬金ツリーの耐久回復系（圧縮木材での回復等）が消耗サイクルの調整弁になる
