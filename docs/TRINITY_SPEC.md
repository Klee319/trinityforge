## 1. 三すくみの再定義 = 相補トリニティ（モデルA）

旧ロック「三すくみ＝物理/魔法/囮」は、攻撃属性2種と機能1種を混ぜていた。本サーバ（**PvE協力・最高難易度ダンジョン制覇／PvPなし**）に合わせ、**相補トリニティ**へ再定義する。

- **「すくみ（循環）」ではない**。3軸が揃うほど高難易度を抜けやすい**相補関係**
- 厳密RPS（モデルB）は対人で映えるがPvPがないため不採用

### 1.1 3軸の格付け（囮は「おまけ」の補助極）

| 軸 | 位置づけ |
|---|---|
| **物理**（攻撃属性） | **主柱**。攻撃源＝武器で確定。モブの物理耐性%で減衰 |
| **魔法**（攻撃属性） | **主柱**。攻撃源＝触媒で確定。モブの魔法耐性%で減衰 |
| **囮（ヘイト）** | **おまけ／補助極**。タンク・獣使いが担う前線の土台。DPS属性ではなく、アタッカーを**成立させる支援**。必須化しすぎず、難易度に応じて価値が出る |

- 主柱は**物理/魔法の2本**（同格）。囮はそれを支える**第3の補助レイヤー**であって、対等な火力極ではない

## 2. 耐性の偏り（粒度 = c：ダンジョン＋モブ両方）

属性の使い分けを生むため、物理耐性%/魔法耐性%の偏りを**2層**で設計する。

| 層 | 役割 |
|---|---|
| **ダンジョン単位** | 大枠の耐性傾向（物理寄り/魔法寄り/両刀必須）→ 攻略前の編成・装備選びの動機 |
| **モブ単位** | 同一ダンジョン内でもモブ種別ごとに耐性が異なる → その場で武器↔触媒を持ち替える動機 |

- 実装: モブ（EliteMobs/バニラ問わず）に**耐性プロファイル**を付与（COMBAT §6のデフォルトstatプロファイルを拡張）。ダンジョン定義側で大枠、モブ定義側で個別に上書き

## 3. ソロ/少人数との両立（人数ゲートにしない）

少人数運用（鯖民同士で回す）でも詰まないことを構造原則とする。

- **攻撃属性**: 武器/触媒の**持ち替えで物理↔魔法を1人でカバー**可能（攻撃源で確定するため自然）
- **囮役**: **ペット（獣使い）がヘイトを肩代わり** → ソロでも前線の土台を確保
- 原則: **「3人いれば最適・1人でも持ち替え＋ペットで攻略可能」**。人数で効率は変わるが、**人数を突破ゲートにはしない**

---

## 4. 囮（ヘイト役）の必然性の担保

ヘイト管理が「無くてもゴリ押せる」と相補が崩壊し、「必須すぎる」と過疎で詰む。両極を避ける：

- **難易度が上がるほどモブの瞬間火力（バースト）を上げ**、ヘイト分散しないとアタッカーが溶ける → ヘイト役の価値が難易度に比例して上がる
- ただしソロは**ペットでヘイト肩代わり**できるため詰まない（§3と接続）
- 構造原則: **「難易度が上がるほどヘイト管理の価値が上がる。ただし代替手段（ペット）は常にある」**

## 5. 用語整理（旧ロックの上書き）

- 進捗memory等の「**三すくみ物理/魔法/囮**」表記は、本仕様の**相補トリニティ（物理・魔法の2主柱 ＋ 囮ヘイトの補助極）**に置き換える
- "囮" = 攻撃属性の第三極ではなく、**ヘイト管理機能（おまけの補助極）**
