# 実装フェーズ計画書（設定駆動・依存順マイルストーン）

> 統合MMOサーバ（EliteMobs fork + ArsPaper fork + ValhallaMMO[無改造] + 自作ペットPL[依存]）の実装計画。
> 設計フェーズ完了（詳細spec 11本＋統合spec 2本＋fork仕様2本）を受けて、実装着工点と依存順マイルストーンを定義する。
> **数値・バフ・レシピは未確定。すべて設定ファイル外出しし、コード変更なしで調整可能にすることを最初から前提とする。**
> 数値確定は実装後（M7・プレイ後）。本計画はあくまで構造を先に立てるためのもの。

参照元: `ADDON_INTEGRATION_SPEC.md §7`（チェックリスト）／各詳細spec／`fork/ELITEMOBS_FORK_SPEC.md`・`fork/ARSPAPER_FORK_SPEC.md`

## 0. 横断方針：設定駆動（Config-Driven）= 計画の核

実装の最重要制約。**仮の既定値＋設定外出し**で進め、ハードコードを禁止する。

### 0.1 ハードコード禁止リスト（設定へ外出しする対象）

| ドメイン | 外出しする数値 | 設定ファイル（例） |
|---|---|---|
| 戦闘 | ダメージ係数・8stepの各係数・固定ダメージcap | `combat/damage.yml` |
| ステータス | ロール範囲(min/max)・品質別確率分布・基礎値・Attribute写像係数 | `stats/roll.yml` `stats/quality.yml` `stats/mapping.yml` |
| バフ | 補助職常時バフ値・戦闘職内部強化量・倍率(経験値1.2倍 等) | `roles/buffs.yml` |
| 魔法 | form別CT秒数・マナレート・Tierスロット数・増減グリフ係数 | `magic/cooldown.yml` `magic/mana.yml` `magic/tier.yml` |
| ダンジョン | 各供給元ドロップ率・属性テーマ配分・人数カーブ・Guildランク対応表 | `dungeon/loot.yml` `dungeon/resist.yml` `dungeon/scaling.yml` |
| 育成 | レベルキャップ・プレステージ上限/逓減カーブ・装備使用レベル要求カーブ | `progression/levels.yml` `progression/prestige.yml` |
| ヘイト | 各種ヘイトレート・タンク/獣使い/ペット係数 | `hate/rates.yml` |
| ペット | 主火力化抑制の基礎値・属性付与既定 | `pets/balance.yml` |

### 0.2 設定基盤要件

- **スキーマ検証付きロード**: fail-fast（不正値で起動拒否 or 明示ログ）＋既定値フォールバック。
- **ホットリロード**: `/reload`系コマンドで再起動なしに数値調整反映。
- **ドメイン別小ファイル構成**: 上表の `combat/` `stats/` `roles/` `magic/` `dungeon/` `progression/` `hate/` `pets/` でディレクトリ分割（CLAUDE.md: many small files）。

### 0.3 厳選ステの導出（不変ベイク禁止）

厳選ステは `rollSeed ＋ 品質(0-5) ＋ 調整可能パラメータテーブル` から **毎回導出**（SELECTION §5）。
テーブル＝設定。既存アイテムも再計算で新バランスを反映できる（不変ベイクしない）。

## 1. 依存グラフ

```
M0 基盤(Config基盤 + PDC framework)
  ├─> M1 戦闘コア(対称パイプライン + 新規ステ + Attribute写像 + ステ導出)
  │     ├─> M2 魔法統合(ArsPaper fork)
  │     ├─> M5 ダンジョン(EliteMobs fork)
  │     └─> M6 ヘイト・ペット
  ├─> M3 育成・解放(Valhalla perk参照 / 使用ゲート / 使用レベル / バインド / プレステージ / ルーティング)
  └─> M4 厳選(入手3系統 + 品質)
M7 仕上げ(コレクション / クロスプレイ検証 / 数値バランス調整)
```

- 根: **M0**（全マイルストーンが Config基盤＋PDC framework に依存）
- 葉: **M7**（全機能完成後の統合・調整）
- 循環なし。M1 完了が M2/M5/M6 の前提。M3/M4 は M0 直後から並行可能。

## 2. マイルストーン（各DoDに「該当数値が設定で変えられる」を必須化）

### M0 基盤
- **内容**: Config基盤（スキーマ検証 / ホットリロード / ドメイン別小ファイル）＋ PDC framework（§6スキーマの読み書きラッパ）。
- **DoD**: 任意の数値を設定に置き、リロードで反映できる器が動く。PDCの読み書きが型安全に通る。

### M1 戦闘コア
- **内容**: 対称8stepダメージパイプライン本体（係数=設定）＋新規ステ群（COMBAT §1.2 / §3）＋Attribute写像＋バニラstatプロファイル写像＋厳選ステ導出関数。
- **対応チェックリスト**: 対称ダメージパイプライン本体／新規ステ群とAttribute写像／厳選ステ導出関数と再計算（導出ロジック。入手系統はM4）。
- **DoD**: バニラ敵（全ステ0＋level）に物理/魔法成分が流れ、設定変更が即ダメージに反映される。

### M2 魔法統合（ArsPaper fork）
- **内容**: デフォルト魔法ダメージ供給（SpellEffect→対称パイプライン）＋増減グリフ隔離（§8二重計上回避）＋form別CT（form独立トラッカー・詠唱成立起点・マナ消費前cancel）＋setManaCost/マナ連携。
- **対応チェックリスト**: ArsPaper（使用ゲートα/β・form別CT・setManaCost・増減グリフ隔離・unlockRecipe/Ritual）のうち魔法戦闘部分。
- **DoD**: 攻撃魔法ダメージがM1パイプラインに乗り、CT秒数・マナレート・グリフ係数がすべて設定で変わる。

### M3 育成・解放
- **内容**: Valhalla perk参照層（読取）＋使用ゲートα(作成時)/β(発動時)＋解放ルーティング（種別判定）＋装備使用レベルチェック＋バインド/所有権＋プレステージ処理＋解放維持アイテム。
- **対応チェックリスト**: 装備使用レベルチェック／バインド・所有権／プレステージ処理／解放維持アイテム／解放ルーティング／ArsPaperのunlockRecipe・Ritual perkゲート。
- **DoD**: perk有無で使用可否が切替わり、使用レベル要求カーブ・プレステージ逓減カーブが設定で変わる。

### M4 厳選
- **内容**: 入手3系統（能動クラフト/受動ドロップ/特殊トレジャー）＋品質0-5（設定分布）＋既存アイテム再計算。
- **対応チェックリスト**: 厳選ステ導出の入手・品質側（導出関数本体はM1）。
- **DoD**: 品質別確率分布・ロール範囲が設定で変わり、リロード後に既存アイテムへ再計算が効く。

### M5 ダンジョン（EliteMobs fork）
- **内容**: gear非依存ダメ改造＋combatレベル写像（Valhalla戦闘職スキルツリー平均→EliteMobs combat）＋3層構造/Guild入場ゲート＋供給loot（PlayerTable=1人あたり一定）＋耐性2層（ダンジョン属性＋逆張りモブ）＋人数スケーリング。
- **対応チェックリスト**: combatレベル写像／EliteMobs（gear非依存・combat差し替え・供給loot・耐性2層・人数スケール・Guild入場）。
- **DoD**: gear非依存でダメが成立し、写像カーブ・ドロップ率・属性配分・人数カーブ・Guildランク対応表が全部設定。

### M6 ヘイト・ペット
- **内容**: ヘイト値システム＋EliteMobs targetingフック＋ペット3点（攻撃属性付与/ヘイト参加/ダメージfixer）＋依存ペットPL選定。
- **対応チェックリスト**: ヘイト値システム＋targetingフック／ペット3点＋依存PL選定。
- **DoD**: ヘイトでターゲットが動き、ペット素ダメが対称パイプラインに乗る。各種レート・抑制基礎値が設定。
- **未決の入口**: 依存ペットPLの具体選定とAPI/イベント有無で実装手段が決まる（§8へ）。

### M7 仕上げ
- **内容**: コレクション図鑑→報酬解放（縦強化にしない）＋クロスプレイ表示検証（Bedrock/Geyser）＋数値バランス調整（各spec末尾の未決節を消化）。
- **対応チェックリスト**: コレクション図鑑→報酬解放／クロスプレイ表示検証。
- **DoD**: 図鑑進捗で称号/コスメ/恒久QoLが解放され、Bedrockで表示崩れがなく、§8未決数値が確定値で埋まる。

## 3. 最初のマイルストーン（着工点）= M0 → M1前半

単独で着手可能な具体ステップ:

1. **Config基盤PoC**: 1ドメイン（`combat/damage.yml`）をスキーマ検証付きでロード＋ホットリロード。不正値はfail-fast、欠損は既定値。
2. **PDC framework最小**: §6のアイテム/プレイヤー/mobキーを型安全に読み書きするラッパ。
3. **対称パイプラインの物理成分のみ**を係数=設定読み込みで実装。
4. **検証**: バニラ敵（全0＋level）に流し、`damage.yml` の係数を変えてリロード→即ダメージに反映されることを確認。

これが通れば M1 残り（魔法成分の器・新規ステ全部・Attribute写像・厳選導出）へ展開する。
