## 1. 統合アドオンの責務

### 1.1 ダメージパイプライン（COMBAT §2）
- 1攻撃を**物理/魔法成分に分解**し、各成分を同一8ステップで処理:
  `base→会心→防御率(貫通適用)→耐性→補正→preFlat保持→flat(守備力+防具強度)減算→max1クランプ→固定ダメージ相殺(preFlat上限)`
- 与/被ダメ**対称**（攻撃者が敵でも自分でもペットでも同一式）
- バニラ敵にも**デフォルトstatプロファイル付与**（耐性0/守備力0/防御率0/level=エリア基準・COMBAT §6）
- バニラ`Resistance`は無効化し**防御率%へ統合**（二重軽減防止・COMBAT §5）

### 1.2 新規ステータス実装（COMBAT §3）
- 攻撃系: 触媒攻撃力／貫通率%／会心率・会心ダメージ(物理・魔法)／追加ダメージ(固定・%)／固定ダメージ／ダメージ補正%
- 防御系（LD-13 typing）: 被ダメージ軽減%(共通)／守備力(flat・**共通**)／物理・魔法耐性%(**typedのみ**)／防具強度(type非依存flat)／回避(共通・攻撃全体を無効化)。※防御率%(armor由来)・守備力・防具強度は物理魔法**両方**を軽減
- Ars装備系: 被弾時/攻撃時/非発動時マナ回復（ArsPaper fork連携）
- ※バニラ流用（独自ストックしない）: 攻撃力(武器=attackDamage)／防御率%(armor)／防具強度(toughness)／ノックバック耐性／耐久力

### 1.3 ヘイト値システム（新規・ROLE §4）
- タンク/獣使い/ペットが共有する単一システム。**EliteMobs targetingにフック**して敵視を制御
- タンク＝ヘイト上昇、ペット＝常時じわ稼ぎ＋獣使い能動挑発（PET §3.2）

### 1.4 厳選ステ導出（SELECTION §5・重要）
- アイテムステは**「rollSeed＋品質(0-5)＋調整可能パラメータテーブル」から導出**（不変ベイクしない）
- テーブル変更→既存アイテムも**再計算で反映**できる導出関数を用意（パッチ再バランス・リロール後付けの基盤）
- 基礎値（ベース）は固定＝バランス主ノブ、味付けステがロール範囲で振れる

### 1.5 combatレベル写像（DUNGEON §2・重要）
- **EliteMobsのcombatレベル＝LD-7写像**（`max(物理柱, 魔法柱) × 上限`。`OPEN_DECISIONS.md` LD-7参照）で算出（ValhallaMMOレベル読取→EliteMobs combatへ差し替え）
- ⚠**実装は暫定**: 現行 `CombatLevelModel` は加重平均（軽量/重量/弓/ARS_MAGICの等重み平均）で、LD-7の max-of-pillars とは構造が別。完全移行はコード変更後（`OPEN_DECISIONS.md` Q6/LD-7注記・`SKILL_TREE_SPEC §4`）
- gear非依存（DESIGN v0.4）の代替指標。柱内λ・上限・変換カーブは数値フェーズ

### 1.6 育成/所有権（PROGRESSION）
- **装備使用レベル制限**: 強い装備/触媒の使用に関連スキルツリーレベルを要求（チェックして使用可否）
- **バインド/所有権**: 厳選完成品=ソウルバインド／素材コアスレッド=取引可／エンドアイテム=所有者UUID付与。取引制限フック
- **プレステージ処理**: スキルレベルreset、保護perk再付与、永続ボーナス累積（上限/逓減）。保持perkはPDC記録
- **解放維持アイテム**: 指定perkをプレステージ耐性化（補助アイテムはこの1種のみ）

### 1.7 解放ルーティング（UNLOCK §3）
- スキルツリーの「○○解放」を種別判定し振り分け: グリフ使用権→ArsPaper使用ゲート／レシピ→unlockRecipe()orValhalla／儀式→unlockRitual()／機能→アドオン内部フラグ・他PL連携／厳選特典→loot

### 1.8 コレクション（DUNGEON §5）
- 図鑑（コア/スレッド/モブ討伐）進捗→段階的に称号/コスメ/恒久QoLを解放（縦強化にしない）

### 1.9 ペット連携fixer（PET §2）
- ①ペット攻撃にダメージ属性付与／②ペットをヘイト値システムへ参加／③ペット素ダメをCOMBATパイプラインへ乗せ直す補正器

## 2. EliteMobs fork 改変点

- **ダメージシステム改造**: gear非依存。物理生与ダメ＝「バニラ基準 × mob levelスケール」のみ（装備tier倍率を排除・DESIGN v0.4 / COMBAT §1）
- **targetingフック**: ヘイト値システム連携（§1.3）
- **combatレベルのソース差し替え**: item level → LD-7写像（物理柱/魔法柱のmax、§1.5）
- **ダンジョン3層 + Adventurer's Guildランク入場ゲート**（DUNGEON §1-2）
- **供給元（CustomDrops/loot）**: 転職アイテム(②ボス)／厳選装備触媒(②)／コア(①+②雑魚)／エンドアイテム(③)（DUNGEON §3）
- **耐性2層プロファイル**: ダンジョン属性テーマ大枠＋モブ個別逆張り（DUNGEON §4 / TRINITY §2）
- **人数スケーリング**: ソロクリア可能カーブ＋ドロップ期待値1人あたり一定（DUNGEON §6）

## 3. ArsPaper fork 改変点

- **使用ゲート（UNLOCK §2.2）**: (α)作成時ブロック＝scribe/spellbind時に未許可グリフを組み込ませない（主）／(β)発動時不発＝既存スペルが後から未許可化した場合castで不発（保険）。判定の真実＝Valhalla perk
- **form別CT（MAGIC_BALANCE §3 / ARS_SPEC §6.1）**: `ArsSpellCastEvent#getCastForm()`でform識別、form独立トラッカー、詠唱成立時起点、**マナ消費前にcancel**
- **マナ消費改竄**: `ArsSpellCastEvent#setManaCost`（マナ消費量低下ステ・COMBAT §3.5）
- **デフォルト魔法ダメージ供給**: 「Arsスペル攻撃力(Ars config値) + 触媒攻撃力ステ」をパイプラインへ（COMBAT §2.2）
- **増強/減衰グリフの隔離（MAGIC_BALANCE §2）**: Ars側の増減はデフォルト魔法ダメージの内側に閉じ込め、本式の`割合追加ダメージ%`/`ダメージ補正%`とは二重計上させない
- **unlockRecipe() / unlockRitual()**（UNLOCK §3）
- **マナ最大値/回復速度ステ連携**（COMBAT §3.4）
- **ItemQuality(0-5) / rollSeed**（SELECTION §3。品質効果は「抽選質の底上げ」へ再マッピング）
- **修繕儀式の許可**（バニラ修繕は廃止、Ars鍛冶B-2-3の修繕儀式のみ・コスト重め・UNLOCK §6）

## 6. データスキーマ（PDC・暫定キー設計）

> 数値の真実はPDC。以下は集約の見取り図（正式キー名・型は実装フェーズ）。

| 対象 | 主な保持データ |
|---|---|
| アイテム | rollSeed／quality(0-5)／各ステ値（導出元 or キャッシュ）／所有者UUID／バインド種別／使用レベル要件 |
| プレイヤー | ヘイト関連値／保持perk一覧（解放維持）／プレステージ回数・永続ボーナス／コレクション図鑑進捗／ロール（戦闘職1+補助職1） |
| mob（敵/ペット含む） | statプロファイル（物理/魔法 耐性・守備力・防御率）／level／ダンジョン属性テーマ／ヘイトテーブル† |

- ステは**不変ベイクせず**、rollSeed＋品質＋調整可能テーブルから導出（§1.4・再バランス可能性を担保）
- † **整合注記（2026-07-03・現実装準拠）**: ヘイトテーブルは実際にはPDC永続化せず、`com.trinityforge.hate.HateService` 内でメモリ揮発（cap/LRU・TTL・sweep）として保持される。本表は当初の見取り図であり、この点は実装と乖離
