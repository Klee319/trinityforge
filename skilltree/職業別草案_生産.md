# 生産10ツリー スキルツリー草案

対象: 採掘 / 伐採 / 農業 / エンチャント / 切削 / 鍛冶 / 錬金 / 釣り / Ars魔法 / Ars鍛冶
（`skilltree/_草案作成ブリーフ.md` 準拠。戦闘6ツリーは別作業者担当のため対象外）

## 凡例

- `・A:` `・B:`… = 主軸（A=Lv10 / B=Lv30 / C=Lv50 / D=Lv70 / E=Lv90）。全員が必ず通る。
- `　・X-n:` = 全角スペース1つで字下げした分岐ノード（チェーンの深さに関わらずインデントは1段固定。順序はノードidの連番で示す）
- `・X-α-1:` = ギリシャ路線（`group` で排他）。`※αを選ぶと…` でレーン固定を明記
- 実装メモの `buffs:` はスキルツリーの `buffs:`（常時発動）、`mainhand-buffs:` はメインハンド限定
- 【要実装】= Java新規実装が必要。【フォーク側の対応待ち】= TF側は配線済みだがArsPaperフォークがまだ読みに来ていない
- ⚠ 印は今回の草案で新たに見つけた「文言はあるのに buffs が空」バグの修正箇所

## 1. 採掘（mining.yml）

**方針: 値だけ直す**（構造・parent・group は変更なし）

```
職業名：採掘
プレステージ内容：採掘王の栄光　メインにツルハシを持つと最終効率 永続+1・ドロップ増加 永続+20%
　※最終効率：バニラの効率強化エンチャントと同じ扱いで採掘速度が上がる度合い
　※ドロップ増加：鉱石のドロップ量が増える度合い（採掘運）

・A:はじまりの鉱夫　破壊で少量のバニラEXPを獲得
・B:洞窟の導き手　光源グリフ解放
　・B-1:精密破壊I　鉱石のドロップ増加+15%
　・B-2:精密破壊II　鉱石のドロップ増加+20%
　・B-3:精密破壊III　鉱石のドロップ増加+25%
　・A-1:高速破壊I　スキル発動で8秒間・CD30秒の高速破壊【アクティブ・実装済み】
　・A-2:高速破壊II　スキル発動で10秒間・CD22.5秒の高速破壊
　・A-3:高速破壊III　スキル発動で12秒間・CD15秒の高速破壊
・C:鉱山の仕事人　破壊で2倍のバニラEXPを獲得 ⚠
・D:露天掘りの匠　破壊グリフ解放・シルクタッチでスポナーの回収が可能に・最終効率 永続+1
　・D-1:鉱脈破壊　鉱石のみ一括で破壊
・E:至高の採掘王　採掘グリフ解放・ジュエリーコアのクラフト解放・最終効率 永続+1
```

### 実装メモ（採掘）

- ⚠ **C「破壊で2倍のバニラEXP」は現状 `buffs` が完全に空で何も起きていない**（`mining.yml:76-85` に `effects:` の文言はあるが `dedicated-effects`/`buffs` が無い）。修正:
  ```yaml
  C:
    buffs:
      break-vanilla-exp-bonus: 1.0   # ちょうど2倍
  ```
- D/E に `gathering-efficiency: 1` を追加（design doc §4-2 の「主軸に薄く配置」方針）。ツリー内合計 = D(1) + E(1) = **2**（上限5に対し余裕あり）
- プレステージ（現状 `mining-fortune: 20` のみ、速度分が無い＝ブリーフ#1で指摘済み）:
  ```yaml
  prestige:
    mainhand-buffs:
      mining-fortune: 20
      gathering-efficiency: 1
  ```
  プレステージ込みのツリー全体合計 = 2(D+E) + 1(prestige) = **3 ≤ 5 ✓**
- A-1/A-2/A-3 は `feature:haste-active-mining`（実装済み）そのまま。新規アクティブなし。
- 使用キー: `break-vanilla-exp-bonus` / `gathering-efficiency` / `mining-fortune` — いずれも `StatVocabulary.GENERAL_KEYS` に存在（後述の検証参照）。

### 実装メモ（農業）

- 🚨 **最優先修正（ブリーフ#4）**: `farming.yml` に `feature:break-vanilla-exp` が1箇所も無く、収穫でバニラEXPが一切出ていない。A に追加:

- ⚠ **C・D も「収穫量UP」「バニラEXPを追加で獲得」の文言はあるが `buffs` が空**（`farming.yml:58-81`）。修正:

- ゴミ食の段階化（α-1/α-2 の増減幅を変える）は**現状 Java 実装ではグローバル設定値のため不可**（design doc §4-3）。段階化するなら `junkfood-saturation-bonus` 系の stat 化が要る。**【要実装】**（今回のスキルツリー草案の範囲外・本ドキュメントでは現状の ON/OFF フラグのみ扱う）。

- プレステージ（現状 `buffs` 空＝6件の空手形の1つ、かつ元の文言「エンチャントポイント+20・消費経験値量-10%」の「消費経験値量」に対応する stat が**存在しない**）:
  ```yaml
  prestige:
    buffs:
  ```

- ※ `enchant_luck` / `enchant_exp_gain_bonus` は `stats/lore.yml` に登録が無いため、**アイテムのロアには表示されません**（プレイヤーはスキルツリー画面の説明文でしか自分の運値を確認できない）。バフの効果自体は `EnchantLuckListener` / `NativeSkillExperienceListener` が正常に消費するため機能面は問題ない。

## 判断に迷った点・一次情報と食い違って決められなかった点

1. **伐採 C-2 の `mining-fortune: 45`**: C-1が5であるのに対し9倍という異常値。タイプミス（`5`→`45` の誤入力等）と推測して`15`に修正したが、**意図的な高倍率だった可能性はゼロではない**ため要ユーザー最終確認。
2. **鍛冶 主軸A〜Eの「品質+1」が全ノード未配線**だった件は、design doc §4-5 が「鍛冶はスライドの構想がほぼ丸ごと実装済み」「あとは数値を入れるだけ」と評価していた箇所と矛盾する新発見。design doc執筆時点でも見落とされていたと判断し、本草案で埋めたが、**意図的に主軸は品質なしで進める設計だった可能性**も否定はできない（ユーザー確認推奨）。
3. **釣り A/C・農業 C/D・採掘/伐採/切削 C の「空buffsバグ」**は、ブリーフが明示的に指摘した6+3件のリストには入っていないが、同型の「文言はあるのに buffs が無い」事故だったため本草案の範囲内として修正した。ブリーフの優先順位づけでは触れられていない箇所なので、**範囲外として差し戻す判断もあり得る**。
4. **エンチャントプレステージの「消費経験値量-10%」**に対応する stat が存在しない件は、既存の読み替え前例（エンチャントポイント→エンチャント運）に倣い `enchant_exp_gain_bonus` へ転用したが、**意味合いとしては「エンチャント時に消費するEXPレベル」ではなく「エンチャント作業で得られるスキルEXP」であり、本来の意図とは方向が違う**。真に「消費レベルを減らす」報酬が欲しい場合は新規stat実装が要る。
