# 戦闘6ツリー スキルツリー草案 (2026-07-26)

`_草案作成ブリーフ.md` 準拠。対象: 軽量武器 / 重量武器 / 弓術 / 軽装備 / 重装備 / パワー。
6ツリーとも `dedicated-effects` 0件＝**すべて buffs だけで完結**（要実装なし）。

## 凡例

- `・A:` `・B:`… = 主軸（A=Lv10 / B=Lv30 / C=Lv50 / D=Lv70 / E=Lv90）。全員が必ず通る。
- `　・X-n:` = 全角スペース1つで字下げした分岐ノード（チェーンの深さに関わらずインデントは1段固定。順序はノードidの連番で示す）
- `・X-α-1:` = ギリシャ路線（`group` で排他）。`※αを選ぶと…` でレーン固定を明記
- 実装メモの `buffs:` はスキルツリーの `buffs:`（常時発動）、`mainhand-buffs:` はメインハンド限定
- 【要実装】= Java新規実装が必要。戦闘6ツリーは**0件**（後述）
- 率系ステータスは既存ファイルの慣習（分数表記 `0.04`=4%）に合わせる。`crit-damage` のみ元々分数

## 設計方針（6ツリー共通）

- ギリシャ路線を**レーン固定**（`B-α-1` の親を `A-α-1` に付け替え）。A帯で選んだ路線が最後まで続く。
- 3路線を「同じ物の3段階」から**性格の違う3型**に変更（α=火力型／β=技巧型／γ=特化型）。
- 主軸(A〜E)の buffs は**変更しない**（ルール5: 取り逃し厳禁の基礎値）。変えたのは枝(greek)のみ。

### 実装メモ（重量武器）
- レーン固定: light_weapons と同様に `parent` をレーン継続へ付け替え。`group` は帯ごとに維持。

- ノード名変更: 5帯すべての γ ノード「芯・○○」→「崩・○○」。理由: 中身が「固定ダメージ(一点集中)」から「範囲攻撃+スタン(なぎ払う制圧)」に変わり、「芯(核心を突く)」という名称と実態が逆方向になるため。
- D帯 主軸の文言修正: 現行 effect-text は「攻撃速度・スタン時間増加」だが、buffs は `attack-speed-bonus` + `stun_chance`(確率) + `attack-reach`(間合い) であり、**「スタン時間」という stat キーは存在しない**(lore.yml に `stun-duration` 等は無い)。新規実装するより実態に文言を合わせる方が安全なため、effect-text を「攻撃速度・スタン率・攻撃間合い増加」に修正することを提案する。
- プレステージ: 変更なし。
- 使用キー確認: `percent-bonus-damage` / `penetration` / `aoe-radius` / `aoe-damage-rate` / `stun-chance` すべて `lore.yml` に存在。

2. **プレステージが既に生きていた**: 事前の改訂案(§3-B)は6生産ツリーのプレステージ空手形を問題視しているが、
   戦闘5ツリー(軽量武器・重量武器・弓術・軽装備・重装備)は実 yml を確認したところ**既にbuffsが入って機能していた**。
   パワーだけが `enabled: false` で無効だった。ブリーフの「担当ツリーのプレステージは buffs まで明示すること」に
   従い、パワーのみ新規設計し、他5ツリーは「現状で問題なし」として buffs を再掲するに留めた。
3. **パワーへのギリシャ路線新設は「構造を変える」に該当する大きめの変更**。ブリーフのルール6「構造ごと変えたい
   場合は理由を1行書く」に従い実装メモに理由を明記したが、**既存の15ノード(A-1〜D-3)と新設15ノードで
   パワーツリーのノード総数が20→35に膨れる**。既存ノードのレベル配置(15/35/55...)と新設ノードのレベル配置
   (10/30/50/70/90、他5ツリーに合わせた)が帯としてズレる点は、editorでのレイアウト(座標)調整が別途必要になる
   可能性がある。これは「要確認」として残す。
4. **軽量武器C帯本体の名称**（「受け流しの型」）は effect-text 自体は実態(damage-reduction等)と合っているため
   据え置いたが、フレーバー名としては「受け流し」の語が残っている。C-greek 3ノードのみ改名するのがブリーフの
   明示要求だったのでそこに留めたが、統一感のためC本体も改名する余地はある(判断保留)。
5. **heavy_weapons D帯の文言修正**は「スタン時間」という未実装stat語彙を「スタン率」に寄せる方向で提案したが、
   本来「スタン時間を伸ばす」という意図だった場合はコード新規実装(stun-duration相当のキー追加)が必要になる。
   今回は「新規実装をしない」という制約下での判断であり、意図確認が必要なら別途要相談。
