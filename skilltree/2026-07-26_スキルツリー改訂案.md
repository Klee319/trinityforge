# TrinityForge スキルツリー改訂案 (2026-07-26)

同フォルダのスライド草案（`skilltree/skilltree/スライド1〜17.PNG`）を土台に、
**config-editor で今できるようになったこと**を踏まえて役職（スキル）ごとに改訂案をまとめたもの。

> 🔄 **2026-07-26 改訂済み。** 初版には「未実装」の誤判定が4テーマあり、全面訂正した（詳細は末尾の改訂履歴）。

> **この文書の使い方**
> 各ツリーの表は「スライドの意図」→「今の実装」→「私の推奨」の3列構成。
> **「editor」列が ● のものは、コードを一切触らずあなたがブラウザ上で今すぐ変更できる。**
> ○ は既存の機構に値を書くだけ（同じくコード不要）、× はコードの新規実装が要る。
>
> 数字はすべて**たたき台**。バランスはプレイして決めるものなので、●○の項目は遠慮なく上書きしてほしい。

## 0. 結論を先に

1. **戦闘6ツリー（軽/重武器・軽/重装備・弓術・パワー）は、もう100%あなたの手で完結する。**
   `dedicated-effects` が0件＝コード依存ゼロで、全ノードが `buffs` / `mainhand-buffs` だけで出来ている。
   スライドの内容もほぼそのまま数値化済み。**改訂案の主眼は「数値の刻み方」と「削除済みステの穴埋め」。**

2. **生産10ツリーが本題。** ここに `dedicated-effects`（機構フラグ）が集中しているが、
   スライドの構想のうち**まだコードが無いのは2テーマだけ**まで減っている（後述§5）。
   07-25 の仕分けレポートが「機構なし18件」としていたものは、**その後ほぼ全部実装済みになっている。**

3. **本当のボトルネックは「未実装」ではなく「配線ミス」と「数値の桁」だった。**
   実コードを当たった結果、新規実装が要るのは2件だけで、代わりに次の3件が見つかった。

   - `farming.yml` の A ノードは効果文言に「バニラEXPを収穫時に獲得」と書いてあるのに
     `feature:break-vanilla-exp` が置かれていない（mining / woodcutting / digging には置かれている）。
     **farming だけEXPが出ていない。**
   - `alchemy.yml` の `coating_charges` 3ノードが、**総合ステ経由では誰にも読まれておらず無効**（§4-6）。
   - `enchanting.yml` の `enchant_luck` が全帯合計 90 で、**格上げ確定・上限突破確定**まで振り切れている（§4-7）。

> ⚠️ **初版からの重要な訂正**: 初版の §4-6 / §4-7 / §4-8 / §5 は「ポーション品質・醸造速度・残留時間・
> エンチャント運・特定グリフ威力ブーストは未実装」と書いていたが、**すべて実装済み・配線済み**だった。

## 2. editor で今できること（＝設計の自由度）

改訂案はこの範囲内に収まるよう作ってある。

### 2-A. ノードに書ける中身

| 項目 | 内容 |
|---|---|
| `buffs` | **常時発動**のステータス加算。約90キーから選べる |
| `mainhand-buffs` | **指定の物をメインに持っている時だけ**発動するステータス加算 |
| `multipliers` / `mainhand-multipliers` | 加算ではなく倍率で効かせたい時 |
| `dedicated-effects` | 機構フラグ。`feature:` 25種 / `glyph:`（Arsの全グリフ） / `drop:`（ドロップ表） |
| `commands` | 解放時に走らせるコマンド |
| `effects` / `effect-text` | プレイヤーに見せる説明文 |
| `cost` | 必要スキルポイント |
| `group` | **同じ値を書いたノード同士が排他になる**＝スライドの「ギリシャ文字路線はいずれかのみ解放可能」がそのまま作れる |
| `parents-any` | 複数の親のうち**どれか1つ**を満たせば解放（合流点が作れる） |
| `prestige` | 周回時の永続ボーナス。`mainhand-buffs` が使える |

### 2-B. 今セッションで editor に増えたもの

- **スキル選択にステータスカテゴリのフィルタが付いた。** 約90キーから探すのに、
  「攻撃」「防御」「採取」等で絞り込めるようになった。改訂案でキーを大量に指定しても選びやすい
- **ログインが不要になった**（ローカル運用前提）
- アイテムを消しても**タブのピン留めゴミが残らなくなった**（幽霊エントリ102件の原因だった）

### 2-C. スキルツリーに置けるようになったステータス（2026-07-26）

ステータスの分類を見直し、**今までアイテムにしか書けなかった8キーが総合ステータスに昇格**した。
＝**スキルツリーのノードから直接配れるようになった。** 改訂案ではこれを使う。

| キー | 使いどころ |
|---|---|
| `armor-strength` | 防具強度（会心軽減率%）。**重装備ツリーの新しい軸になる** |
| `aoe-radius` / `aoe-max-targets` / `aoe-damage-rate` | 範囲攻撃。重量武器の γ 路線に厚みが出る |
| `hit-mana-recovery` / `damage-mana-recovery` | 殴った時／被弾した時のマナ回復。**Ars魔法の A〜E帯を差別化できる** |
| `mana-cost-reduction-flat` / `mana-cost-reduction-percent` | 詠唱コスト減。同上 |

逆に**アイテム固有に降格**したもの（＝**スキルツリーからは配れない**）:

| キー | 理由 |
|---|---|
| `attack-speed`（絶対値） | メインハンドの武器が決める値。`attack-speed-bonus`（割合）は今までどおり配れる |
| `coating-charges` | その武器のコーティング容量。ツリー側は dedicated effect `coating-stack-increase` を使う |
| `durability` / `item-cooldown` / `thread-slots` / `tool-enchant-*` | 従来からアイテム固有 |

### 2-D. 逆に editor では書けないもの（**残り2件**）

> 初版はここに5件挙げていたが、実コードを確認したところ3件は実装済みだった。

- **ゴミ食だけを強化する段階値** — 増減幅がグローバル設定値で、ノードごとに変えられない（§4-3）
- **「消費した耐久の累積量」に応じた変動** — 切削 C-1/C-2 の構想。現在は EXP 換算のみ実装

（**ポーション品質・醸造速度・残留時間 / エンチャント運 / 特定グリフの威力アップ**は
**すべて実装済みで、editor から数値を書ける**。詳細は §4-6 / §4-7 / §4-8）

## 3. 改訂の設計原則

### 原則1 — 主軸A〜Eは「ステータス」、枝は「機構」に寄せる

主軸（A〜E＝Lv10/30/50/70/90）は必ず取るので、**取り逃しが起きない場所**。
ここに数値を置き、枝（A-1, B-α-1…）に解放・ギミックを寄せると、
**「どのルートを通ってもベースは伸びる／個性は枝で決まる」**という読みやすい形になる。
現状の戦闘6ツリーは既にこの形。生産系も揃えたい。

### 原則2 — ギリシャ文字路線は必ず「トレードオフ」にする

`group` で排他にできるが、**片方が明確に強いと選択にならない**。
スライドで既にこれが出来ているのは農業（ゴミ食 ⇄ 健康食）と釣り（宝を捨てて売却 ⇄ 宝特化）。
逆に**軽量武器/重量武器/弓術のα/β/γ（ダメージ／会心率／会心ダメージ）は
「3つとも取れる並列強化」になっていて排他の意味が薄い**。
→ **§4-1 の排他化は 2026-07-26 に承認済み。** そちらが確定案。

### 原則3 — 削除したステータスの穴は「別ステに差し替え」（あなたの決定に従う）

今セッションで消えたステータス:

| 消えたもの | 差し替え先 | 状態 |
|---|---|---|
| `parry-damage-reduction`（受け流し） | `damage-reduction`（被ダメージ軽減） | 適用済み（軽量武器 C/E） |
| `craft-quality-bonus` | `workbench-quality-bonus` に統合 | 適用済み |
| `craft-thread-slot-bonus` / `thread-slot-cap-bonus` | `ritual-quality-bonus` | 適用済み（Ars鍛冶3ノード） |

**ノードは残して中身だけ差し替える**方針なので、スライドの見た目とツリー構造は変わらない。

### 原則4 — 率系ステータスの数値は「%表記」で書く

`penetration: 20` と書けば20%として扱われる（内部で0.2に正規化される）。
**`0.2` と書くと20%ではなく20%の1/100になる**キーがあるので、率系は必ず整数%で書くこと。
今セッションで、この二重縮小が原因で**巣の採集ボーナスが設定値の100分の1**になっていた実例がある。

### 原則5 — 「解放」は永続、「数値」は積み上げ

スライド備考（`スライド17.PNG`）の方針をそのまま採用:
- グリフ解放はプレステージしても**素材の再取得は不要**
- ゴールを明示せず、**ゴールまでの道を増やすことで質を担保する**
- プレステージ時にスキルを引き継げるアイテムを追加する ← **これはまだ未実装**

## 3-B. 🚨 プレステージが「空手形」になっている（2026-07-26 発見）

**16ツリー中6ツリーで、プレステージ報酬が effect-text だけ書かれていて `buffs` が1つも無い。**
Lv100まで育てて周回した報酬が、**文言だけで実際には何も起きない**。

| ツリー | 表示されている報酬 | 実際の `buffs` |
|---|---|---|
| **alchemy** | 全ての品質 永続+50・ランダムステータス品質 永続+15% | **なし** |
| **smithing** | 全ての品質 永続+50・ランダムステータス品質 永続+15% | **なし** |
| **enchanting** | エンチャントポイント 永続+20・消費経験値量 永続-10% | **なし**（しかも「エンチャントポイント」は存在しない語彙） |
| **farming** | 満腹度回復量 永続+1・経験値獲得 永続+10% | **なし** |
| **fishing** | 同時ヒット確率 永続+10%・宝釣りの確率 永続+10% | **なし** |
| **woodcutting** | 採掘速度+1・リンゴドロップ+10%・木材の経験値変換効率+10% | **なし** |

さらに、**書かれているが足りない**ものが3件:

| ツリー | 不足 |
|---|---|
| **mining** | 「採掘速度上昇 永続+1」と書いてあるが `mainhand-buffs` は `mining-fortune: 20` だけ。**速度分が無い**（`gathering-efficiency` で実装可能になった） |
| **digging** | 同上（`mining-fortune: 15` のみ） |
| **ars_smithing** | 「品質+1・必要ソース-10%」だが `workbench_quality_bonus: 1` のみ。**ソース-10%が無い**（`ingredient-save-chance` で表現できる） |
| **power** | `enabled: false`。**プレステージそのものが無効** |

**これはスキルツリー草案より優先度が高い。** 周回という最大の目標に報酬が無いのは、
数値バランス以前の問題。§4 の各ツリー案では**プレステージの `buffs` を必ず明示する**。

> 表示だけあって中身が無いのは、このプロジェクトで繰り返し出ている「無言で何も起きない」型の事故
> （`coating_charges` の3ノード、`farming` の `break-vanilla-exp` 欠落と同型）。
> `docs/design/2026-07-26-stat-scope-ux.md` §6 のドリフト検査を
> **プレステージにも広げる**（effect-text があるのに buffs/dedicated-effects が空ならビルドを落とす）
> のが恒久対策。

## 4. 役職ごとの改訂案

### 4-1. 戦闘6ツリー（軽量武器・重量武器・弓術・軽装備・重装備・パワー）

**現状**: 主軸A〜Eに個性、α/β/γの3枝に「ダメージ増加／会心率／会心ダメージ」を段階配置。全て `buffs`。

**問題点**（⚠️ 2026-07-26 訂正 — 初版は原因の記述を間違えていた）:

初版は「α/β/γが排他になっていない」と書いたが、**実際には既に排他になっている**。
`light_weapons.yml:155` 他、15ノード全部に `group: A-greek` 〜 `E-greek` が入っている。

真の問題は**排他の粒度**にある。

```
A ──┬─ A-alpha-1 ┐
    ├─ A-beta-1  ├─ group: A-greek （ここで1つ選ぶ）
    └─ A-gamma-1 ┘
B ──┬─ B-alpha-1 ┐   ← parent は「B」であって「A-alpha-1」ではない
    ├─ B-beta-1  ├─ group: B-greek （ここでまた選び直せる）
    └─ B-gamma-1 ┘
```

**帯ごとに独立して選び直せる**ため、5帯を通すと α2 / β2 / γ1 のような混合配分になり、
**誰がやっても合計値がほぼ同じ**になる。排他が5回あるのに、結果としてビルドの個性が出ない。

**修正案（editor ● / コード不要）**: 帯ごとの `group` はそのまま残し、
**greek ノードの `parent` を1つ上の帯の同じ路線に付け替える**（レーン固定）。

```
A-alpha-1 → parent: A          （入口はこれまでどおり主軸から）
B-alpha-1 → parent: A-alpha-1  （α を選んだ人だけが進める）
C-alpha-1 → parent: B-alpha-1
```

こうすると **A帯の1回の選択が最後まで効く**＝3つの型が成立する。
`parents-any` を使えば「途中で乗り換えられる合流点」も作れるので、
完全固定が厳しすぎる場合は D帯だけ `parents-any: [C-alpha-1, C-beta-1, C-gamma-1]` にする逃げ道もある。

> 📌 **ついでに直すべき文言**: `light_weapons.yml` の C帯 greek は
> 「剛・受け流し」「疾・受け流し」「冴・受け流し」という名前のままだが、
> **受け流しは今セッションで廃止して被ダメージ軽減に統合済み**。名前が実態と合っていない。

**確定案（2026-07-26 承認済み / editor ● / コード不要）**

`group` による排他は既にあるので、**やることは (a) `parent` のレーン固定と (b) 中身の差別化**の2つ。
下表は (b)。現在は3路線とも「ダメージ／会心率／会心ダメージ」で**性格が分かれていない**ため、
型として意味を持つキーに差し替える。

| ツリー | α（火力型） | β（技巧型） | γ（特化型） |
|---|---|---|---|
| 軽量武器 | `percent-bonus-damage` | `crit-chance` + `attack-speed-bonus` | `bleed-chance` + `bleed-damage` |
| 重量武器 | `percent-bonus-damage` | `penetration` | `aoe-radius` + `aoe-damage-rate` + `stun-chance` |
| 弓術 | `distance-damage-bonus` | `crit-chance` + `arrow-velocity` | `arrow-piercing` + `ammo-save-chance` |
| 軽装備 | `dodge-chance` | `armor-defense-rate` | `damage-reduction` + `move-speed` |
| 重装備 | `flat-defense` | `magic-resistance` | `armor-strength` + `knockback-resistance` |
| パワー | `max-health` | `health-regen-bonus` | `reflect-percent` + `reflect-flat` |

> **2026-07-26 の分類見直しを反映した2箇所**:
> - 重量武器 γ を `fixed-damage` から **AoE** に変更。`fixed-damage` は全防御貫通なので枝に置くと
>   壊れやすく、また AoE 3キーが総合ステに昇格して初めてツリーから配れるようになったため。
> - 重装備 γ を `damage-reduction` から **`armor-strength`** に変更。軽装備 γ と被っていたのを解消し、
>   「重装は会心を潰す」という性格を与える。こちらも今回の昇格で初めて配れるようになったキー。

刻みは主軸の帯に合わせて **5段（A/B/C/D/E帯に1つずつ）**、
1段あたり「火力型なら +4%」「技巧型なら +3%」程度から。合計で20%前後に収まる。

> **なぜ排他にするか**: 3本とも取れると全員が同じ最終形になり、
> 「軽量武器を極めた人」同士の差がゼロになる。排他にすると3通りの完成形ができ、
> 装備の厳選（ランダムステータス）と噛み合って組み合わせが一気に増える。
> スライドの「質は明示的でない（優位でない）ゴールまでの道を増やすことで担保する」に沿う。

**あわせて直したいもの**

- 軽量武器 C/E の「受け流し」は `damage-reduction` に差し替え済みだが、
  **effect-text がまだ「受け流し解放」のまま**なら、表記も直したい（editorで可）
- 弓術のスライドにある注記「弓の命中率の初期値をバニラより少し低いくらいに引き上げる」は
  `bow-accuracy` の初期値の話。**`combat/base-stats.yml` で全員一律の初期値として設定できる**（editor ●）
