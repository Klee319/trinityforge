# config-editor UI/UXレビュー (2026-07-25)

対象: `tools/config-editor`（Node+express / 素のHTML・CSS・JS、`public/` 配下 約25,000行）。
依頼: 表示とUIのレビュー（UXの良し悪し・体裁の乱れに着目）。**修正は明白かつ低リスクなもののみ実施**、
それ以外は判断材料つきで報告に留める方針で進めた。

## 0. 検証方法についてのお断り（重要・判断に迷った点）

ブリーフでは「`public/style.css` を読み込む検証用HTMLをスクラッチパッドに書き、`file://` でブラウザ表示して
目視確認する」よう指示されていたが、**このセッションのBrowserツールでは以下の理由で実行できなかった**:

- `file://` でスクラッチパッド配下のHTMLを開いても、ツール側が「プロジェクトフォルダ外は static snapshot」
  として扱い、`screenshot` / `read_page` / `javascript_tool` などがすべて `No site is open in this tab` で
  失敗する（ユーザーへの見た目表示だけで、こちらからは中身を読み取れない）。
- `data:` URLは `navigate` が「有効なfile pathまたはURLでない」として拒否する。
- ローカルに簡易HTTPサーバーを立てても（`python -m http.server`）、ブラウザツールのポリシーで
  `http://127.0.0.1:<未許可ポート>` への遷移がブロックされる。
- 事前許可されたローカルオリジンを増やすには `.claude/launch.json` の作成が必要だが、この書き込みは
  auto-modeの権限クラシファイアに拒否された。
- 唯一到達できたローカルオリジン（`http://127.0.0.1:8000`、ツールに元から見えていた `seed` タブ）は
  **本物のconfig-editorサーバ自身**で、Basic認証がかかっており `{"error":"認証が必要です"}` を返すのみ
  だった（ブリーフの制約どおり、これへログインする経路は使っていない）。

このため、**A-1（起点の `.stat-row-label` 崩れ）を含む折り返し系の判定は、スクリーンショットではなく
実際のCSSルール（`flex: 0 0 220px` は grow=0/shrink=0 なので幅は常に220pxに固定される、`white-space:nowrap`
や `text-overflow:ellipsis` が無いので収まらない文字列は箱の中で2行に折り返される、というCSSボックスモデル
上の確定事実）と、このリポジトリ自身が既に採用している文字幅の目安（`labels.js` の
`MAX_STAT_LABEL_LENGTH = 14` 文字 ≈ 182px、ブリーフに明記）を根拠に判定した**。目視スクリーンショットは
撮れていない点を明記する。これは「検証手段が指示通りに使えなかった」という着手前提の破綻に近いが、
タスク全体を止めるほどではないと判断し、代替手段（CSSボックスモデルの確定的推論）で続行した。判断が
分かれる部分なので、ここに明記して報告する。

## 2. 今回修正したもの（A-1）

### 修正前の実装（`public/js/tf-base-stats.js`）
`base-stats.yml` の絶対値系5キーで、`.stat-row-label` の **表示テキストに直接** `" (絶対値・既定N)"` を
連結していた（コメントには「別要素で挟む」と書かれていたが実装は連結のまま）。

```js
const labelText = vanillaDefault === null
  ? statLabel(k)
  : statLabel(k) + " (絶対値・既定" + vanillaDefault + ")";
...
h("span", { class: "stat-row-label", text: labelText, title: labelTitle }),
```

`.stat-row-label` (`public/style.css:317`) は
```css
.stat-row > .stat-row-label { flex: 0 0 220px; max-width: 100%; color: var(--muted, #9aa); font-size: 13px; }
```
`flex: 0 0 220px` は grow=0・shrink=0 なので**箱の幅は常に220px**。`white-space:nowrap` も
`text-overflow:ellipsis` も無いため、連結後の文字列が220pxに収まらなければ**箱の中で複数行に折り返す**
（`stat-row` は `flex-wrap:wrap` だが、これは行内の子要素の折り返しであり、ラベル文字列自体の折り返しとは
別問題）。

「1. の 検証方法についてのお断り」に記載の通りスクリーンショットは撮れなかったが、以下は確定的に言える:
- 対象5キーの元ラベル（例: `戦闘:攻撃速度↑` 8文字相当）に `" (絶対値・既定4)"` 相当（10文字前後）を
  足すと、このリポジトリ自身の目安（13px全角1文字≈13px、14文字≈182pxがブリーフに明記の基準）に沿って
  計算すると **合計18〜24文字相当 ≈ 234px〜312px となり220pxを超える**。
- 一方、通常表示（キー名のみ）の他の全ステータス行は最長でも14文字（`STAT_LABELS` 内の実測、
  `flat-bonus-damage` の「戦闘:追加ダメ(実)【廃止】」で14文字）で220px以内に収まっており、
  **この5行だけ**が突出して長くなっていた。
- 結果、この5行だけ2行に折り返り、他の1行行と行高が揃わない「体裁の乱れ」が発生していた（実害:
  カテゴリ内で行の高さがガタつき、パッと見の一覧性が落ちる）。

### 修正内容
ラベル本体のテキストは元の日本語ラベルのみに戻し（`.stat-row-label` の幅レイアウトは一切変更しない）、
「絶対値・既定N」ヒントは**別要素**として、既存の `.field-unit` バッジクラス（`public/style.css:318-328`、
`flex: 0 0 auto; white-space: nowrap;` の小さいバッジ）を転用して `stat-row-label` の直後・値入力欄の前に
差し込んだ。`.stat-row` は `flex-wrap: wrap` のままなので、バッジがラベル+入力欄と同じ行に収まらない
極端な狭幅では行が折り返るが、**ラベル文字列自体が2行になることはなくなる**（バッジは独立した要素なので
折り返しても行高崩れ方が「短いバッジチップが次の行に落ちる」だけで、ラベルの縦幅は常に1行分で揃う）。
`title` 属性による詳細説明（バニラ既定値・絶対値方式の注記）は維持した。

他画面への波及確認: `.field-unit` クラスは既に `mining-gimmick` 等の単位表示で使われている既存クラスで、
今回は**新規CSSを追加していない**（既存クラスを別画面で再利用しただけ）。`.stat-row-label` のCSSルール
自体（`style.css:317`）は変更していないため、他の `.stat-row-label` 使用箇所（lore/mob-defense-block等、
`labels.js` grep で確認した全ステ表示箇所）への影響はゼロ。

### diff相当（要点）
`public/js/tf-base-stats.js` の該当ブロックを、ラベルテキストとヒントバッジを別要素にする形へ変更。
（テストは既存328件がベースラインのまま通過、対象コードに対する専用ユニットテストは既存テストスイートに
無かったため新規追加はしていない — 4章の検証参照）

## 5. 問題なしと判断した観点（網羅性のため明記）

- A-3 `.entry-sum-name`: ellipsis+nowrap が既に適切に設定されており折り返し・行崩れなし。
- C-2 lore.yml ステ表示テーブルの横スクロール: テーブル自身に閉じ込められており、ページ全体の横スクロール
  には波及しない。意図的な設計であることがCSSコメントからも読み取れる。
- 単位ヒント全般: PERCENT系ステータスは `isPercentStat` 判定で自動的に専用の `%` 付き入力コントロールへ
  切り替わっており（`tf-base-stats.js:87-96` 等）、「割合(0.0〜1.0)」と「パーセント(0〜100)」を同じ生の
  数値入力欄で混在させている箇所は見当たらなかった（サンプリング範囲内）。
- 危険操作のうち、カテゴリ削除・互換リスト削除・リソースパック一括操作・乗算レイヤ削除には `confirm()`
  ガードが確認できた（B-1で報告した「不統一」の裏返しとして、一部は既にガードされている）。

## 6. レビューのカバレッジについて（正直な申告）

`public/js/*.js` は計約25,000行・25ファイルあり、今回は以下の方法で重大度の高そうな箇所を優先的に
サンプリングした（全行の逐次読み込みは行っていない）:
- ブリーフで名指しされた `.stat-row-label` / `.form-label` / `.entry-sum-name` / `.field-input.num` の
  CSS定義とその使用箇所。
- `labels.js` の実データから機械的に最長ラベルを算出し、該当CSSと突き合わせ。
- `confirm(` / `削除` / `help-icon` などのキーワードでの横断grep。
- `lib/registry.js` の全 `group`/`section` 定義の目視確認。

このため、個別フォーム（`mob-forms.js`, `tf-dungeon-forms.js`, `recipes.js` 等）内の細かい入力部品の
自由入力/セレクト不統一（観点B-5相当）は、代表例のみ確認しほぼ手を付けられていない。追加で深掘りが
必要な場合は範囲を絞って指示いただきたい。

## 7. 検出総数と重大度内訳

- 高 (実害あり・修正実施): 1件（A-1）
- 中 (実害の可能性あり・判断要): 1件（B-1）
- 低 (軽微 or 判断要): 4件（A-2, B-2, C-1, C-2のうちC-2は「問題なし」に分類替え。実質: A-2, B-2, C-1の3件）
